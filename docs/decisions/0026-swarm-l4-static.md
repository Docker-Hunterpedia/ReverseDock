# ADR-0026: v0.6: TCP routes and PROXY protocol in our accept loop, a polling Swarm provider in task mode, static files as a terminal middleware, DNS adapters on raw REST, a per-attempt connect budget

- Status: accepted
- Date: 2026-11-07

## Context
v0.6 adds Docker Swarm (W-SWM-01…03), TCP routes with SNI passthrough, TLS termination and PROXY protocol (M-L4-01…03), static files (F-WEB-01), seven DNS-01 adapters (W-DNS-03) and the performance plan of [#181](https://github.com/Docker-Hunterpedia/ReverseDock/issues/181). The config model already describes TCP listeners, routes and services, PROXY protocol and the Swarm provider; `rdock run` refuses them as "planned for v0.6". [Research](../research/v0.6-swarm-l4-static.md) checked the facts on 2026-11-06. The findings that shape this decision:
- Pingora 0.9.0 has no raw TCP relay and no PROXY-protocol parser or writer; its `PreTlsProcess` hook runs only inside Pingora's own listeners, which we replaced in [ADR-0012](0012-own-listeners-pingora-http-engine.md).
- rustls's `Acceptor` and tokio-rustls's `LazyConfigAcceptor` keep the bytes of the ClientHello they consume, so they cannot be used for passthrough. A current ClientHello with an X25519MLKEM768 key share is larger than one TCP segment and may span several TLS records.
- Swarm emits no task events (only service, node, network, secret and config events), and bollard 0.21.1 has no `Task.networks_attachments`, so task addresses cannot be read through it.
- With Swarm's `vip` mode the proxy sees one address per service: per-task health checks, sticky cookies, retries to another backend and drain have nothing to act on.
- Pingora ships no file server; replies from our middlewares are fully buffered today, and `Route.service` is required.
- The AWS SDK needs Rust 1.94.1 (our MSRV is 1.89) and uses aws-lc-rs by default (banned in `deny.toml`); the Azure DNS crate has had no release since 2024-10.
- A stopped container makes every connect to its address wait for ARP to give up (about 6 s), so our 5 s connect timeout is what users wait once per backend stop, as the v0.5 soak showed.

## Decision

### TCP routes (M-L4-01, M-L4-02)
- A `tcp` listener is our accept loop ([ADR-0012](0012-own-listeners-pingora-http-engine.md)) with a different per-connection `serve()`, not a Pingora `Service`/`ServerApp`. It gets the same reload behaviour (sockets kept for unchanged addresses, settings swapped atomically, drain bounded by `lifecycle.drain_timeout`).
- Per connection, in order: PROXY header (below) → optional `starttls: postgres` (answer PostgreSQL's 8-byte SSLRequest with `S`, off by default) → ClientHello peek → route match → passthrough or termination → relay.
- **ClientHello peek** is our own parser in `rdock-tls` (record and handshake headers, reassembly across records and reads, `server_name` and ALPN), capped at 16 KiB and bounded by the listener's header timeout; every byte read is put back with `L4Stream::rewind`. tls-parser and the rustls `Acceptor` are used as oracles in tests and a fuzz target, not at run time. Bytes that are not a TLS record only match `HostSNI(*)`; anything else is closed and counted.
- Routes match with the existing grammar: `HostSNI` (exact, one-label wildcard, `*`), `HostSNIRegexp`, `ALPN`, `ClientIP`. On a listener that answers TLS-ALPN-01, no route may match `acme-tls/1`. With ECH (RFC 9849) the outer SNI is the public name, so a passthrough route matches the public name; ECH decryption is out of scope.
- **Passthrough** relays the original bytes. **Termination** uses the listener's existing rustls `Acceptor` (SNI certificates, TLS policy, tickets); the plaintext goes to the backend, optionally re-encrypted. Only implicit-TLS protocols can be terminated (MQTT 8883, SMTPS 465, IMAPS, LDAPS, PostgreSQL 17 with `sslnegotiation=direct` or with `starttls: postgres`); MySQL and SMTP/IMAP STARTTLS are passthrough only, and `rdock validate` says so when it can tell.
- **Relay** is `tokio::io::copy_bidirectional` inside an idle timer reset by traffic in either direction (`timeouts.idle`, default 10 minutes for TCP, like NGINX `proxy_timeout`) and a `termination_delay` (default 100 ms, like Traefik) that starts when one direction ends. Backends are chosen per connection by `rdock-balancer`; TCP health checks already exist. Metrics: `rdock_tcp_connections{listener,route}` and `rdock_tcp_bytes_total{route,direction}`.
- Middlewares on TCP routes: `ip_allow`/`ip_deny` and `in_flight` (per client address, through `rdock_limits::ConcurrencyLimiter`). Traefik labels accepted: `traefik.tcp.routers.<r>.{rule, entrypoints, service, priority, middlewares, tls, tls.passthrough}`, `traefik.tcp.services.<s>.loadbalancer.server.port`, `traefik.tcp.middlewares.<m>.{ipallowlist.sourcerange, inflightconn.amount}`. `serverstransport`, `tls.options` and `tls.certresolver` on TCP routers get a diagnostic.
- Out of scope for v0.6: UDP (M-L4-04), weighted TCP services, server-side ECH, mixed HTTP and `HostSNI(*)` routes on one listener (a diagnostic).

### PROXY protocol (M-L4-03)
- One parser runs in the accept loop of every listener type (`http`, `https`, `tcp`) before the TLS handshake or the HTTP preface, using the proxy-header crate (0.1.3, MIT, parse and encode of v1 and v2 with TLVs), pinned exactly.
- **Trust:** a header is read only when `listeners.<l>.proxy_protocol` is set **and** the TCP peer is in its `trusted` list. A trusted peer must send a header unless `optional: true`; a peer outside `trusted` that sends the v1 or v2 signature is closed and counted (`rdock_proxy_protocol_rejected_total{listener,reason}`). Without `proxy_protocol` nothing is ever detected (the spec's "must never try to guess"). There is no `insecure` switch. This is stricter than Traefik (headers from untrusted peers are kept as plain connections) and Caddy (`fallback_policy: ignore`), and matches Envoy.
- The parsed source address is set as the connection's peer address (`SocketDigest.peer_addr`), so access logs, `ClientIP`, IP filters, rate limits and the real-client-IP algorithm (B-NET-08) see the original client; the TCP peer stays in the log as `proxy_peer`. `LOCAL` headers keep the real endpoints.
- **Outbound:** `tcp_services.<s>.proxy_protocol: v1|v2` writes the header as the first bytes of every backend connection (v2 carries ALPN and, after termination, the SSL and authority TLVs); health probes send `LOCAL`. The same writer is used later for HTTP services through Pingora's `PeerOptions.custom_l4`.

### Swarm provider (W-SWM-01…03)
- `rdock-provider-swarm` reuses the Docker provider's pure translator unchanged: each running task becomes the translator's `Container` (name `<service>.<slot>`, or `<service>.<task id>` in global mode; labels from the service's `Spec.Labels`, which is where Compose `deploy.labels` land; addresses from the task). Native `rdock.*` labels, the Traefik subset, diagnostics, the conformance fixtures and `rdock migrate traefik` carry over.
- **Updates:** subscribe to `service`, `node`, `network`, `secret` and `config` events for an immediate re-list, and poll `/services` and `/tasks?desired-state=running` every `providers.swarm.poll_interval` (default 5 s, minimum 1 s) because tasks emit no events; coalescing, the 60 s reconcile, last-snapshot-on-loss and backoff come from the Docker provider. Traefik polls every 15 s with no events.
- **Endpoint mode:** the default becomes `tasks` (the model's `vip` default changes before it ships): the proxy balances over task addresses with its own health checks, sticky sessions and retries, and drains a task as soon as its `DesiredState` is `shutdown` while it still runs. `vip` stays as an opt-in (routes to the service's virtual IP and lets Swarm balance); for such services active health checks and sticky cookies are disabled with a diagnostic. A `dnsrr` service in `vip` mode gets a diagnostic, not a silent drop.
- **Task health:** Swarm reports a task `running` only after its healthcheck passes and replaces unhealthy tasks, so `Status.State == running` is the readiness signal; the existing fail-open rule applies.
- **Network:** `rdock.network` / `traefik.swarm.network` label → `providers.swarm.network` → the one network shared by the proxy's own container and the task, never `ingress` → otherwise the existing "several networks, choose one" diagnostic. Never random.
- **Labels:** `traefik.swarm.*` and the deprecated `traefik.docker.*` spelling are both accepted (the latter with a warning; both together is a diagnostic, as in Traefik); `traefik.swarm.lbswarm=true` maps to `vip` for that service; job-mode services are skipped with a diagnostic. The port label is required when the service publishes no single port, as in Traefik, because Swarm reports none.
- **Engine API:** bollard stays for events and services; tasks are fetched with our own small client over the hyper and hyperlocal crates already in the tree, deserialising only the fields we read, until a bollard release exposes `networks_attachments`. The provider needs only `SERVICES`, `TASKS`, `NODES`, `NETWORKS`, `EVENTS` read access on a manager (a socket proxy with `POST` off works); it never calls a write endpoint.
- **Replicas share nothing in v0.6** (cluster state is v0.9). Two supported shapes are documented: one ACME-enabled replica with host-mode ports, or global mode with certificates from Swarm secrets or DNS-01 on exactly one replica. `rdock validate` warns when `acme` and `providers.swarm` are both on. A data directory on a shared file system is refused at start (two ACME managers on one store race).
- Secrets and configs need nothing new: `rdock.yaml` can be a Swarm config and reference `/run/secrets/*` through `${file:…}`; both are immutable, so a rotation is a task replacement.

### Static files (F-WEB-01)
- `static` is a **terminal middleware** in `rdock-middleware`, as the architecture planned, so it composes with `basic_auth`, `headers`, `compress` and later `cache`. `Route.service` becomes optional when the route's chain ends with a terminal middleware (`static` without `pass_through`, `maintenance`); `rdock validate` checks it. `pass_through: true` sends a miss to the route's service (assets from disk, everything else to the backend).
- `Reply` gains a streaming body: files up to 1 MiB are read in one call, larger ones are streamed in 256 KiB chunks through `write_response_body`, which keeps HTTP/2 flow control, `min_send_rate` and the `bandwidth` middleware working. No sendfile (Pingora has none and TLS would defeat it).
- **Path safety:** the root is opened once as a directory handle with cap-std (`openat2` with `RESOLVE_BENEATH` on Linux 5.6+, per-component checks elsewhere) and never built from request data. The forwarded path is decoded exactly once more after `rdock-rules` normalisation; `\`, NUL, invalid UTF-8 and any `..` segment answer 404 before the file system is touched; the kernel enforces containment.
- **HTTP:** strong `ETag` from modification time (ns) and size, `Last-Modified`, the full RFC 9110 §13.2.2 precondition order (304/412), single-range 206 with `If-Range`, 416 with `Content-Range: bytes */len`, `Accept-Ranges: bytes`, HEAD with GET's headers. Precompressed sidecars (`.zst`, `.br`, `.gz`, in that order) chosen by `Accept-Encoding` q-values with their own ETags and `Vary: Accept-Encoding` on every answer; ranges apply to the chosen encoding. `Content-Type` from mime_guess with `charset=utf-8` for text, JavaScript, JSON, XML and SVG, a small override table (`mjs` → `text/javascript`) and a `types` map; unknown types are `application/octet-stream` with `nosniff`.
- **Defaults, each offered with its opposite:** `symlinks: none` (also `within_root`, `all` with a warning), `hidden: refuse` for any dot-file or dot-directory component, `listing: false` (F-WEB-02 is P3), `max_ranges: 1` (more answers 200; up to 16 as multipart when raised), `cache_control` `no-cache` by default with per-path overrides such as `public, max-age=31536000, immutable` for hashed assets, `index: [index.html]`, `directory_redirect: true` (308 to the trailing slash), `fallback` off. `fallback: /index.html` (SPA) answers 200 only for GET/HEAD whose last segment has no extension and outside `fallback_except` prefixes, so a missing bundle stays a 404.
- Docker: `rdock.middlewares.<m>.static.*` labels and the shorthand `rdock.static.root`, which creates a terminal `static` middleware for the container's route. The root is on rdock's file system (a volume in Docker); the docs say so first.

### DNS-01 adapters (W-DNS-03)
- New `type`s under `acme.dns_providers`: `route53`, `google_cloud_dns`, `azure_dns`, `digitalocean`, `hetzner`, `desec`, `rfc2136`, behind the existing `DnsSolver` trait. The six HTTP providers are raw REST calls on the existing hyper-rustls client with two signing helpers on ring: AWS SigV4, and RS256 JWTs for Google service accounts and Azure certificate assertions. No cloud SDKs. RFC 2136 uses hickory-proto and hickory-net 0.26.3 (already in the lockfile) with the `dnssec-ring` feature.
- A shared layer handles zone discovery by walking labels (an explicit `zone` short-circuits it; Azure requires it), private-zone skipping, record-set read-modify-write under a per-zone lock for set-based APIs (Route 53, Google, Azure, Hetzner, deSEC) so an apex and a wildcard value coexist, provider change-status polling (Route 53 `INSYNC`, Hetzner actions, Google `done`) **followed by** the existing authoritative-server poll, and backoff with jitter that honours `Retry-After` and the providers' rate-limit headers.
- Safe defaults: secrets only as `${file:…}`/`${env:…}` references; RFC 2136 over TCP with TSIG `hmac-sha256` by default, `hmac-md5` refused, `hmac-sha1` accepted with a warning, unsigned updates only with `insecure_unsigned: true`; 30 s per call; no redirects; cloud endpoints fixed per `environment` (public, US government, China), `api_url` only for tests and only on loopback unless `https`. Static credentials only in v0.6; ambient cloud credentials (instance roles, workload identity) wait for a later `credentials: ambient`.
- Testing: a fake HTTP API in `rdock-testkit` (route table, request recording, failure injection) and one contract test every adapter runs: two values on one name, cleanup of one keeps the other, retry after 429, zone discovery, token file re-read after rotation, private zone skipped. RFC 2136 is tested against an in-process TSIG-verifying server and BIND and Knot containers. Live tests run only on the test server, gated by `RDOCK_LIVE_DNS_<PROVIDER>`.
- `exec` and `webhook` remain the answer for other providers; an `acme-dns` adapter may follow if time allows.

### Connect budget and performance (#181)
- **Per-attempt connect budget** (amends [ADR-0015](0015-status-code-retries.md)): when a retry on `connect` is configured and another eligible backend exists, a non-final attempt may wait at most `timeouts.connect_attempt` (default 1 s) before the next backend is tried; the final attempt keeps the full `timeouts.connect` (default unchanged at 5 s, Envoy's default). Target: the soak's longest request under 1.5 s with the same backend stops. Parallel (Happy Eyeballs style) connects are not adopted unless this misses the target.
- A `profiling` Cargo profile (release with line tables, no stripping, frame pointers) so `perf` gets call graphs; release builds are unchanged.
- The per-core runtime of [#176](https://github.com/Docker-Hunterpedia/ReverseDock/issues/176) is prototyped behind `runtime.model: steal | per_core` (default `steal`): N current-thread runtimes (`pingora_runtime::Runtime::new_no_steal`), one accept loop per thread on a per-thread `SO_REUSEPORT` socket, one `HttpProxy` per listener and thread with `upstream_idle_connections / N` idle connections each. It is adopted as the default only if #176's gate passes; that outcome is recorded in a later ADR either way.

## Consequences
- `gate.rs` stops refusing `tcp` listeners, TCP routes and services, `proxy_protocol` and `providers.swarm` as each lands; the schema, website reference and status badges change with them (`just schema`, `pnpm gen`).
- `SwarmEndpointMode` defaults to `Tasks`; `SwarmProvider` gains `poll_interval`; `ProxyProtocolIn` gains `optional`; `Listener` gains `starttls`; TCP timeouts gain `termination_delay`; `Timeouts` gains `connect_attempt`; `Route.service` becomes `Option<String>`; new `StaticMiddleware` and seven DNS provider types. These are additive or change defaults of features that have not shipped; `Route.service` stays required unless the chain ends with a terminal middleware, so every existing configuration keeps its meaning.
- New dependencies: proxy-header (exact pin), cap-std, http-range-header. No new TLS or crypto stack.
- The data plane gains code on the accept path (PROXY parsing, ClientHello peek); both are fuzzed and bounded by size and time, and HTTP listeners without `proxy_protocol` run exactly as before.
- CI gains a parallel job for single-node Swarm, PostgreSQL passthrough, PROXY protocol and the static suite (about 6–9 minutes); the 3-node Swarm and the 2/4/8-CPU ladder run on rented servers before the release.
- [Architecture §12 and §17](../05-architecture.md) are updated to match.
