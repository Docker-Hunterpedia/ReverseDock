# v0.7 research: Kubernetes

Research note for milestone **v0.7 "Kubernetes"**. Requirements in scope: W-K8S-01…05 (Gateway API controller, Ingress translation, EndpointSlices and Secrets, leader election and RBAC, Helm chart and manifests). Every fact was checked on 2026-11-11 against the source linked next to it; crate facts against crates.io, the published sources and a probe crate built on the repository's own pins. Lines marked *(our reasoning)* are conclusions, not sources; lines marked *unverified* were not confirmed against a primary source. Sections 2 to 5 were researched one topic at a time and read together for section 6. The decision is [ADR-0029](../decisions/0029-kubernetes-gateway-api.md).

## 1. Where we start

- The config model is ahead of the engine again: `providers.kubernetes` parses (`gateway_class`, `namespaces`, `ingress`) and `rdock run` refuses it with "planned for v0.7" (`crates/rdock-proxy/src/gate.rs`). `rdock-provider-kubernetes` is a skeleton (`Cargo.toml`, README, `lib.rs`).
- A provider hands the engine a complete `Snapshot { provider, fragment, diagnostics }` over a `watch` channel; the engine merges fragments under `name@provider` keys, validates, compiles and swaps (ADR-0009, ADR-0018). The Docker and Swarm providers split into a pure translator (inventory in, fragment and diagnostics out) and a small API loop; the Kubernetes provider keeps that split.
- **A fragment carries routes, services, middlewares, TCP routes and TCP services, and nothing else** (`crates/rdock-config/src/merge.rs`). Listeners and certificates belong to the file configuration. In Kubernetes a `Gateway` defines listeners and names TLS Secrets, so this is the first provider that needs to contribute both.
- Listener changes already apply in process without a restart ([ADR-0012](../decisions/0012-own-listeners-pingora-http-engine.md)): new sockets are bound first, unchanged addresses keep theirs, removed listeners drain. Opening a listener for a new Gateway is an ordinary reload.
- Provider snapshots are stored on disk (`state.save_snapshot`) and appear in the configuration history and the admin API. Whatever a fragment carries is therefore visible there; private keys must not be part of it.
- Certificates are loaded from files only (`Certificate { cert_file, key_file }`, `rdock-tls/src/cert.rs`).
- What the data plane already has for Gateway API semantics: rules for host (exact and one-label wildcard), exact path, path prefix, path regex, method, header (exact and regex) and query (exact and regex); explicit route priorities; weighted splits between services (`Service.split`); request mirroring with a percentage; `headers` (set, add, remove, for requests and responses), `redirect`, `rewrite`, `strip_prefix`, `replace_path`, `cors`; `Scheme::H2c` to backends and h2c with prior knowledge on plain listeners (gRPC without TLS); TCP listeners with `HostSNI` passthrough and termination, and `https` listeners that hand a matching ClientHello to a TCP route (v0.6); backends that drain; per-service retries and timeouts.
- What it lacks (checked in the code, section 6 lists the consequences): `PathPrefix` is a string prefix (`router.rs`: `path.starts_with`), not a path-segment prefix; `redirect` can change the scheme and port or apply a regex to the whole URL, but cannot set a hostname, replace a path or a prefix, or choose 303/307/308 by number; nothing answers a fixed status for a share of a route's traffic (Gateway API wants 500 for an invalid backend reference); there is no total request timeout per route (`RouteTimeouts` has connect, read, write).
- The build has cargo features per provider (`docker`, `swarm`); `docs/06-repo-layout.md` already reserves `kubernetes` (on by default), `deploy/helm/reversedock`, `deploy/kubernetes/` and `tests/conformance/gateway-api`.

*(our reasoning)* **Design: one reflector per kind, no `Controller`.** The Docker and Swarm providers already have the shape we need: any change → coalesce (100 ms) → rebuild the whole snapshot → pure `translate(&Snapshot, &KubernetesProvider) -> Translation { fragment, statuses, diagnostics }`. So:
- one `reflector(writer, watcher(api, cfg)).default_backoff().touched_objects()` task per kind, each forwarding "something changed" into one `tokio::sync::Notify`/`mpsc(1)`;
- start-up waits for `wait_until_ready()` on **every** store before the first translation (otherwise the first snapshot has routes without their Services and we would publish 500s and `ResolvedRefs: False` for a moment);
- kinds whose CRD is absent (TCPRoute, UDPRoute, ListenerSet, BackendTLSPolicy on an older install) answer 404 on list: probe the API group with `Discovery`/`Api::list` once at start, skip the missing kinds with one diagnostic, and re-probe on the 60 s reconcile tick;
- when the API server is unreachable the stores simply stop changing: the last snapshot stays in force (the existing "keep last snapshot on loss" rule), and `default_backoff` handles reconnection;
- `ListWatch` stays the initial-list strategy (kube's default; `StreamingList` needs the `WatchList` feature on the API server and was being fixed as late as 5.0.0). `page_size` default (500) is fine;
- Secrets: watch only what is referenced is not expressible in one selector; watch `type=kubernetes.io/tls` with `.fields("type=kubernetes.io/tls")` (a supported field selector for Secrets), namespace-scoped when `providers.kubernetes.namespaces` is set. This keeps other Secrets out of our memory and lets the RBAC stay `list/watch secrets` only;
- EndpointSlices and Services are watched cluster-wide (or per configured namespace) rather than per referenced Service: fewer watches, and the translator needs them atomically.

*(our reasoning)* **Status writes: JSON merge patch on `/status`, computed by the pure translator, sent only when it differs and only by the leader.** For `Gateway`/`GatewayClass` the controller owns the whole `status`, so a merge patch of `{"status": {...}}` is enough. For routes, `status.parents[]` is a list shared with other controllers and merge patch replaces lists whole, so the writer reads the object from the store, keeps entries whose `controllerName` is not ours, replaces ours, and sends the full `parents` array with `metadata.resourceVersion` in the patch body so a concurrent writer causes a 409 and a retry instead of a lost update. Server-side apply would be cleaner in principle, but `parents[]` is an atomic list in the CRD schema (no `x-kubernetes-list-map-keys` usable across controllers with the same parentRef), so SSA gives no per-entry ownership there; Linkerd's fix above is the same read-merge-write. Conditions carry `observedGeneration` and keep `lastTransitionTime` when `status` did not flip (compare with the stored object) so an unchanged status produces no write and no watch echo loop.

```rust
use std::pin::pin;

use futures_util::StreamExt;
use k8s_openapi::api::coordination::v1::Lease;

#[kube(group = "gateway.networking.k8s.io", version = "v1", kind = "Gateway", namespaced)]
#[kube(status = "GatewayStatus", schema = "disabled")]

}

#[serde(rename_all = "camelCase")]
pub struct GatewayStatus {
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    #[schemars(skip)]
    pub conditions: Vec<Condition>,
}

/// `gateway.networking.k8s.io/v1` HTTPRoute (the generated Rust type is `HTTPRoute`).
#[derive(CustomResource, Clone, Debug, Deserialize, Serialize, JsonSchema)]
#[kube(group = "gateway.networking.k8s.io", version = "v1", kind = "HTTPRoute", namespaced)]
#[kube(schema = "disabled")]
#[serde(rename_all = "camelCase")]
pub struct HTTPRouteSpec {
    #[serde(default)]

}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // In-cluster (service-account token, re-read every minute) or kubeconfig.
    let config = Config::infer().await?;
    let client = Client::try_from(config)?;

    let gateways: Api<Gateway> = Api::all(client.clone());
    let routes: Api<HTTPRoute> = Api::all(client.clone());
    let _services: Api<Service> = Api::all(client.clone());
    let _slices: Api<EndpointSlice> = Api::all(client.clone());
    let _secrets: Api<Secret> = Api::namespaced(client.clone(), "default");

    // One reflector per kind: a store kept current by a watcher with backoff.
    let (store, writer) = reflector::store::<Gateway>();
    let stream = reflector(writer, watcher(gateways.clone(), watcher::Config::default()))
        .default_backoff()
        .touched_objects();
    let (route_store, route_writer) = reflector::store::<HTTPRoute>();
    let route_stream = reflector(route_writer, watcher(routes, watcher::Config::default()))
        .default_backoff()
        .touched_objects();
    tokio::spawn(async move {
        let mut s = pin!(route_stream);
        while s.next().await.is_some() {} // each item is "something changed"
    });
    store.wait_until_ready().await?;
    route_store.wait_until_ready().await?;
    for gw in store.state() {
        println!("{}/{}", gw.namespace().unwrap_or_default(), gw.name_any());
    }

    // Status: merge patch on the status subresource.
    let status = serde_json::json!({ "status": { "conditions": [] } });
    Api::<Gateway>::namespaced(client.clone(), "default")
        .patch_status("gw", &PatchParams::default(), &Patch::Merge(&status))
        .await?;
    // Status: server-side apply with our field manager (compiles; not the recommended path, §3).
    let apply = serde_json::json!({
        "apiVersion": "gateway.networking.k8s.io/v1", "kind": "Gateway",
        "status": { "conditions": [] }
    });
    Api::<Gateway>::namespaced(client.clone(), "default")
        .patch_status("gw", &PatchParams::apply("reversedock.dev/gateway-controller").force(), &Patch::Apply(&apply))
        .await?;

    // Leader election: read the Lease, then an optimistic replace (resourceVersion guards the race).
    let leases: Api<Lease> = Api::namespaced(client, "rdock-system");
    if let Some(mut lease) = leases.get_opt("rdock-leader").await? {
        let spec = lease.spec.get_or_insert_default();
        spec.holder_identity = Some("pod-a".to_owned());
        spec.lease_duration_seconds = Some(15);
        leases.replace("rdock-leader", &PostParams::default(), &lease).await?;
    }

    let mut s = pin!(stream);
    while let Some(ev) = s.next().await {
        let _gw = ev?;
    }
    Ok(())
}
```

Notes for implementers:
- `watcher::Config::default().streaming_lists()` also compiles; keep `ListWatch`.
- `Lease.spec.renew_time`/`acquire_time` are `MicroTime` (k8s-openapi 0.29 wraps a `jiff::Timestamp`); jiff is already in the tree through kube, so no `time`/`chrono` conversion is needed in the provider.
- `kube::Error::Api` carries the `Status`; check `.code == 409` for a lost compare-and-swap and `404` for an absent CRD or Lease.
- Library rules still apply: no `unwrap`/`expect` (the probe uses `?` throughout), errors as a `thiserror` enum wrapping `kube::Error`.
- Building `kube::Client` needs a rustls crypto provider; hyper-rustls's `ring` feature selects ring explicitly, so it does not depend on the process-default provider that `rdock` installs.

| The table: `Prefix /` matches all; `Exact /foo` matches only `/foo` (not `/foo/`), `Exact /foo/` not `/foo`; `Prefix /foo` and `Prefix /foo/` both match `/foo` and `/foo/`; `Prefix /aaa/bb` does not match `/aaa/bbb`; `Prefix /aaa/bbb/` matches `/aaa/bbb` ("ignores trailing slash"); `Prefix /aaa/bbb` matches `/aaa/bbb/` and `/aaa/bbb/ccc`, not `/aaa/bbbxyz`; with `/`, `/aaa`, `/aaa/bbb` the longest wins; `Prefix /aaa` vs `/ccc` uses the default backend; `/foo` Prefix + `/foo` Exact on `/foo` prefers Exact | [Examples](https://kubernetes.io/docs/concepts/services-networking/ingress/#examples) |

| `secretName` is optional "to allow TLS routing based on SNI hostname alone. | Missing Secret is not specified by the API. ingress-nginx served its default ("fake" or `--default-ssl-certificate`) certificate; with no `tls:` section it served the default certificate and did not force HTTPS | [ingress-nginx TLS](https://github.com/kubernetes/ingress-nginx/blob/main/docs/user-guide/tls.md) |
| **Status.** `status.loadBalancer.ingress[]` holds `ip` or `hostname` (+ `ports`). ingress-nginx: `--publish-service ns/name` mirrors that Service's addresses, `--publish-status-address` sets fixed ones, `--report-node-internal-ip-address`, `--update-status` (default true), written by the elected leader (`--election-id`). *(our reasoning)*
- Our rule grammar already has exact and one-label wildcard hosts; `Prefix` must be translated to "path == p **or** path starts with p + `/`" (with a trailing slash on `p` dropped first), not to a string prefix. Traefik needed a `strictPrefixMatching` option to get this right; we do it by default.
- Priority must encode: exact host > wildcard host > no host; then longer path; then Exact > Prefix. `ImplementationSpecific` = `Prefix` (documented), not regex.
- Claim an Ingress when (a) `ingressClassName` names an IngressClass with `spec.controller: reversedock.dev/ingress-controller`, or (b) the legacy annotation equals our class name (default `rdock`), or (c) it has neither and `ingress.watch_without_class: true` (default false, like ingress-nginx) — never silently take everything.
- A referenced Secret that is missing or invalid: keep the route, serve HTTP, drop that TLS entry with a diagnostic and an Event; never fall back to a self-signed certificate silently.
- `resource` backends: diagnostic, not supported.
- Status address: `publish_service` (default: the chart's own Service) or a fixed `publish_address`; leader only.

### 3. EndpointSlice (`discovery.k8s.io/v1`)

| Fact | Source |
|---|---|
| `serving`: "currently serving responses, and so it should be used as a target for Service traffic"; maps to the Pod's `Ready`. `terminating`: set when the Pod gets a deletion timestamp. `ready`: "a shortcut for checking "`serving` and not `terminating`" (though it will also always be `true` for Services with `spec.publishNotReadyAddresses` set to `true`)" | [EndpointSlices, Conditions](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/#conditions) |
| "Service proxies will normally ignore endpoints that are `terminating`, but they may route traffic to endpoints that are both `serving` and `terminating` if all available endpoints are `terminating`" (kube-proxy does this, stable in 1.28) | same; [virtual IPs, terminating endpoints](https://kubernetes.io/docs/reference/networking/virtual-ips/#traffic-to-terminating-endpoints) |
| Slices of a Service carry the label `kubernetes.io/service-name`; `endpointslice.kubernetes.io/managed-by` names the writer; default 100 endpoints per slice (max 1000) | [EndpointSlices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/) |
| One slice has one `addressType` (`IPv4`, `IPv6`; `FQDN` deprecated); a dual-stack Service has at least two slices | same |
| "Clients of the EndpointSlice API must iterate through all the existing EndpointSlices associated to a Service and build a complete list of unique network endpoints … endpoints may be duplicated in different EndpointSlices" | [Duplicate endpoints](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/#duplicate-endpoints) |
| Slice `ports[]` are `{name, protocol, port, appProtocol}` and hold the **target** port; with named target ports, pods may map one name to different numbers, "requiring different EndpointSlices". The slice port `name` equals the Service port `name` | [EndpointSlices, Distribution](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/#distribution-of-endpointslices) |
| Endpoints carry `nodeName`, `zone` and `hints`; `spec.trafficDistribution` (`PreferSameZone`, `PreferSameNode`; `PreferClose` deprecated) is expressed through those hints and is a preference with cluster-wide fallback | [Service, traffic distribution](https://kubernetes.io/docs/concepts/services-networking/service/#traffic-distribution), [virtual IPs](https://kubernetes.io/docs/reference/networking/virtual-ips/#traffic-distribution) |
| `appProtocol` is mirrored from the Service port into the slice; values are IANA names, `kubernetes.io/*` or vendor-prefixed | [Service, application protocol](https://kubernetes.io/docs/concepts/services-networking/service/#application-protocol) |
| GEP-1911 (Standard): implementations "MUST recognize" `kubernetes.io/h2c`, `kubernetes.io/ws`, `kubernetes.io/wss`; SHOULD honour the Service port's `appProtocol`; a backend whose protocol cannot be spoken gets `ResolvedRefs=False`, reason `UnsupportedProtocol`. Absence of `appProtocol` must not disable features such as WebSocket upgrades | [GEP-1911](https://gateway-api.sigs.k8s.io/geps/gep-1911/) |
| Gateway API: "Implementations SHOULD NOT support ExternalName Services" (CVE-2021-25740); Core support is for Services of any other type. An invalid backendRef must answer 500 for its share of traffic; a Service with no ready endpoints SHOULD answer 503 | [object_reference_types.go](https://github.com/kubernetes-sigs/gateway-api/blob/main/apis/v1/object_reference_types.go), [httproute_types.go](https://github.com/kubernetes-sigs/gateway-api/blob/main/apis/v1/httproute_types.go) |
| ExternalName Services have no selector and no EndpointSlices; DNS returns a CNAME; the docs warn that HTTP `Host` and TLS names will not match | [Service, ExternalName](https://kubernetes.io/docs/concepts/services-networking/service/#externalname) |
| Traefik routes to pod addresses from EndpointSlices by default; `nativelb` switches a Service to its ClusterIP; ExternalName needs `allowExternalNameServices` (off by default) | [Traefik Ingress routing](https://github.com/traefik/traefik/blob/master/docs/content/reference/routing-configuration/kubernetes/ingress.md), [provider](https://github.com/traefik/traefik/blob/master/docs/content/reference/install-configuration/providers/kubernetes/kubernetes-ingress.md) |

*(our reasoning)*
- Route to **pod addresses from EndpointSlices** (the same choice as Swarm task mode in ADR-0026): our health checks, sticky cookies, retries to another backend and draining only work with one address per pod; the ClusterIP hides them and adds a kube-proxy hop. Offer `endpoints: service` (ClusterIP) per Service by annotation for meshes.
- Backend set = union over all slices with the Service's label, de-duplicated by (address, port). Port resolution: `backendRef.port` → the Service port with that number → its `name` → the slice port with the same name → the number to dial. Never dial `targetPort` read from the Service (it can be a name).
- Conditions: `ready != false` → in the pool. `serving && terminating` → **draining** (existing connections stay, no new requests), used for new requests only when no ready endpoint is left (the kube-proxy fallback). Not serving → out. A nil condition is treated as true, as the API documents.
- Headless Services work unchanged (they have slices). ExternalName: refused by default with `ResolvedRefs=False`/a diagnostic; opt-in `allow_external_name: true`.
- Topology hints: ignored in v0.7 (documented); we balance over all ready endpoints. Dual-stack: use both families' slices.
- `appProtocol`: `kubernetes.io/h2c` → `scheme: h2c`; `kubernetes.io/ws` → http/1.1 (upgrades already work); `kubernetes.io/wss` and `https` → TLS to the backend; GRPCRoute without `appProtocol` → h2c.

| BackendTLSPolicy: Core CA source is a ConfigMap with the bundle in key `ca.crt`; a missing object or key sets `InvalidCACertificateRef` | [backendtlspolicy_types.go](https://github.com/kubernetes-sigs/gateway-api/blob/main/apis/v1/backendtlspolicy_types.go) |
| Traefik and Envoy Gateway charts grant `get/list/watch` on all Secrets cluster-wide (or per namespace in namespaced mode) | [Traefik chart](https://github.com/traefik/traefik-helm-chart/blob/master/traefik/templates/rbac/clusterrole.yaml), [Envoy Gateway chart](https://github.com/envoyproxy/gateway/blob/main/charts/gateway-helm/templates/_rbac.tpl) |

*(our reasoning)*
- RBAC cannot express "only referenced Secrets", so a cluster-wide controller needs `list/watch` on Secrets; reading every Secret of the cluster into memory is the real cost. Limit it three ways: (1) a field selector `type=kubernetes.io/tls` on the watch (the API server supports `type` as a Secret field selector **(unverified today)**), (2) namespace scoping (`providers.kubernetes.namespaces`), (3) keep only referenced Secrets' bytes in the store and never log or expose them through the admin API.
- Validate before use: PEM parses, key matches the leaf, chain order; an invalid Secret keeps the previous good certificate (last known good) and sets `ResolvedRefs=False`/`InvalidCertificateRef`.
- Certificates from Secrets go into the existing in-memory certificate store (ADR-0020), never onto disk.

### 7. Leader election

| Fact | Source |
|---|---|
| The lock is a `coordination.k8s.io/v1` `Lease`: `holderIdentity`, `leaseDurationSeconds`, `acquireTime`, `renewTime`, `leaseTransitions` | [leaderelection.go](https://github.com/kubernetes/client-go/blob/master/tools/leaderelection/leaderelection.go) |

*(our reasoning)*
- Every replica watches, translates and serves; **only status writes (Gateway API conditions and addresses, `Ingress.status.loadBalancer`) and Events are gated by the Lease**. Losing the lease or the API server never affects traffic (ADR-0009).
- Because there is no fencing, status writes must be idempotent and conflict-safe on their own: compute the full desired status, skip the write when it equals what is observed, patch the status subresource with `resourceVersion` (or server-side apply with a field manager), and stop writing as soon as a renewal has not succeeded within `RenewDeadline` measured on a monotonic local clock.
- Implement it in the provider crate on the existing kube client (a ~200-line state machine with the client-go rules above) rather than add a 0.x leader-election dependency; defaults 15 s / 10 s / 2 s, lease name `rdock-controller` in the pod's namespace, identity = pod name, release on SIGTERM.

Routes attached to a Gateway are only bound to that Gateway's internal listeners.
- `status.addresses` = that Service's `status.loadBalancer.ingress` (IP or hostname); for `type: ClusterIP`, the ClusterIP. Service type comes from chart values / GatewayClass parameters (default `LoadBalancer`), with `spec.addresses` honoured through `loadBalancerIP`-style fields only where the platform supports it (otherwise `Programmed=False, AddressNotUsable`).
- Dynamically provisioned: the Service (ports follow listeners), nothing else. A cross-namespace Service selector does not exist, so the per-Gateway Service lives in rdock's namespace, **or** an `EndpointSlice`-backed selectorless Service is written in the Gateway's namespace. *(our reasoning)* Simplest: put the Service in the controller's namespace, named from the Gateway's namespace and name (hash-suffixed to 63 chars), with labels `gateway.networking.k8s.io/gateway-name` and the Gateway namespace; ownerReferences cannot cross namespaces, so the controller deletes it with a finalizer-free sweep (list by label, delete those whose Gateway is gone).
- RBAC cost over shape (a): `create/update/delete` on `services` in one namespace. No Deployments, no image templating, no per-Gateway upgrades.
- Shape (c) stays as a documented chart option (`kind: DaemonSet`, `hostPort`) for single-node k3s and bare metal, with the stated limit of one Gateway per port; a per-Gateway Deployment (shape b) can come later without changing the API.

`GatewayInfrastructureMetadata` (extended, feature `GatewayInfrastructure`) expects `spec.infrastructure.labels/annotations` on generated components; with a per-Gateway Service these can be copied onto the Service *(unverified whether the test also requires Pods to carry them — read `tests/gateway-infrastructure.go` before claiming the feature)*.

## 6. What the findings mean together *(our reasoning)*

### Gap analysis: Gateway API against the data plane

| Gateway API needs | Today | What v0.7 does |
|---|---|---|
| Listeners defined by `Gateway` objects, several Gateways each on port 80 with their own address | listeners only in the file configuration | fragments may carry listeners; one Service per Gateway maps the listener port to an internal port of the shared pods, so the local port identifies the Gateway |
| TLS certificates from Secrets, rotated without a restart | certificates from files | the provider writes Secret contents to files in a private directory (mode 0600) and contributes `certificates` that name them; the fragment never holds key material |
| `PathPrefix` by path segment | string prefix | the translator emits ``Path(`/a`) \|\| PathPrefix(`/a/`)``; the router is unchanged |
| Precedence: exact path, longest prefix, method, header count, query count, route age, name, rule order | `priority`, then rule length | the translator computes an explicit priority per match |
| 404 without a matching rule | yes | nothing |
| 500 for an invalid backend reference, for its weighted share | no | a service that answers a fixed status (a split target like any other) |
| 503 when a Service has no ready endpoint | yes ("the service has no available backend") | nothing |
| `RequestHeaderModifier`, `ResponseHeaderModifier` | `headers` | translate |
| `RequestRedirect`: hostname, scheme, port, full path, prefix replacement, 301/302/303/307/308 | scheme and port, or a regex | `redirect` gains `hostname`, `path`, `prefix` and `status` |
| `URLRewrite`: hostname, full path, prefix replacement | `replace_path`, `rewrite` (regex), `headers.request.set.Host` | translate; prefix replacement as an anchored regex |
| `RequestMirror` with a percentage | `mirror` (one target) | translate; several mirrors are not claimed |
| `timeouts.request`, `timeouts.backendRequest` | connect, read, write | `backendRequest` maps to `read`; a total request timeout is added only if it is small, otherwise the feature is not claimed |
| GRPCRoute: service and method, headers, h2c and TLS | path and header rules, `Scheme::H2c` | translate (`/service/method` paths) |
| TLSRoute passthrough by SNI | TCP routes with `HostSNI`, also on `https` listeners | translate |
| TCPRoute | TCP routes with ``HostSNI(`*`)`` | translate |
| UDPRoute | UDP is planned for v0.8 (M-L4-04) | the listener reports `UnsupportedProtocol`; the route is not accepted |
| Pod addresses from EndpointSlices, draining on `terminating` | backends that drain | translate; `ready` in the pool, `serving && terminating` drained |
| Status on every object, written by one replica | no writer to any provider | status as a pure function next to the translator; written by the leader only |

### Choices the facts force

- **Gateway API v1.7.0, Standard channel, `v1` only.** Every kind in W-K8S-01 is `v1` there. The requirements and roadmap text ("v1.7 at rc", "once Standard", "as they leave provisional status") is corrected in the same pull request.
- **kube 5.0.0 with our own resource types.** The gateway-api crate 0.22.0 needs Rust 1.92, kube 4 and is generated from Gateway API v1.5.1; hand-written `#[derive(CustomResource)]` types with only the fields we read build on our MSRV and pins, add no banned crate and keep the dependency count at 43 new crates.
- **A shared data plane with one Service per Gateway.** One address for all Gateways cannot pass two core conformance tests; a Deployment per Gateway would need the controller to template and upgrade pods. A Service per Gateway in front of the shared pods costs write access to `services` in one namespace.
- **The leader writes, every replica serves.** All replicas watch, translate and serve identically and are Ready after their first full sync; only the Lease holder writes status, Events and the per-Gateway Services. client-go's leader election gives no fencing, so every write is idempotent and computed from the same inputs.
- **Our own Lease loop** (about 200 lines, client-go's algorithm and timings) instead of a 0.x dependency that either needs kube 4 or brings its own algorithm.
- **Ingress is a landing pad, not a second product.** `networking.k8s.io/v1` is implemented as specified; the ingress-nginx annotations that map one to one onto an existing middleware are honoured, every other one is a diagnostic, and `*-snippet` annotations are refused.
- **ACME inside the cluster is off unless asked for.** Replicas share no certificate storage until v0.9; cert-manager is the supported way to get certificates in Kubernetes, and its HTTP-01 solver needs the challenge route to outrank both the application's `/` route and our own http→https redirect.

### What can be proven where

- In a development sandbox without nested containers: unit tests of the translator and the status function on fixtures; integration tests of the controller against a standalone `kube-apiserver` and etcd (watches, status patches, Lease, Service provisioning, restricted RBAC); the data plane on the host with hand-written EndpointSlices that point at local backends; `helm lint` and `helm template`.
- Only in GitHub Actions: the upstream conformance suite on kind, the Helm install on k3s. Those jobs start as informational and are promoted to required checks when the core tests of `GATEWAY-HTTP`, `GATEWAY-GRPC` and `GATEWAY-TLS` pass; until then the conformance claim is "implemented, not yet proven", and the documentation says so.
