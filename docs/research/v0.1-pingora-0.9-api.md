## 0. Findings that change plans (read first)

1. **tokio ≥ 1.54.0 breaks Pingora 0.9.0 at runtime.**
   - tokio 1.54.0 (released 2026-10-19, "io: panic when BufReader or BufStream is created with zero capacity (#8494)", `tokio:CHANGELOG.md:31`) added `assert!(capacity > 0)` (`tokio:src/io/util/buf_reader.rs:51`).
   - `impl From<TcpStream> for Stream` calls `BufStream::with_capacity(0, 0, ..)` (`core:protocols/l4/stream.rs:546-566`, call at :549). It does the same for UDS and virtual streams.
   - Result: every accepted connection panics the accept loop. The listener dies and the process keeps running. **[run]** see `live_probe_tokio-1.54.1_panic.log`.
   - All Pingora crates require `tokio = "1"`, so a fresh `cargo update` picks 1.54.1.
   - **Pin `tokio` to `<1.54` workspace-wide** (1.53.3 verified, MSRV 1.71) and block Dependabot/Renovate from bumping it until Pingora ships a fix.
2. **Building Pingora requires CMake and a C compiler, whatever TLS backend you pick.**
   - `pingora-core` depends on `flate2` with feature `zlib-ng`, which pulls `libz-ng-sys`, which builds zlib-ng with CMake.
   - `zstd-sys` and `ring` need `cc`.
   - `cargo check` fails without CMake **[run]**: "is `cmake` not installed?".
   - `ring` is C plus assembly, not "pure Rust".
   - The default crate features are `default = []`, which means **no TLS at all** (`noop_tls`), not OpenSSL.
3. **Pingora's rustls backend is hard-wired to `ring`, not aws-lc-rs.**
   - `pingora-rustls` enables rustls features `ring`, `logging`, `std`, `tls12` and depends on `ring` directly (`prls` Cargo.toml).
   - `install_default_crypto_provider()` installs ring (`prls:44-46`). Pingora calls it in `TlsSettings::build` and in the connector.
   - aws-lc-rs works only if *we* call `CryptoProvider::install_default(aws_lc_rs)` first. ring stays linked either way: `hash_certificate` uses `ring::digest` (`prls:188-191`).
   - ring offers no post-quantum key exchange: the kx groups are X25519, P-256 and P-384 only (`rustls:crypto/ring/mod.rs:180-181`).
4. **MSRV 1.89: passes, but only with an MSRV-aware lockfile.**
   - Resolution with `rust-version = "1.89"` and resolver 3 gives "Locking 240 packages to highest Rust 1.89 compatible versions". `cargo +1.89 check --examples` then passes.
   - With an unconstrained lockfile, 1.89 fails. `pingora-lru` declares `parking_lot = "0"`, which resolves to parking_lot 0.13.0 / lock_api 0.5.0 / parking_lot_core 0.10.0, and those require **rustc 1.95**.
   - Pingora's own crates declare only 1.85 (`pingora-proxy`, `pingora-cache`) or nothing at all.
   - The real floor is **1.88**, from `time` 0.3.55, which comes in via x509-parser → asn1-rs through the `rustls` feature.
5. **Graceful shutdown is a fixed sleep, and in-flight requests are cut when it ends.**
   - SIGTERM, or a programmatic `GracefulTerminate`, does the following:
     - stops accepting at once;
     - closes idle keep-alive connections at once **[run]**;
     - sends GOAWAY on h2;
     - **then sleeps `grace_period_seconds` unconditionally**, even when nothing is in flight. The default is `None`, which means **300 s** (`core:server/mod.rs:63,800-813`).
   - After the sleep, `Runtime::shutdown_timeout(graceful_shutdown_timeout_seconds, default 5 s)` drops every remaining task.
   - **[run]** A stream that started before shutdown ended exactly at the end of the grace period: 2.005 s with grace 2 s and timeout 2 s.
   - Docker's default 10 s stop timeout will SIGKILL a process that keeps the default. Always set both values.
6. **Status-code retries (502/503/504) work without a fork.** This refutes ADR-0010.
   - Return an `Err` with `retry = true` from `upstream_response_filter`. Nothing has been written downstream at that point.
   - The error flows through `error_while_proxy`, then into the retry loop, which calls `upstream_peer()` again (`proxy:proxy_h1.rs:869`, `proxy:proxy_h2.rs:893`, `proxy:lib.rs:1280-1316`).
   - **[run]** The upstream answered 503 and then 200. The client received 200 with `tries=2`. A POST was not retried, because of the default policy.
7. **Listener bind failures are silent.**
   - `Listeners::build(..).expect("Failed to build listeners")` runs inside the service task (`core:services/listening.rs:293`).
   - A bind error panics that service's thread. The process keeps running and the other listeners keep serving **[run]**.
   - `EADDRINUSE` is first retried 30 × 1 s (`core:listeners/l4.rs:62-63,274-286`).
   - Fix (verified): pre-bind the sockets ourselves, call `set_nonblocking(true)`, and insert the raw fds into Pingora's fd table from a wrapper service (§2.6). Without non-blocking mode, a runtime worker blocks in `accept()` **[run]**.
8. **TLS: the standard listener path takes only `TlsSettings`.**
   - What works with `TlsSettings`:
     - A custom `ResolvesServerCert`. Runtime certificate swap is verified **[run]**.
     - ALPN h2.
     - A client-cert verifier.
     - The SNI capture callback.
   - What is fixed and cannot be changed:
     - TLS 1.2 and 1.3 are always both on (`core:listeners/tls/rustls/mod.rs:62`).
     - Cipher suites come from the process-default provider.
     - Session tickets are never produced.
     - ALPN can be only one of H1, H2, H2H1 or a single custom protocol.
   - **Consequence for TLS-ALPN-01:** `acme-tls/1` plus h2 on one listener is impossible. The handshake fails with alert 120 `no_application_protocol` **[run]**.
   - `Acceptor::from_server_config` exists (`core:listeners/tls/rustls/mod.rs:236`), but **it cannot be attached to a `Service` listener**. It needs our own accept loop that feeds `HttpProxy` as a `ServerApp`. Verified working: TLS 1.3-only policy, 3 ALPNs, SNI capture **[run]**, §8.3.
9. **The upstream connection pool shares connections across different trust settings.**
   - `HttpPeer::reuse_hash` covers address, scheme, proxy, SNI, client cert, `verify_cert`, `verify_hostname`, `alternative_cn`, `group_key`, `max_h2_streams`, curves and `second_keyshare` (`core:upstreams/peer.rs:777-801`).
   - It does **not** include `ca`, `alpn` or timeouts.
   - **[run]** A peer that uses system roots (which fail against our test CA) reused a pooled connection that a custom-CA peer had verified, and succeeded.
   - Always set `peer.group_key` to a hash of the TLS trust policy.
10. **What the HTTP/1 parser accepts and rejects (all [run]).**
    - Accepted, against RFC MUSTs or common strictness:
      - HTTP/1.1 requests without Host;
      - bare-LF line endings;
      - `Transfer-Encoding: gzip, chunked`;
      - lowercase or unknown methods;
      - spaces in the request-target, which Pingora silently percent-encodes (`/in spect` becomes `/in%20spect`).
    - Rejected with 400: duplicate or differing Content-Length, obs-fold, space before the colon, NUL, `chunked, identity`, TE in HTTP/1.0, duplicate Host, absolute-form whose Host does not match, userinfo, more than 256 headers, header blocks over 1 MiB.
    - Requests rejected by the parser (and CONNECT, which gets 405) **never reach any `ProxyHttp` hook, including `logging()`.** 16 of the 32 vectors bypassed logging.
    - Pingora-generated errors carry `Server: Pingora` (`core:protocols/http/error_resp.rs:28`).
11. **Hop-by-hop headers are stripped on requests but not on responses.**
    - Toward the upstream, Pingora strips Connection, Connection-nominated fields, Keep-Alive, Proxy-Connection, Proxy-Authorization, TE, Trailer, Transfer-Encoding, Upgrade and HTTP2-Settings (`proxy:proxy_common.rs:178-189`) **[run]**.
    - Toward an HTTP/1 client, the upstream's `Keep-Alive` and Connection-nominated headers (for example `X-Secret`) **are forwarded unchanged**. Only `Connection` is overwritten **[run]**.
    - `X-Forwarded-For` from the client passes through. Pingora adds no forwarding headers.
12. **Compression module surprises (all [run]).**
    - The level applies to *every* algorithm, so `br, gzip` produces Brotli.
    - If only gzip is enabled and the client lists `br` first, nothing is compressed. Only `Vary` is added.
    - q-values are ignored, so `gzip;q=0` still gets gzip.
    - SSE (`text/event-stream` matches `text/`) is buffered until the end of the stream: one 62-byte block arrived at 1510 ms instead of a chunk every 300 ms.
    - 206 responses are not excluded.
    - Accept-Encoding is parsed in the module's request phase. Compression enabled *later* in `request_filter` sees an empty list unless you re-feed the request (§12).
13. **h2c on a cleartext listener removes the first-byte timeout.**
    - Pingora `read_exact`s 24 bytes to look for the h2 preface, with no timeout (`core:protocols/l4/stream.rs:646-655`, `core:apps/mod.rs:281-298`).
    - **[run]** An 18-byte `GET / HTTP/1.0\r\n\r\n` hung with no response.
    - Idle sockets can therefore be held forever.
14. **Overriding `error_while_proxy` can panic.**
    - Errors on reused connections carry `RetryType::ReusedOnly`. `Error::retry()` panics with "Retry is not decided" (`err:77`) unless you call `e.retry.decide_reuse(client_reused)` or `set_retry(..)`.
    - Pingora does **not** stop retries after response headers were sent downstream. Your hook must check `session.response_written().is_none()`.

### 1.5 Signals (`core:server/mod.rs:150-178`, `main_loop` at :240-325)
`UnixShutdownSignalWatch` (default `RunArgs`) maps:
- `SIGQUIT` → `GracefulUpgrade`
- `SIGTERM` → `GracefulTerminate`
- `SIGINT` → `FastShutdown`

Nothing else is handled. Daemon mode also uses `SIGUSR1` between child and parent. **SIGHUP is not registered**: its default action kills the process, so register it early.

**[run]** A tokio `signal(SignalKind::hangup())` inside a background service received `kill -HUP` while Pingora ran (hits=1, process alive). tokio signal handling is process-wide and fan-out, so there is no conflict. The window before that service starts is still exposed. If that matters, register earlier, for example with `signal-hook`'s safe `flag::register` in `main`.

### 1.6 Custom shutdown / programmatic shutdown (verified)
```rust
#[async_trait] pub trait ShutdownSignalWatch { async fn recv(&self) -> ShutdownSignal; }   // :144-148 (Self: Sync via async_trait)
pub enum ShutdownSignal { GracefulUpgrade, GracefulTerminate, FastShutdown }             // :131-140
pub type ShutdownWatch = tokio::sync::watch::Receiver<bool>;                             // :125

struct RdockShutdown { rx: tokio::sync::Mutex<tokio::sync::mpsc::Receiver<ShutdownSignal>> }
#[async_trait] impl ShutdownSignalWatch for RdockShutdown {
    async fn recv(&self) -> ShutdownSignal {
        use tokio::signal::unix::{signal, SignalKind};
        let (Ok(mut term), Ok(mut int), Ok(mut quit)) =
            (signal(SignalKind::terminate()), signal(SignalKind::interrupt()), signal(SignalKind::quit()))
            else { return ShutdownSignal::FastShutdown };
        let mut rx = self.rx.lock().await;
        tokio::select! {
            _ = term.recv() => ShutdownSignal::GracefulTerminate,
            _ = int.recv()  => ShutdownSignal::FastShutdown,
            _ = quit.recv() => ShutdownSignal::GracefulUpgrade,
            s = rx.recv()   => s.unwrap_or(ShutdownSignal::GracefulTerminate), // our "restart required" path
        }
    }
}
server.run(RunArgs { shutdown_signal: Box::new(RdockShutdown { rx: Mutex::new(rx) }) });
std::process::exit(exit_code);
```
A custom watch replaces the default handlers, so it must register SIGTERM, SIGINT and SIGQUIT itself (as above). `recv()` is polled on a dedicated 1-thread "Server" runtime (:780-790).

### 1.7 Runtimes and threads
- `run()` creates **one tokio runtime per service** (`run_service` :390-446, `create_runtime` :859-871). The runtime is built with `enable_all()` (pingora-runtime `lib.rs:467-478`) and its thread name is the service name (16 chars).
- Threads per service = `service.threads()`, otherwise `conf.threads` (:727).
- `GenBackgroundService.threads` defaults to `Some(1)` (`core:services/background.rs:76`).
- A separate 1-thread "Server" runtime runs `main_loop`.
- Each `HttpProxy` also owns **its own upstream connection pool** (`proxy:lib.rs:222`). Many proxy services mean many pools and many runtimes. Prefer one proxy service that carries all listeners.

### 1.8 `ExecutionPhase` (`core:server/mod.rs:83-121`)
The phases are Setup, Bootstrap, BootstrapComplete, Running, GracefulUpgradeTransferringFds, GracefulUpgradeCloseTimeout, GracefulTerminate, ShutdownStarted, ShutdownGracePeriod, ShutdownRuntimes and Terminated. **[run]** Observed order: Running → GracefulTerminate → ShutdownStarted → ShutdownGracePeriod → ShutdownRuntimes → Terminated. Use these phases for `/readyz` and metrics, but note that "Running" does **not** mean the listeners are bound (§2.6).

- The `add_*` methods "have no effect if the server is already started" (:132).
- The address is a string. `to_socket_addrs()` takes the first result and may do blocking DNS (`core:listeners/l4.rs:246-250`). It is also the **fd-table key used for upgrades**, matched exactly.
- **`TcpSocketOptions`** (`#[non_exhaustive]`, `Default`; `core:listeners/l4.rs:96-123`). Build it with `let mut o = TcpSocketOptions::default(); o.x = ..`. Fields:
  - `ipv6_only: Option<bool>`
  - `tcp_fastopen: Option<usize>` (backlog)
  - `tcp_keepalive: Option<TcpKeepalive>`
  - `dscp: Option<u8>`
  - `so_reuseport: Option<bool>` (off by default)
  - `tcp_snd_buf` / `tcp_recv_buf: Option<usize>` (accepted sockets)
- `SO_REUSEADDR` is always set (:261-263). The backlog is fixed at 65535 (:65). `TCP_NODELAY` is always set on accepted sockets (:433).
- **`TcpKeepalive { idle, interval, count, #[cfg(target_os="linux")] user_timeout }`** (`core:protocols/l4/ext.rs:762-777`) has no `Default`. Struct literals need the cfg'd field.
- **`L4BufferSettings { read: Option<usize>, write: Option<usize> }`** (defaults 64 KiB read, 1460 B write; `core:protocols/l4/stream.rs:363,370,377-420`). ### 2.6 Bind behaviour and the verified pre-bind pattern
- How Pingora binds: `ListenerEndpointBuilder::listen` (`core:listeners/l4.rs:335-389`) looks the address string up in the fd table first. If it is found, it adopts the fd with `from_raw_fd`. Otherwise it binds and **adds** the fd to the table, which is what SIGQUIT later sends.
- Failure handling: AddrInUse is retried 30 × 1 s (:274-286). After that, or on any other error, the service task panics (`core:services/listening.rs:293`) **[run]**.
- Verified wrapper (`examples/lifecycle_edges.rs`):
```rust
struct PreBound { inner: Service<HttpProxy<P>>, prebound: Vec<(String, std::net::TcpListener)> }
#[async_trait] impl ServiceWithDependents for PreBound {
    async fn start_service(&mut self, #[cfg(unix)] fds: Option<ListenFds>, shutdown: ShutdownWatch,
                           listeners_per_fd: usize, ready: ServiceReadyNotifier) {
        if let Some(t) = fds.as_ref() { for (addr, l) in self.prebound.drain(..) { t.lock().add(addr, l.into_raw_fd()); } }
        ServiceWithDependents::start_service(&mut self.inner, fds, shutdown, listeners_per_fd, ready).await
    }
    fn name(&self) -> &str { "rdock http" }
    fn listen_addresses(&self) -> Option<Vec<String>> { ServiceWithDependents::listen_addresses(&self.inner) }
}
// main: let l = TcpListener::bind(addr)?;  l.set_nonblocking(true)?;   inner.add_tcp(addr) // same key string
```
- What the pattern gives us:
  - bind errors are synchronous, so we report and set the exit code ourselves;
  - readiness is known;
  - systemd socket activation becomes possible: insert fds 3.. after `set_nonblocking`.
- Limitations:
  - `TcpSocketOptions` bind-time options (reuseport, v6only, fastopen) are **not** applied to adopted fds. Set them on our own socket.
  - Per-connection options (keepalive, dscp, buffers) still apply.
- `pingora::server::Fds` (`add`, `get`, `close_unclaimed`) and `ListenFds = Arc<Mutex<Fds>>` are public (`core:server/mod.rs:57,127`).

**Call order** (`proxy:lib.rs:1148-1365`, `proxy_h1.rs`):
1. Header parse (parser errors give 400 and **stop here**). CONNECT gives 405 (`proxy:lib.rs:322-398`).
2. `new_ctx`, then `on_connection_reuse`, then `early_request_filter`.
3. Downstream modules' `request_header_filter`, then `request_filter`.
4. Cache phase, then `proxy_upstream_filter`.
5. The attempt loop runs up to `max_retries` times:
   1. `upstream_peer`, then connect. On failure, `fail_to_connect` (retry if marked).
   2. `connected_to_upstream`.
   3. Hop-by-hop sanitize, then `upstream_request_filter`, then the request header is written.
   4. Duplex phase: `request_body_filter` for each chunk on the request side. On the response side: `upstream_response_filter`, then `response_filter`, then the modules' header filter, then `upstream_response_body_filter` / `response_body_filter`, then trailer filters.
   5. Any error goes to `error_while_proxy`, which decides whether to retry.
6. `fail_to_proxy` (only on final error), then `logging`, then `finish` (keep-alive reuse).

## 6. Downstream protocols (Q6)

- **h2c prior knowledge:** `HttpServerOptions.h2c = true`. There is **no** `Upgrade: h2c` support. Watch the peek hang from §0.13. **[run]** curl `--http2-prior-knowledge` got `HTTP/2 200`. Sent to a listener without h2c, it got no response.
- **ALPN h2 over TLS:** `TlsSettings::enable_h2()` sets ALPN to `[h2, http/1.1]` (`core:listeners/tls/rustls/mod.rs:109`). The default is **no ALPN**, which means h1 only. **[run]** "ALPN: server accepted h2".
- **WebSocket (HTTP/1.1 Upgrade)** **[run]**:
  - The upstream received a normalized `Connection: Upgrade` and `upgrade: websocket`. `Sec-WebSocket-*` headers and custom headers were kept.
  - The 101 was relayed and bytes were echoed through the tunnel.
  - Non-WebSocket `Upgrade: foo` is stripped under `WebSocketOnly`. If the upstream answers 101 anyway, Pingora returns **502** ("mismatched upstream/downstream upgrade status", `proxy:lib.rs:1037-1063`).
  - 101 turns keep-alive off. The upgraded body is close-delimited (`core:protocols/http/v1/server.rs:860-903`).
- **RFC 8441 (WebSocket over h2) is not supported.**
  - Extended CONNECT is not enabled in the default `H2Options`.
  - A CONNECT reaching the proxy gets 405 unless `allow_connect_method_proxying` is set.
  - There is no translation of `:protocol` to an h1 Upgrade (only an authority check at `core:protocols/http/v2/server.rs:338-353`).
- **gRPC:**
  - It needs h2 on both legs.
  - **h2→h2**: response trailers are forwarded (`proxy:proxy_h2.rs:1238-1270`, `core:protocols/http/v2/server.rs:713`). `TE: trailers` is forwarded, because the h2 downstream is not sanitized (`proxy:proxy_h2.rs:148-161`).
  - **Any h1 leg drops trailers:**
    - h1 response trailers are discarded (`core:protocols/http/v1/body.rs:816`);
    - writing trailers to an h1 client is a no-op (`core:protocols/http/server.rs:253-260`);
    - TE is stripped for h1→h2 and h2→h1 **[run]**.
  - Request trailers are never forwarded.
  - If an h2 upstream asks to downgrade and the peer is h2-only, Pingora does not retry (`proxy:lib.rs:443-455`).
  - The `grpc_web` module exists (`core:modules/http/grpc_web.rs`).
- **Streaming and backpressure:**
  - Halves are connected by bounded `mpsc` channels of **4 `HttpTask`s** (`proxy:lib.rs:81`). Body reads are at most 64 KiB (`core:protocols/http/v1/body.rs:31`). The h1 retry buffer copies the first 64 KiB of every request body and frees it once truncated (`core:protocols/http/body_buffer.rs`).
  - **[run]** SSE without compression arrived every ~300 ms with no buffering.
- **100-continue:** the proxy **never** sends `100 Continue` itself. `Expect` is forwarded, and the upstream's 100 is relayed to h1 clients. h2 clients never see 1xx; they are ignored (`core:protocols/http/v2/server.rs:629-634`). **[run]** Nothing arrived within 1.5 s; after the body was sent, 200.
- **CONNECT:** 405 by default (`proxy:lib.rs:376-396`) **[run]**.

### 9.2 Default `fail_to_proxy` (`proxy:proxy_trait.rs:631-669`)
1. `HTTPStatus(c)` gives `c`.
2. Otherwise the code depends on the source:
   - `Upstream` → 502;
   - `Downstream` → 0 for Write/Read/ConnectionClosed (dead connection, nothing is written), otherwise 400;
   - `Internal` or `Unset` → 500.
3. If the code is not 0, Pingora calls `session.respond_error(code)` with an empty body, `Server: Pingora`, `Cache-Control: private, no-store` (`core:protocols/http/error_resp.rs:26-36`).
4. It returns `can_reuse_downstream: false`. Then Pingora logs `error!("Fail to proxy: ..")` unless `suppress_error_log` is set (`proxy:lib.rs:1347-1359`).

### 9.3 Custom error page
Override `fail_to_proxy`, compute the code the same way, build a `ResponseHeader` with our body, and call `session.as_downstream_mut().write_error_response(resp, body).await` (compile-verified, `api_surface.rs`). It is skipped automatically once a final response was written.

### 9.4 Retries (ADR-0010 relevant)
- Built-in retryable errors:
  - h1 `ConnectionClosed` or OS `ReadError` while reading the **response header** on a connection, marked `ReusedOnly` (`core:protocols/http/v1/client.rs:405-430`);
  - h2 GOAWAY or REFUSED_STREAM, marked `true` (`core:protocols/http/v2/client.rs:509-565`).
- Connect errors are retried only when `fail_to_connect` marks them.
- The default `error_while_proxy` blocks retries for non-idempotent methods or when the 64 KiB retry buffer is truncated. It does **not** look at `response_written()`.
- The retry buffer (≤ 64 KiB) is replayed on each attempt (`proxy:proxy_h1.rs:483-499`).
- **Status-code retry (verified):**

All `adjust_*` methods **panic in BodyPhase**.
- **Behaviour** (`compression/mod.rs:312-1160`):
  - Algorithms are gzip, br and zstd. Decompression supports gzip and br. There are **no Cargo features**: all three are compiled in.
  - The ctx compresses with the **first** recognized Accept-Encoding token (`decide_action` :689-727). q-values are ignored (TODO at :597).
  - It decompresses when the upstream's `Content-Encoding` is not accepted and decompression is enabled.
  - MIME allow-list: `^(text/|application/|font/|image/(x-icon|svg+xml|nd.microsoft.icon)|binary/octet-stream)`, excluding anything containing "zip" (:984-1024). That covers `application/grpc` and `text/event-stream`.
  - Minimum Content-Length is 20 bytes.
  - It adds `Vary: Accept-Encoding` even when it then does nothing **[run]**.
  - It removes `Content-Length` and `Accept-Ranges`, sets `Transfer-Encoding: chunked`, and weakens or clears the ETag (:1103-1160).
  - There is no status check, so 206 responses are compressed. 101 and bodiless responses are skipped.
  - The gzip encoder only flushes at the end (`compression/gzip.rs:96-110`), so SSE is buffered **[run]**.
- **Recipe:**
  - Enable the module globally at the desired level. Remember that level 0 disables per algorithm (br/zstd at 0 means no fallback **[run]**).
  - In `request_filter`, disable it per route: `adjust_level(0)`.
  - In `response_filter`, disable it for `text/event-stream`, `application/grpc*`, 206, `Content-Range`, and existing `Content-Encoding`.
  - If compression must be enabled only after `request_filter` decided the route, also call `c.request_filter(session.downstream_session.req_header())`. This uses a disjoint field borrow (compile-verified).

  2. Accept loops break and listeners close; new connections are refused (`core:services/listening.rs:208-227`).
  3. `HttpProxy::http_cleanup` wakes idle keep-alive readers and closes their connections immediately (`proxy:lib.rs:1598-1602`).
  4. New H1 responses carry `Connection: close` (`proxy:lib.rs:1582-1585`).
  5. h2 connections get `graceful_shutdown()` / GOAWAY (`core:protocols/http/v2/server.rs:161-164`).
  6. Background services see `shutdown.changed()`.
  7. The main thread sleeps `grace_period_seconds` (default 300 s), **always**.
  8. Each runtime gets `shutdown_timeout(graceful_shutdown_timeout_seconds, default 5 s)`, which drops tasks. **In-flight requests are cut at the end of the grace period.**
  9. `run()` returns.
- **SIGINT / `FastShutdown`:** no grace and timeout 0, so it is immediate.
- **SIGQUIT / `GracefulUpgrade`** (:273-323):
  1. If the fd table is not empty, `Fds::send_to_sock(upgrade_sock)` connects up to 5×1 s and sends the fds by SCM_RIGHTS with the bind-address list.
  2. It always sleeps `CLOSE_TIMEOUT` = 5 s (:66) and then follows the graceful path.
  3. If no new process is listening, the error is logged and the process still exits gracefully.
  - **Limits:**
    - Linux only (`core:server/transfer_fd/mod.rs:128,228-239,382-393`);
    - at most **32 fds** (`MAX_FDS`, :138);
    - the receiver sets `MSG_CMSG_CLOEXEC` (:208).
- **`--upgrade` (`Opt.upgrade = true`):** `bootstrap()` binds `upgrade_sock` and waits up to 5×1 s for the old process (`accept_with_retry_timeout`). On failure it calls `exit(1)`. It then closes inherited fds whose addresses no service claims (`close_unclaimed`, `core:server/bootstrap_services.rs:246-270`). New addresses are bound fresh. So **a new process can have a different listener set**, which helps H-PERF-04.
- **Runtime add or remove of listeners in a running process:**
  - Confirmed impossible for Pingora-managed listeners: `add_*` has no effect after start, and `run(self)` consumes the `Server`.
  - Possible with an own listener service (§2.7).

## 14. Logging and metrics (Q14)

- Pingora logs through the **`log`** crate (`log = 0.4` in every crate). Only `h2` uses `tracing`.
- To bridge into tracing, use `tracing-subscriber` with the `tracing-log` feature (`LogTracer`).
- Noisy `error!` sites:
  - "Downstream handshake error" for every failed TLS handshake (`core:services/listening.rs:241-249`);
  - "Fail to proxy" for every final error (`proxy:lib.rs:1350`);
  - "H2 handshake error" (`core:apps/mod.rs:312`).
- Filter them by target, or use `suppress_error_log`.
- Metrics: pingora-core has none built in. `pingora-prometheus` 0.9.0 uses `prometheus` 0.14's **default registry**, so register `rdock_*` with the re-exported `pingora_prometheus::prometheus`.
- Per-connection timing: `TimingDigest { established_ts, establishment_duration, offload_wait_duration }` (`core:protocols/digest.rs:49-66`).
- Pool idle metrics: `ConnectorOptions.keepalive_pool_callback`.
- Unexpected-data counters: `HttpProxy::unexpected_data_connection_count()`.

## 15. Other relevant 0.9.0 features (Q15)

- **`connection_filter`** (pingora feature, which forwards to core and proxy):
  - With the feature: `#[async_trait] trait ConnectionFilter: Debug + Send + Sync { async fn should_accept(&self, addr: Option<&std::net::SocketAddr>) -> bool }` (`core:listeners/connection_filter.rs:66-95`). The doc examples show `&SocketAddr`, which is wrong.

- **Virtual L4 streams:** `core:protocols/l4/virt.rs`.
- **`pingora::prelude`** (`pingora-0.9.0/src/lib.rs:81-101`) contains:
  - `Opt`, `Server`, `background_service`, `HttpPeer`;
  - every `ErrorType` variant and `pingora_error::*` (`Error`, `ErrorType`, `ErrorSource`, `RetryType`, `Result`, `BError`, `OrErr`, `OkOrErr`, `Context`, `ImmutStr`);

  - proxy: `http_proxy`, `http_proxy_service`, `ProxyHttp`, `ProxyWarnLogContext`, `Session`.
- `pingora::time` needs feature `time`; `pingora::prelude::timeout` does not.
- **Hidden dependencies:**
  - `serde_yaml` 0.9.34+deprecated, which pulls `unsafe-libyaml` (RUSTSEC unmaintained), comes unconditionally with pingora-core for `ServerConf::from_yaml` (`core:server/configuration/mod.rs:352`). This conflicts with ADR-0011's "no unsafe YAML parser in the binary".

## 17. Gotchas (consolidated)

1. Pin **tokio < 1.54** (zero-capacity BufStream panic). Watch every lockfile update.
2. Install **CMake + cc** in CI, the Dockerfile builder and contributor docs. Do not expect a pure-Rust build.
3. Commit an MSRV-aware lockfile. Renovate/Dependabot must not bump `parking_lot` to 0.13 (rustc 1.95).
4. `ServerConf::default().threads == 1` per service. `grace_period_seconds` defaults to 300 s and is a fixed sleep. Set both explicitly; for Docker stop, keep grace + teardown below the stop timeout.
5. `run_forever()` always exits 0. Use `run()` + `exit(code)`. A custom `ShutdownSignalWatch` must register SIGTERM/SIGINT/SIGQUIT itself. Register SIGHUP early, because its default action kills the process.
6. Listener bind or TLS-build failures panic only the service thread (silently). EADDRINUSE retries for 30 s. Pre-bind + fd-table adoption (non-blocking!) or Option B.
7. Pingora readiness (`ExecutionPhase::Running`, `ServiceReadyNotifier`) is signalled **before** binding.
8. h2c on cleartext means no first-bytes timeout and a hang for requests < 24 bytes. Prefer h2c only on dedicated internal listeners, or put an own timeout in Option B.
9. Parser rejects (400/405) bypass every hook, so access logs miss them and they carry `Server: Pingora`. Count them via logs only.
10. Enforce in `early_request_filter`: Host present (h1.1) and consistent with SNI if needed; method case policy; header/URI limits (Pingora allows 1 MiB / 256 headers); and the absolute-form/space-escaping effects on routing.
11. Response hop-by-hop headers (Keep-Alive, Connection-nominated fields, Proxy-Connection, Upgrade on non-101) must be stripped by us in `upstream_response_filter`.
12. Pingora never adds or replaces `X-Forwarded-*` / `Via`. Overwrite or append ourselves (B-NET-08).
13. `HttpPeer::new` unwraps address resolution. Pass a `SocketAddr`; never hostnames.
14. TLS upstream needs a non-empty SNI under rustls. Use the hostname, or the IP string for IP-only upstreams.
15. `reuse_hash` ignores `ca` and `alpn`, so set `group_key` = hash(trust policy, client cert, ALPN policy).
16. Default upstream `alpn = H1` and `max_h2_streams = 1`. Set them for h2, gRPC and multiplexing. No upstream timeouts are set by default.
17. `alternative_cn` is ignored with rustls. System roots come from rustls-native-certs (an empty store in scratch images silently fails verification). An invalid global `ca_file` or `client_bind_to_*` panics at service construction.
18. Override `error_while_proxy` carefully: resolve `RetryType::ReusedOnly` (else **panic**) and refuse retries once `response_written()` is Some.
19. `fail_to_connect` does not retry by default. `max_retries` counts attempts (default 16).
20. Status-code retries: only error when another attempt is allowed. Otherwise Pingora replaces the upstream 5xx with its own empty page.
21. Compression: per-algorithm levels; first-token choice; q ignored; Vary added even when not compressing; buffers SSE; compresses `application/*` (gRPC!) and 206. Gate it in `response_filter`.
22. `TlsSettings`: TLS 1.2+1.3 always on; ciphers are process-global; no tickets; ALPN cannot include `acme-tls/1` alongside h2; `certificate_callback` is not called for rustls; a `None` from the resolver gives `access_denied`.
23. SNI is not in `SslDigest`. Capture it in `handshake_complete_callback` (store it in the extension).
24. In Option B accept loops, set the socket digest (or `client_addr()` is None), call `set_nodelay`, and add a handshake timeout. Streams are unbuffered.
25. `IntoCaseHeaderName` does not accept non-static `&str`. `HeaderName` constants serialize lowercase except the titled list.
26. `HttpModules::add_module` panics on duplicate types and after `build_ctx`. The default `init_downstream_modules` already adds the compression module.
27. Each `HttpProxy` service has its own runtime(s) and upstream pool. Avoid one service per listener.
28. `pingora::prelude::*` exports every ErrorType variant and shadows `Result`.
29. `serde_yaml`/`unsafe-libyaml` come with pingora-core (cargo-deny advisories), so ADR-0011's "no unsafe YAML in the binary" no longer holds once Pingora is added.
30. `Weighted` selection is not smooth WRR and allocates O(Σweight). Ketama ignores UDS backends. `Backend` equality ignores `ext`.
31. The default `TcpSocketOptions` gives no SO_REUSEPORT. SO_REUSEADDR and TCP_NODELAY are always on. Backlog is 65535. Each accepted connection holds a 64 KiB read buffer.
32. `ConnectionFilter`'s signature differs with and without the feature (async `Option<&SocketAddr>` vs sync `&SocketAddr`) and is awaited inside the accept loop.

  - `fail_to_proxy`: own error pages via `write_error_response`.
  - `logging`: access log + metrics.
