### A.5 Minimal deny.toml changes (justified; validated)

With these changes, `cargo deny check` prints `advisories ok, bans ok, licenses ok, sources ok` for Pingora alone and for the full v0.1 set (`deny-crates-probe-proposed.txt`, `deny-crates-probe-full-proposed.txt`):

```toml
[advisories]
version = 2
yanked = "deny"
# Pingora 0.9.0 transitive dependencies without a fixed release. Re-check on every Pingora bump.
ignore = [
  { id = "RUSTSEC-2024-0388", reason = "derivative (unmaintained proc-macro) via pingora-core/pingora-load-balancing 0.9.0; upstream cloudflare/pingora#889" },
  { id = "RUSTSEC-2025-0134", reason = "rustls-pemfile (unmaintained) via pingora-rustls 0.9.0 and rustls-native-certs 0.7; our code parses PEM with rustls-pki-types; upstream cloudflare/pingora#1011" },
  { id = "RUSTSEC-2024-0449", reason = "unsafe-libyaml (unmaintained) via serde_yaml in pingora-core 0.9.0; ReverseDock builds ServerConf in code and never loads Pingora YAML; upstream cloudflare/pingora#1058" },
  { id = "RUSTSEC-2026-0391", reason = "zstd 0.13 via pingora-header-serde (pingora-cache); the affected stream with_context constructors are never called; upstream cloudflare/pingora#1073" },
  { id = "RUSTSEC-2026-0398", reason = "zstd-safe 7 via pingora-header-serde; Seekable needs the `seekable` feature, which is off; upstream cloudflare/pingora#1073" },
  { id = "RUSTSEC-2026-0403", reason = "zstd-safe 7 via pingora-header-serde; it only uses the bulk API, not DCtx::decompress_stream; upstream cloudflare/pingora#1073" },
]

[licenses]
# … allow list unchanged …
# CC0-1.0 grants no patent licence, so it is allowed per crate, not globally.
exceptions = [
  # Build time only: const-random-macro (proc-macro) <- ahash "compile-time-rng" <- Pingora.
  { crate = "tiny-keccak", allow = ["CC0-1.0"] },
  # File watching for the file provider (B-CFG-07); needed only once notify is added.
  { crate = "notify", allow = ["CC0-1.0"] },
]
```

Why the zstd ignores are safe. pingora-header-serde 0.9.0 calls only `CCtx::compress`, `compress_using_cdict`, `DCtx::decompress` and `decompress_using_ddict` (one-shot, thread-local contexts; see `src/thread_zstd.rs`), plus `zstd::dict` training in an offline helper. The advisories are function-scoped to `zstd::stream::raw::{Encoder,Decoder}::with_context`, `zstd_safe::seekable::*` and `DCtx::decompress_stream`. pingora-header-serde is used only by pingora-cache, which v0.1 never enables. Upstream issue #1072 and fix PR #1073 were opened on 2026-10-26; drop the ignores once a Pingora release includes them.

Not needed: `[bans] skip`, `[sources]` changes, or allowing `CC0-1.0` globally. Optional: `[graph] targets = [...]` to keep Windows and WASM duplicates out of the warnings. Later: when the `openssl`/`boringssl` features land, `all-features = true` will pull those trees into the deny graph as well.

## B. MSRV (Rust 1.89) and the pinned toolchain (1.99.1)

All runs used `CMAKE=<scratchpad cmake>`. Without cmake every check stops at `libz-ng-sys`.

| Probe / lockfile | `cargo +1.89 check --locked` | `cargo +1.99.1 check --locked` |
|---|---|---|
| Pingora, lockfile resolved for **latest** versions (no `rust-version`) | ✗ `rustc 1.89.0 is not supported by the following packages: lock_api@0.5.0 requires rustc 1.95, parking_lot@0.13.0 requires rustc 1.95, parking_lot_core@0.10.0 requires rustc 1.95` | ✓ |
| Pingora, `rust-version = "1.89"` → cargo "Locking 240 packages to highest Rust 1.89 compatible versions" (parking_lot 0.12.5, which also removes a duplicate) | ✓ (17.9 s) | ✓ |
| Full v0.1 set (372 packages) | ✓ (17.0 s) | ✓ |
| Alternatives set (283 packages) | ✓ | — |

- Cause of the 1.95 requirement: pingora-lru 0.9.0 declares `parking_lot = "0"`, so a latest-version resolution picks 0.13.0 (rust-version 1.95). Our workspace sets `rust-version = "1.89"` with resolver 3, so cargo falls back to 0.12.5 automatically. **No MSRV bump is needed.**
- Highest declared rust-version in the Pingora tree: time 0.3.55 (1.88), which explains docs/02's "some crates 1.88". pingora-proxy and pingora-cache declare 1.85, and Pingora's README says "Our current MSRV is 1.85".
- In the full v0.1 set: **uuid 1.29.0 (1.89.0)** and **aes 0.9.3 (1.89, via pkcs8 `encryption`)** sit exactly at our floor; rcgen 0.14.10, sha2 0.11.1, tonic 0.14.6 and tonic-prost 0.14.6 need 1.88.
- Risk: Pingora's README states a rolling MSRV policy ("at least 6 months old"), so a future Pingora release may require up to about Rust 1.95. Expect MSRV bumps with Pingora upgrades; ADR-0011 already ties MSRV to our dependencies.

### C.2 rustls crypto provider

- `pingora-rustls 0.9.0` depends on `ring = "0.17.12"` and on `rustls` with `default-features = false, features = ["ring", "logging", "std", "tls12"]`, and `tokio-rustls` with `ring`.
- `pingora_rustls::install_default_crypto_provider()` runs `CryptoProvider::install_default(rustls::crypto::ring::default_provider())` and ignores the "already installed" error. `TlsSettings::build()` (listener) and `TlsConnector::build_connector()` (upstream) call it, then use `ServerConfig::builder_with_protocol_versions` / `ClientConfig::builder_with_protocol_versions`, which take the process default.
- So **ring is what Pingora 0.9.0 ships**. If ReverseDock installed aws-lc-rs as the process default before Pingora initialises, Pingora's call would be a no-op and its builders would use aws-lc-rs. `Acceptor::from_server_config(Arc<ServerConfig>)` also accepts a config built with `ServerConfig::builder_with_provider(...)`. Either way ring is still compiled, and aws-lc-sys adds a second C/C++ crypto build (aws-lc-rs docs, Linux: non-FIPS needs a C/C++ compiler and never CMake or Go; FIPS needs C/C++, CMake and Go).
- Upstream: PR #630 "Allow using ring or aws-lc-rs as rustls crypto provider" (open since 2025-05-28) and PR #887 "Make ring an optional dependency in pingora-rustls" (open). #965/#966 (closed) made sure aws-lc-rs is no longer compiled when ring is used.
- **Recommendation:** v0.1 uses ring. Declare `rustls` with `default-features = false` (its defaults are `aws_lc_rs` and `prefer-post-quantum`; turning them on compiles aws-lc-sys and makes provider auto-selection ambiguous). Write an ADR that supersedes ADR-0002's "aws-lc-rs provider" sentence and keeps aws-lc-rs/FIPS as a later opt-in feature.

## E. RustSec

### E.1 Pingora 0.9.0 tree

The cargo-deny findings are listed in A.4, and A.5 covers the reachability argument for the ignores. Two more points:

- **Not shown by default:** zstd-safe 7.3.0 (via pingora-header-serde) also falls inside the ranges of the *unsound* advisories RUSTSEC-2026-0395, -0397, -0399, -0400, -0401, -0402, -0404 and -0406. cargo-deny reports unsound advisories only for direct dependencies (`unsound = "workspace"` is its default).
