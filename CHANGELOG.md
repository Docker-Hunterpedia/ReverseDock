# Changelog

All notable changes to ReverseDock are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/). From M0 onward this file is generated from Conventional Commits with git-cliff.

## [Unreleased]

### Added
- **Kubernetes Gateway API controller** (W-K8S-01, W-K8S-03, W-K8S-04, ADR-0029): `providers.kubernetes` makes `rdock run` a Gateway API v1.7.0 controller (Standard channel, `v1` kinds) in the same process as the data plane; the section is the switch, there is no mode flag. It serves GatewayClass (controller name `reversedock.dev/gateway-controller`), Gateway, HTTPRoute, GRPCRoute, TLSRoute (passthrough), TCPRoute, ReferenceGrant and ListenerSet, applies BackendTLSPolicy, and writes `status` with conditions, `observedGeneration`, `attachedRoutes`, `attachedListenerSets` and `supportedFeatures` (only the features the translator claims, in one list in the crate). Backends are the pods in a Service's EndpointSlices (ready endpoints, terminating ones as a fallback), with weights, `appProtocol`, and 503 for a Service without endpoints and 500 for an invalid reference. Each Gateway gets a Service of its own in ReverseDock's namespace with internal ports from `gateway.port_range`, and that Service's address is the Gateway's address. Every replica serves; a Lease holder (own election loop with client-go's timings) alone writes status and Services, and a replica is Ready after its first full sync whatever the Lease does. TLS Secrets become files in the data directory (memory-backed in the chart) and never enter the stored configuration; cert-manager is the supported certificate source, and `acme` together with the provider is refused unless `providers.kubernetes.allow_acme` is set. Built on kube 5.0.0 with our own Gateway API types. Not supported, and reported: `timeouts.request` and `retry`, several mirrors, the CORS filter, static Gateway addresses, TLSRoute `Terminate`. **Implemented, not released. It passes the upstream Gateway API v1.7.0 conformance suite in CI on kind (GATEWAY-HTTP, GATEWAY-GRPC, GATEWAY-TLS and GATEWAY-TCP: all core tests and every claimed extended feature; 2026-11-11, commit 19e88cc); no report has been submitted upstream yet.**
- **ListenerSet** (W-K8S-01, ADR-0029): a Gateway that allows them (`allowedListeners`: `Same`, `All` or `Selector`; the default `None` allows none) takes the listeners of its ListenerSets after its own, ListenerSets ordered by creation time, then namespace and name. A listener that conflicts with one that takes precedence is refused (`Conflicted=True`, `ProtocolConflict` or `HostnameConflict`) and the earlier one keeps working; a ListenerSet without a valid listener is `Accepted=False/ListenersNotValid`. ListenerSet listeners share the internal listener of a port with the Gateway's, and a new port gets a port on the Gateway's Service. Certificates are resolved in the ListenerSet's namespace, and a Secret in another namespace needs a ReferenceGrant from kind `ListenerSet`. Routes attach with a parentRef of kind `ListenerSet` (with or without `sectionName`); `allowedRoutes` `Same` means the ListenerSet's namespace, and a parentRef to the Gateway reaches only the Gateway's own listeners. The ListenerSet's status (conditions, listeners with `attachedRoutes`) and the Gateway's `attachedListenerSets` are written; the `ListenerSet` feature is claimed.
- **Ingress translation** (W-K8S-02, ADR-0029): `providers.kubernetes.ingress.enabled` serves `networking.k8s.io/v1` Ingress for migrations, claimed by IngressClass (`reversedock.dev/ingress-controller`), the deprecated class annotation, or the cluster default; `Exact`, `Prefix` by segment, one-label host wildcards, `defaultBackend`, TLS Secrets, and `status.loadBalancer` from `publish_service` or `publish_address`. The ingress-nginx annotations that map one to one onto a middleware are honoured (`ssl-redirect`, `force-ssl-redirect`, `rewrite-target` without capture groups, `backend-protocol`, `proxy-body-size`, `whitelist-source-range`, `enable-cors` and its settings, `app-root`, `permanent-redirect`, `temporal-redirect`); every other one is reported by name and `*-snippet` annotations are refused. Off by default.
- **Helm chart, raw manifests, Kustomize base and examples** (W-K8S-05, ADR-0029): `deploy/helm/reversedock` (Helm 3 and 4, values schema, two replicas, PodDisruptionBudget, restricted pod security, read-only RBAC plus status, one Lease and per-Gateway Services, namespaced mode with `watchNamespaces`, optional DaemonSet host ports, ServiceMonitor, HPA and NetworkPolicy), `deploy/kubernetes/install.yaml` rendered from it (CI fails when stale) with a `kustomization.yaml`, `examples/kubernetes/`, and the conformance harness `tests/conformance/gateway-api/` with the `kubernetes.yml` workflow: the upstream suite on kind and a Helm install on k3s, both of which passed on 2026-11-11 (commit 19e88cc) and now fail the workflow. The Gateway API CRDs are not in the chart. The image published with 0.6.0-alpha.1 predates the controller.
- **`redirect` builds a URL from the request** (ADR-0029): `hostname`, `path`, `prefix` (`{ from, to }`, by path segment) and `status` (301, 302, 303, 307 or 308, for every method) join `scheme` and `port`, in any combination, with the query string kept. A redirect with only `scheme` still leaves requests that already use it alone, unless `always: true` is set (the Gateway API's `RequestRedirect` translation sets it).
- **Services that answer a fixed status** (ADR-0029): `services.<name>.respond: { status: 500 }` answers every request with that status like a middleware reply, takes no backends, and can be a target in a `split`.
- **Certificates for one listener** (ADR-0029): `listeners.<l>.tls.certificates` names certificates that only that listener serves (the one covering the name, else the first), so two listeners can present different certificates for the same host name.
- **Providers may contribute listeners and certificates** (ADR-0029): a fragment of an allow-listed provider (`kubernetes`) carries listeners and certificates under `name@provider` keys; Docker and Swarm labels still cannot open ports or name certificate files. A provider listener never replaces a file listener, and takes no part in the automatic http→https redirect.
- Website: install page, Gateway API and Ingress guides and an ingress-nginx migration page for Kubernetes.
- **Phased middleware pipeline** (F-EXT-01, ADR-0030): middlewares gain the phases `upstream_request` (after the backend is chosen, before the head is sent; once per attempt), `request_body` (the complete body, held by the proxy), `response_body` (each chunk, synchronously, before `compress` and `bandwidth`) and `log` (after the response; read-only, with status, bytes and timings), beside `request` and `response`. A middleware declares the phases it uses, whether it wants a typed per-request state slot, and whether the body should be held; the proxy computes per-route flags once at compile time, so a route that uses none of the new phases does no extra work. Order: list order on the way in (`request`, `upstream_request`, `request_body`), reverse order on the way out (`response`, `response_body`, `log`). `rdock explain` prints each middleware's phases. The context gains the chosen backend and a `consumer` placeholder, which the access log shows as `consumer` once a v0.8 middleware sets it. Groundwork for the cache, plugins and agents.
- **`hold_body` middleware** (F-EXT-01, ADR-0030): `{ type: hold_body, max: 1MiB, timeout: 30s }` holds the request body until it is complete before any of it reaches the backend: in memory up to 64 KiB, then in an unlinked `0600` spool file under `<data dir>/spool/` (emptied at start). A body over `max` (or the route's smaller `max_body`) is refused with `413`, a declared one before the backend is contacted; a body slower than `timeout` gets `408`. The backend connection and the request head already exist while the body is held, so this does not shield backend workers from slow uploads (true pre-buffering waits for Pingora's early-body hook; M-TM-05 stays open). A held body over 64 KiB cannot be replayed by Pingora's retry buffer and is not retried.
- **Directory listings for `static`** (F-WEB-02, ADR-0030): `listing: true` lists a directory that has no index file, as a built-in HTML page or, when `Accept` prefers it, as JSON (`{ "path", "entries": [{ "name", "type", "size", "modified" }], "truncated" }`), with `Vary: Accept`. Off by default and safe when on: names are HTML-escaped and percent-encoded in links, the page carries `Content-Security-Policy: default-src 'none'`, `nosniff` and `Referrer-Policy: no-referrer`, `hidden` and `symlinks` decide what appears (never a name a request would be refused), entries are sorted by name and cut at 10,000 (`truncated`), and the directory is read through the same capability handle as files, on the blocking pool. A directory that exists lists instead of getting the `fallback`; `directory_redirect` also applies to listed directories; the answer has no validator and ignores conditional and range headers. `rdock validate` warns about `listing: true` with `hidden: allow` or `symlinks: all`.
- **UDP routes** (M-L4-04, ADR-0030): `udp` listeners relay datagrams per **session** (one client address and port) to `udp_services`: each session gets its own socket connected to one backend, chosen by the balancer when it starts (`load_balancer.policy`: `round_robin`, `random`, `least_sessions`, `ip_hash`; backend `weight` and `backup`) and kept for its life, and the backend's replies go back to that client only; rdock never sends a datagram that is not a reply on a live session. A session ends after `timeouts.idle` (60 s, Envoy's default) without traffic in either direction, after `responses` replies (NGINX `proxy_responses`; `1` for DNS), when its backend answers ICMP "port unreachable" (which feeds passive health: `health.passive`, on by default), or when its listener is removed (after `lifecycle.drain_timeout`); `requests` detaches a client after that many datagrams (NGINX `proxy_requests`). Sessions are capped by default because UDP sources can be forged: `listeners.<l>.sessions.max` (4,096) and `max_per_client` (64 per client IP), each a number or `unlimited`; datagrams over a cap are dropped and counted, never answered. `udp_routes.<r>` takes `listeners`, an optional `match` of `ClientIP` matchers only (at most one route without `match` per listener), `priority`, `ip_allow`/`ip_deny` middlewares (checked before a session is created) and `enabled`. Optional TCP health probes (`health.tcp_check`) for backends that also listen on TCP. Datagrams up to 64 KiB are relayed whole; one too large for the destination's address family is dropped and counted (`oversize`), never cut. Reloads keep the sockets and sessions of unchanged listeners. Metrics: `rdock_udp_sessions{listener,route}`, `rdock_udp_datagrams_total{route,direction}`, `rdock_udp_bytes_total{route,direction}`, `rdock_udp_dropped_total{listener,reason}`, `rdock_udp_session_ends_total{route,reason}`; one `debug` log line per session when it ends. Docker labels `rdock.udp_routes.*`, `rdock.udp_services.*` and the Traefik subset `traefik.udp.routers.<r>.{entrypoints,service}`, `traefik.udp.services.<s>.loadbalancer.server.port` (other `traefik.udp.*` labels are reported), carried by `rdock migrate traefik`. Not supported: PROXY protocol for datagrams (refused as planned), `SO_REUSEPORT` fan-out, GRO/GSO, and the right reply source address on a wildcard bind of a multi-homed host (bind an explicit address).
- **Gateway API UDPRoute** (W-K8S-01, ADR-0030): `UDP` listeners are accepted (route kind `UDPRoute`; a `UDP` listener shares its port number with TCP-based listeners and conflicts only with another `UDP` one) and UDPRoutes translate like TCPRoutes (attachment, ReferenceGrant, pooled weights; the oldest route of a listener gets its datagrams, all are accepted). The per-Gateway Service keys its ports by protocol and port: TCP and UDP 53 become `tcp-53` and `udp-53` (a mixed-protocol Service), each with its own internal port; Services created earlier keep their `port-<n>` names. `UDPRoute` is claimed in `supportedFeatures` with the nine upstream `GATEWAY-UDP` tests transcribed, and `GATEWAY-UDP` joins the conformance job's profiles (not yet run on kind). The chart's NetworkPolicy allows UDP on the internal port range.
- **HTTP cache** (F-WEB-03, ADR-0030): a `cache` middleware stores a route's responses in a named store under `caches` (`type: memory` with `max_size`, or `type: disk` with `path`, `max_size`, `max_objects`), on pingora-cache's state machine with our own policy and stores in the new crate `rdock-cache`. Safe by default: off unless a route lists it; **no default lifetime** (only `s-maxage`, `max-age` or `Expires`, minus the age the response arrived with, RFC 9111 §4.2.3); `GET` and `HEAD` without a body only; statuses 200, 203, 204, 300, 301, 308, 404, 410; never stored: `no-store`, `private`, `Vary: *`, `Set-Cookie`, and responses to requests that carry `Authorization` unless marked `public`, `s-maxage` or `must-revalidate`; `max_object_size` 64 MiB. Each default has an explicit opposite with its risk documented (`default_ttl` per status, `heuristic_freshness`, `statuses`, `set_cookie: strip`, `authorization: store`, `request_directives: ignore`, `lock.enabled: false`, `tags.keep`, `cache_status: false`). The key frames store, route, scheme, host, forwarded path, query and method class, with `key.query` (`as_sent`, `sorted`, `only`, `ignore`; parameters left out of the key are removed from the forwarded request), `key.headers` and `key.consumer`; override headers such as `X-Original-URL` are removed from requests on caching routes. Added to Pingora's mechanism: the full `304` header update, `Vary` with normalised values, request directives (`no-cache`, `max-age`, `min-fresh`, `max-stale`, `only-if-cached` → `504`), invalidation of the URL and same-host `Location`/`Content-Location` after a successful unsafe method, `stale-if-error` (RFC 5861) on origin errors and 500/502/503/504 within the origin's window capped by `stale_if_error`, and `Cache-Status` (RFC 9211) on every answer of a caching route plus `cache_status` in the access log. Request coalescing is on: one fetch per key, waiters wait at most `lock.timeout` (5 s) and are released to fetch on their own when the fill fails or is not cacheable. Hits still pass every `request`-phase middleware (authentication, IP filters, rate limits); `upstream_request` middlewares do not run on hits; the store holds the origin's representation, so one object serves every `compress` encoding. A route that authenticates (`basic_auth`, `jwt`, `client_cert`, `forward_auth`) and caches is a validation error unless `shared_across_users: true` or `key.consumer: true`; mirrored requests skip the cache. The disk store keeps one file per object (checksummed header with pingora-cache's `CacheMeta`, URL and tags, then the body; temporary name and rename; start-up walk that drops damaged and partial files; LRU by size and count; no `fsync`); a purge cancels fills still in progress. Stores live for the process: adding one applies on reload, changing or removing one is reported as taking effect after a restart. Tags from `Cache-Tag` and `Surrogate-Key`; purges only through the admin API (`POST /api/v1/cache/{store}/purge` by `url`, `prefix`, `tag` or `all`, operator role, audited, rate-limited; `GET /api/v1/cache` for statistics; `rdock cache list|purge`), and **a purge reaches one instance**. Metrics `rdock_cache_requests_total{store,route,status}`, `rdock_cache_objects{store}`, `rdock_cache_bytes{store}`, `rdock_cache_evictions_total{store,reason}`, `rdock_cache_lock_waits_total{store}`, `rdock_cache_dropped_total{store,reason}`. Not supported: background refresh for `stale-while-revalidate` (treated as plain staleness; `background_refresh: true` is refused as planned), a data-plane `PURGE` method, partial reads for waiters, `CDN-Cache-Control`. The disk-header decoder has a property test and a fuzz target. **The run of an external RFC 9111 test suite (`http-tests/cache-tests`) against rdock has not been done yet.** New guide: Cache responses.
- **Terraform and OpenTofu provider** (F-MGMT-02, ADR-0030): source in `clients/terraform` with `reversedock_route`, `reversedock_service` and `reversedock_middleware` resources and data sources, on the admin API's per-object endpoints with `If-Match`, serialised writes and retries on `412` and `429`. The CI job `terraform-provider` runs its tests with Terraform and OpenTofu against a fake and a real rdock. Not published: that needs a public `terraform-provider-reversedock` repository and a signing key. New guide: [Terraform and OpenTofu](https://reversedock.oday-bakkour.com/docs/guides/terraform/).
- **External secret stores** (W-OBS-02, ADR-0030): the Secrets guide explains how External Secrets Operator, the Secrets Store CSI driver and Vault or OpenBao agents end in files and Kubernetes Secrets that rdock already reads, and when a rotated value is picked up for each kind of field. The examples in `examples/kubernetes/secrets` and `examples/secrets` are not exercised by CI. A direct `${vault:…}` reference is planned.

- **Native plugins** (F-EXT-02, ADR-0030): `{ type: plugin, name: <registered name>, config: {…} }` runs a Rust plugin compiled into the binary. The new crate `rdock-plugin-api` (its own `0.x` version line; `http`-crate types only, nothing from Pingora) holds the `Plugin` trait with the six phases, `RequestHead`/`ResponseHead` views with bounded changes, `Decision`, typed per-request state, request facts (client address, route, request id, TLS, consumer and groups, chosen backend), and `Factory`/`typed` with `ConfigError`s that `rdock validate` prints under `middlewares.<name>.config`. An unknown name is an error listing the registered ones. A panic in a hook is caught, counted in `rdock_plugin_panics_total{plugin}`, logged and answered with `500` for that request only. Plugins run with the proxy's privileges; the guide says so first.
- **`rdock` as a library** (F-EXT-02, ADR-0030): `rdock::run(registry)` is the whole command line, so a binary with plugins is a `Registry` and one call; every subcommand behaves as in the stock binary, which is the same call with an empty registry. `rdock version` prints the plugin API version and the registered plugins.
- **Plugin SDK** (F-EXT-05, SDK half, ADR-0030): `rdock_plugin_api::testing` runs a plugin through its phases without a proxy; `examples/plugins` holds `header-rewrite`, `ip-blocklist`, a `custom-rdock` binary with an end-to-end test, and a template to copy, all built and tested in CI. The crates are used as git dependencies (not published on crates.io).
- **Agents** (F-EXT-04, ADR-0030): `type: agent` asks an out-of-process service about each request, with `protocol: rdock` (a JSON document and verdict, `schema/agent.v1.json`) or `protocol: forward` (the request replayed; a 2xx allows, anything else goes to the client). The body goes through the held-body mechanism up to `max_body` (default 64 KiB; `on_oversize: reject` gives `413`, `skip` asks without it), so none of it reaches the backend before the verdict. Fails closed by default (`on_error: deny`: 502, 504 on timeout, 503 while the circuit breaker is open), `timeout` 1 s, a breaker (`failures: 5`, `window: 10s`, `open_for: 30s`), an allow-list of headers sent (credentials only when listed) and of headers the agent may set, TLS settings, and metrics `rdock_agent_requests_total`, `rdock_agent_duration_seconds`, `rdock_agent_breaker_open`, `rdock_agent_ignored_headers_total`. `ext_proc`, `ext_authz` and `spop` are refused as planned.
- **WAF example** (F-EXT-04, H-SEC-02, ADR-0030): `examples/waf` runs the CRS project's ModSecurity image (`owasp/modsecurity-crs` 4.30.0, nginx, pinned by digest) as a `forward` agent with Compose; `smoke.sh`, run by the new `waf-example` CI job, proves a clean request passes, attack patterns get `403` and a stopped WAF fails closed.
- Website: Plugins and Agents guides; plugin and agent metrics in the reference.
- **Cloudflare Access** (W-CF-06, ADR-0030): `{ type: cloudflare_access, team, audience }` verifies the JWT Cloudflare Access adds, as a preset over `jwt`: keys from `https://<team>.cloudflareaccess.com/cdn-cgi/access/certs` (cached 10 minutes, refetched at once on an unknown key ID), issuer `https://<team>.cloudflareaccess.com`, RS256 only, token from `Cf-Access-Jwt-Assertion` then the `CF_Authorization` cookie (the header wins). `audience` (one or more AUD tags) is required. The consumer is the user's `email`, or a service token's `common_name` in the group `service-token`. `team` accepts the name or the team domain and is validated; `certs_url` overrides the derived URL for tests and egress proxies.
- **Problem details** (F-GW-04, first half, ADR-0030): `defaults.errors.format` and a route's `errors.format` (`html`, the default and unchanged behaviour; `problem`; `auto`) render every answer rdock produces itself (no route, middleware refusals, 408, 413, 414, 431, 429, 502, 503, 504, agent and plugin failures, the cache's 504) as `application/problem+json` (RFC 9457) with a stable `type` per kind (listed on the new Problem types reference page), `title`, `status`, a generic `detail`, `instance` (`urn:uuid:` and the request ID), `request_id`, `retry_after`, `Content-Language: en` and `Cache-Control: no-store`. A middleware's own body and `errors` pages keep precedence.
- **Consumers and API keys** (F-GW-01, first half, ADR-0030): top-level `consumers.<name>` with `groups`, inline `keys` (`{ id, hash, expires, note }`) and a watched `keys_file` of `id:hash[:expires]` lines; `{ type: api_key }` reads `rdk_<12-char id>_<32-char secret><6-char CRC32>` keys from `Authorization: Bearer` and `X-API-Key` (a query parameter only when named, never a cookie), refuses malformed keys by checksum without a lookup, finds the key by ID in a map compiled per configuration and compares the SHA-256 of the secret in constant time, checks expiry, sets the consumer, removes the key before the request goes upstream (`forward_credential: false`) and sends `X-Consumer-Name`, `X-Consumer-Groups` and `X-Credential-Id`; `anonymous: allow` and `groups` are optional. Keys minted with `POST /api/v1/consumers/{name}/keys` (operator; the key is in that answer only) are kept hashed in the `api` provider and revoked with `DELETE …/keys/{id}`; `rdock consumers` and `rdock keys` (`create`, `revoke`, `hash`, `generate`) do the same from the shell. The access log gains `key_id`; `rdock_consumer_requests_total{consumer,route,status_class}` counts per consumer (capped at 1,000 consumers, then `_other`). `key.consumer` of the cache keys on the consumer. The token-format code shared with admin tokens moved to the new crate `rdock-credentials`; admin tokens are unchanged.
- **Per-consumer limits and quotas** (F-GW-02, ADR-0030): `rate_limit` gains `key: consumer`, `overrides` per group and `headers: draft`; the new `quota` middleware counts requests per consumer per calendar window (`hour`, `day`, `month`, UTC) with group `overrides`, answers `429` with `Retry-After` until the window ends, optionally adds `RateLimit-Policy`/`RateLimit` in the syntax of `draft-ietf-httpapi-ratelimit-headers-11`, and keeps counters in `<data dir>/quota/` (written every `flush_interval` and at shutdown; per instance and approximate). `GET`/`DELETE /api/v1/quota/{consumer}` read and reset them. Counting per consumer without an earlier `api_key` or `cloudflare_access` is a validation error.
- **Usage metering** (F-GW-05, ADR-0030): `observability.metering` sends one event per request with a consumer (or every request with `all_requests`) to a webhook as CloudEvents 1.0 batches (Standard Webhooks signature and bearer token by reference) and/or OTLP/HTTP logs, batched (`max_batch`, `flush_interval`) from a bounded queue (`queue: 10000`) that drops and counts (`rdock_metering_dropped_total`) instead of slowing requests; failed batches are retried with the same event IDs (at least once). No disk spool; not billing-grade.
- Website: guides for API keys and consumers, quotas, usage metering and Cloudflare Access; problem details on the error-pages guide; the Problem types reference; consumer and metering metrics.
- **Request validation** (F-GW-03, ADR-0030): `{ type: validate }` checks path parameters (named groups of `path.regex`), query parameters, headers, cookies and JSON bodies against inline JSON Schema 2020-12, or the operations of an OpenAPI 3.1 document (`openapi`, JSON or YAML, watched; matched by method and path template, `base_path`, `unknown_operations: deny | allow`, default deny with `404`/`405`). Schemas are compiled when the configuration is loaded with `jsonschema` (no default features: no HTTP or file resolver); a schema that does not compile, a `$ref` outside its document, an OpenAPI 3.0 document and parameter styles other than the defaults are diagnostics. Parameter values are converted to the declared type; a repeated scalar parameter fails. Bodies are held up to `max_body` (default 1 MiB, at most 64 MiB; larger `413`), a non-JSON content type is `415`, invalid JSON `400`. Failures answer `400` with the new problem type `validation-failed` and at most `max_errors` (default 5) entries `{ pointer, message }` in `errors`; messages name the failed keyword and the schema's limits, never the value. `formats: true` (default) asserts `format`; `mode: report` logs and counts instead of refusing. Metric `rdock_validation_requests_total{middleware, result}`.
- **Request and response transformation** (F-GW-04, second half, ADR-0030): `{ type: transform }` sets, adds and removes request and response headers, and applies JSON Patch (RFC 6902, implemented in `rdock-model` with RFC 6901 pointers; the appendix A examples are tests) to JSON request bodies (held up to `max_body`, forwarded without the client's `Content-Length`; `on_error: reject` answers `422` with the new problem type `patch-failed`, or `pass`; non-JSON bodies pass unless `on_non_json: reject`) and to JSON response bodies in the synchronous body phase (2xx other than 204/205/206, identity encoding, at most `max_body`; `Content-Length`, `ETag` and digests are dropped). Anything else passes unchanged and is counted in `rdock_transform_skipped_total{middleware, reason}`. The cache stores the backend's response, so a cached answer is patched on every hit, wherever `transform` stands in the list. New problem type `unsupported-media-type` (415); extension members (`errors`) are rendered in problem details and in the pre-v0.8 JSON object.
- **`${vault:<mount>/<path>#<field>}`** (W-OBS-02, ADR-0030): `secrets.vault` (`address`, `ca_file`, `namespace`, `auth.token` as a `${file:}`/`${env:}` reference or `auth.kubernetes` `{ role, mount, token_file }`, `refresh` default 5m, `timeout` default 5s, `allow_private_targets` default true, `insecure_http` opt-in) reads fields of KV version 2 secrets from HashiCorp Vault or OpenBao over raw REST on the existing hyper-rustls client. References are accepted only in secret fields and only from the configuration file; values are read at every load (a reference never read that fails rejects the configuration, like a missing file; `rdock validate` reads them too), read again every `refresh` (a changed value reloads), and a failed read keeps the last value and marks Vault degraded in `rdock status` (`secrets.vault`) and `rdock_vault_refresh_failures_total`. Kubernetes logins are renewed after two thirds of their lease and after a `403`. Values stay in memory: the served configuration, history, last-known-good copy, snapshots, diagnostics and logs keep the reference. A fake KV v2 server in `rdock-testkit` backs the end-to-end tests; the new CI job `openbao` runs one against OpenBao 2.7.2 in dev mode.
- Website: guides for request validation and for transforming requests and responses; the Secrets guide covers `${vault:…}` and lists every secret field; new problem types and metrics in the references.
### Changed
- **Pingora 0.9.1 and no tokio cap**: Pingora moves to 0.9.1 (released 2026-11-03), which replaces the zero-capacity `BufStream` that panicked on every accepted connection with tokio 1.54 or newer (tokio#8494, pingora#1059); tokio is no longer capped below 1.54 and resolves to 1.54.1 (MSRV 1.89 kept). The whole test suite, and a new regression test with an HTTP/1.1 and an h2 request through a listener, pass on it. The three `zstd` 0.13 advisory ignores in `deny.toml` are gone with Pingora's move to `zstd` 0.14.3, and the Dependabot ignore for tokio is lifted.
- A request body refused by rdock (`413`, a middleware's answer) and a client that goes away no longer count as failures of the backend for passive health checks.
- `providers.kubernetes` is reshaped (it never shipped): `gateway_class` and the boolean `ingress` give way to `controller_name`, `gateway`, `ingress`, `leader_election` and `allow_acme` (ADR-0029). `gateway.pod_selector` is required while `gateway.enabled`.
- A listener contributed by a provider that cannot be bound (the address is in use) is left out with a diagnostic instead of rejecting the reload; a file listener that cannot bind still rejects it (ADR-0029).

### Fixed
- The admin API document (`GET /api/v1/config/api`) carries exactly the sections it accepts. It used to include empty `tcp_routes` and `tcp_services`, which made every `PUT` and `DELETE` on `/api/v1/{kind}/{name}` answer 422; those endpoints now have an end-to-end test.
- UDP listeners created for a Kubernetes Gateway do not cap sessions per client address: datagrams reach them through the Gateway's Service, so the address seen is the load balancer's or the node's.
- **A removed listener no longer blocks its address** (M-L4-04, ADR-0030): a reload whose new listener needs the address of a listener it removes (another name, or a listener that moves) hands the old listener's socket over instead of failing to bind it. A replaced `udp` listener ends its sessions at once; a replaced TCP listener's connections drain as before. A removed `udp` listener still drains its sessions for `lifecycle.drain_timeout` and keeps its socket meanwhile, but a later reload that needs the port ends that drain and binds it. Before, a Kubernetes Gateway that got the internal port of a UDP Gateway deleted moments earlier could not listen until the next unrelated change (the upstream `UDPRouteParentRefAttachAllListeners` test failed every run on kind).
- **A provider listener left out because its address was in use is retried** (ADR-0029): after 250 ms, 500 ms, 1 s, 2 s and then every 5 s, rdock checks whether the address can be bound and reloads only when it can; it stops once the listener binds or is no longer wanted, and does not repeat the warning on every check. File listeners are unchanged: their bind failure rejects the reload.
- **Gateway listeners that are not serving are not reported `Programmed`** (ADR-0029): while a replica's data plane cannot bind a Gateway's internal port, the listener and the Gateway report `Programmed=False` with reason `Pending` and say why (the leader's view is the one written), and turn `True` once the retry binds it.
- **The Kubernetes provider does not hand out an internal port released moments ago** (ADR-0029): a port a per-Gateway Service let go stays out of new allocations for 30 seconds (longer than a removed listener's drain), unless the port range has no other free port; then the one released longest ago is reused and logged. The leader keeps this in memory; a new leader starts without it, which the two fixes above cover.

## [0.6.0-alpha.1] — v0.6 "Swarm, L4, static"

### Added
- **Docker Swarm provider** (#190, W-SWM-01…03, ADR-0026): `providers.swarm` routes Swarm services from their `deploy.labels` with the Docker provider's translator, so `rdock.*` labels and the Traefik subset work unchanged. Each running task is a backend (`endpoint_mode: tasks`, now the default instead of `vip`): ReverseDock balances, health-checks and drains a task as soon as Swarm starts stopping it (`DesiredState: shutdown` or `remove`). `vip` (or `rdock.swarm.lbswarm` / `traefik.swarm.lbswarm` per service) routes to the service's virtual IP and ignores active health checks and sticky sessions with a warning; a `dnsrr` service in that mode is diagnosed. Swarm sends no task events, so services and tasks are listed every `providers.swarm.poll_interval` (5 s, at least 1 s) and at once on service, node, network, secret and config events; the last routes stay in service while the manager is unreachable. The network is the label (`rdock.network`, `traefik.swarm.network`), then `providers.swarm.network`, then the one the task shares with ReverseDock's own container, never `ingress` and never random. `traefik.docker.network` and `traefik.docker.lbswarm` are accepted on Swarm with a deprecation warning. A missing port label says that Swarm reports no ports. `rdock validate` warns when automatic HTTPS is on with `providers.swarm`, because replicas share no certificates in v0.6. Tasks are read with a small `/tasks` client of our own (Engine API 1.44), because bollard 0.21.1 lacks `NetworksAttachments`. New guide: [Docker Swarm](https://reversedock.oday-bakkour.com/docs/guides/docker-swarm/). Static sites from service labels are limited to `providers.swarm.static_roots` (ADR-0027).
- **Static files** (#191, F-WEB-01, ADR-0026): a `static` middleware serves a directory of ReverseDock's file system (a volume in Docker), so sites and single-page apps need no web server next to the proxy. Strong `ETag`s from modification time and size, `Last-Modified`, every RFC 9110 precondition in its order (304, 412), byte ranges with `If-Range` (206, 416; `max_ranges` up to 16 as `multipart/byteranges`), HEAD, precompressed `.zst`/`.br`/`.gz` sidecars chosen by `Accept-Encoding` with `Vary` on every answer, `index` files and `308` to the trailing slash, a single-page-app `fallback` that leaves asset paths and `fallback_except` prefixes a 404, `Cache-Control` by path prefix, media types with `charset=utf-8` and `nosniff`, and `pass_through` to the route's service for everything else. Safe by default: the root is opened once as a directory handle (cap-std; `openat2` with `RESOLVE_BENEATH` on Linux), the path is decoded once and `..`, `\`, NUL and invalid UTF-8 answer 404, hidden files, symbolic links and directory listings are refused (`hidden: allow`, `symlinks: within_root|all`; listings are planned for v0.8). Files over 1 MiB are streamed in 256 KiB chunks, so `bandwidth`, `compress` and HTTP/2 flow control apply.
- A route needs no `service` when its last middleware answers every request: `static` without `pass_through`, or an enabled `maintenance` without `allow`. `rdock validate` reports a route that needs one.
- Docker labels: `rdock.static.root` ends the container's route with a `static` middleware, and `rdock.middlewares.<name>.type=static` works like any other middleware. Label roots must be inside a directory listed in the new `providers.docker.static_roots` (empty by default), so a container cannot serve ReverseDock's own files.
- **DNS-01 with DigitalOcean, Hetzner and RFC 2136** (#192, W-DNS-03, ADR-0026): `acme.dns_providers` takes `type: digitalocean` (API token with `domain:read`, `domain:create`, `domain:delete`), `type: hetzner` (the Hetzner Cloud API, where Hetzner Console DNS lives; the old `dns.hetzner.com` API is not supported) and `type: rfc2136` (dynamic updates to BIND, Knot, PowerDNS or any primary, signed with TSIG `hmac-sha256` by default over TCP; `hmac-sha384`/`-sha512` accepted, `hmac-sha1` with a warning, `hmac-md5` refused, unsigned updates only with `insecure_unsigned: true`). The zone is found by walking up from the record name unless `zone` is set; a wildcard and its base name get separate values that never remove each other; Hetzner actions are followed until they succeed before the propagation check. API calls take at most 30 s, follow no redirects and retry `429`, `409`, `423` and `5xx` up to five times with jittered backoff that honours `Retry-After` and `RateLimit-Reset`. Their secrets must be `${file:…}`/`${env:…}` references, read again for every call; `rdock validate` refuses literals. Every adapter passes one contract test against a fake of its provider (`rdock-testkit::fake_api`, and an in-process TSIG-verifying DNS server for RFC 2136).
- **PROXY protocol on listeners** (#187, M-L4-03, ADR-0026): `listeners.<l>.proxy_protocol` reads version 1 and 2 headers on `http` and `https` listeners, before the TLS handshake, from `trusted` sources only. The header's address becomes the connection's address (client IP, `ClientIP`, IP filters, rate limits, `X-Forwarded-For`, access log), and the load balancer is logged as `proxy_peer`. Trusted sources must send a header unless `optional: true`; other sources that send one are closed; `LOCAL` headers keep the real address; headers must fit in 16 KiB and arrive within `timeouts.request_header`. Closed connections are counted in `rdock_proxy_protocol_rejected_total{listener,reason}`. Parsed with proxy-header 0.1.3, with a fuzz target and an HAProxy `send-proxy`/`send-proxy-v2` interoperability test.
- **TCP routes** (#189, M-L4-01, M-L4-02, M-L4-03 outbound, ADR-0026): `tcp` listeners in ReverseDock's own accept loop route connections with `HostSNI`, `HostSNIRegexp`, `ALPN` and `ClientIP` rules read from the TLS ClientHello without consuming it. `tls.passthrough` relays TLS untouched (the client sees the backend's certificate), `tls: {}` terminates it with the listener's TLS settings and certificates (automatic ones too) and relays plaintext, and a route without `tls` relays any bytes (``HostSNI(`*`)``). `https` listeners hand ClientHellos a TCP route matches to it and keep serving HTTP otherwise. `starttls: postgres` answers PostgreSQL's `SSLRequest` so clients with the default negotiation reach SNI routes (the request is replayed to passthrough servers); `tcp_services.<s>.proxy_protocol: v1|v2` sends a PROXY header to backends (v2 with ALPN, and after termination the server name and TLS version); `ip_allow`, `ip_deny` and `in_flight` (per client IP) apply before connecting; `tcp_services.<s>.timeouts` sets `connect` (5 s), `idle` (10 min) and `termination_delay` (100 ms). Reloads keep open relays; a removed listener drains for `lifecycle.drain_timeout` and logs how many connections it closed. Metrics: `rdock_tcp_connections{listener,route}`, `rdock_tcp_bytes_total{route,direction}`, `rdock_tcp_rejected_total{listener,reason}`. `rdock validate` refuses termination on a listener without `tls`, ``HostSNI(`*`)`` on an `https` listener and HTTP middlewares on TCP routes, warns about MySQL, SMTP, IMAP and POP3 ports behind routes that need a ClientHello, and no longer needs an HTTP listener for a configuration of TCP routes alone. Tested end to end with PostgreSQL 17 (`sslnegotiation=direct`, `starttls: postgres`, termination). UDP stays planned (v0.8).
- **TCP labels** (#189): `traefik.tcp.routers.<r>.{rule, entrypoints, service, priority, middlewares, tls, tls.passthrough}`, `traefik.tcp.services.<s>.loadbalancer.server.port` and `traefik.tcp.middlewares.<m>.{ipallowlist.sourcerange, inflightconn.amount}`, and the full form `rdock.tcp_routes.<r>.<field>` / `rdock.tcp_services.<s>.<field>`; `tls.certresolver`, `tls.options`, `tls.domains` and `serverstransport` on TCP routers and services are reported. `rdock migrate traefik` carries TCP labels of Compose files over.
- **DNS-01 with Route 53, Google Cloud DNS, Azure DNS and deSEC** (#193, W-DNS-03, ADR-0026): `type: route53` (an access key pair, optionally with an STS `session_token`, signed with AWS Signature Version 4 on ring, no AWS SDK; waits for `GetChange` to report `INSYNC`; standard partition only), `type: google_cloud_dns` (a service account key file exchanged for an access token with an RS256 JWT; each change replaces the TXT record set atomically and is followed until `done`), `type: azure_dns` (exactly one of a client secret, a client certificate signing a PS256 assertion, or a managed identity through the instance metadata service; endpoints fixed per `environment`: `public`, `usgovernment`, `china`; record sets written with `If-Match` etags) and `type: desec` (a token that token policies can limit to the `_acme-challenge` TXT record set; no write when the value is already there). Route 53 and Google skip private zones when looking a zone up. Record sets that hold all values of a name are changed under a per-zone lock, so a wildcard and its base name presented at once keep both values. Access tokens are cached until five minutes before they expire and renewed as soon as the key file or secret changes. Every adapter passes the contract test, which now also checks that a private zone is skipped.

### Changed
- **A failed connection is retried on another backend by default** (ADR-0028): a service without `retries` now behaves as `retries: {}` (connection failures only, up to 2 more attempts, within the retry budget); `retries: { attempts: 0 }` turns it off. A connection that timed out is retried only on a backend not tried yet. In the 3-node Swarm lab this took rolling updates from 85 failed requests in 36,001 to none.
- A connection attempt that would be retried on another backend gives up after `timeouts.connect_attempt` (1 s) instead of the full `timeouts.connect` (5 s), so a stopped backend costs about a second per request instead of five; the last attempt keeps the full timeout (#185, ADR-0026).

### Fixed
- Answers produced by middlewares (maintenance pages, redirects, error pages) now pass through `compress` and `bandwidth` like backend responses; before, a `compress` middleware ahead of a large `maintenance` page could announce a `Content-Encoding` the body did not have. `compress` no longer adds a second `Vary: Accept-Encoding`.

## [0.4.0-alpha.1] — v0.4 "Production reliability"

### Fixed
- **Every response to an HTTP/1 client left as two packets** ([#93](https://github.com/Docker-Hunterpedia/ReverseDock/issues/93)): the header and the body were written separately, because the client connection had no write buffer. It now has one (8 KiB, allocated on the first write), so a header and a typical body leave in one write and one segment, as from NGINX.
- **About 500 requests in flight was the most a container could hold** ([#93](https://github.com/Docker-Hunterpedia/ReverseDock/issues/93)): rdock now raises its soft open-file limit to the hard one at start, as Go programs do; containers often start with a soft limit of 1024 (Docker 29.1 with containerd 2.2). The limit raised, and a warning when it cannot be, are in the log.
- **Throughput collapsed under overload** ([#86](https://github.com/Docker-Hunterpedia/ReverseDock/issues/86), ADR-0023): each listener kept only 128 idle connections to backends, so with more requests in flight every extra request opened and closed its own backend connection. The pool is now 4096 and configurable with `security.limits.upstream_idle_connections` (M-LB-08). At a 40,000 req/s target the benchmark now holds about 14,900 req/s with 0.37 % failures instead of 1,925 req/s with 52 %.

### Changed
- `compress` offers `[zstd, br, gzip]` by default instead of `[gzip]`. Set `algorithms: [gzip]` to keep the old behaviour.

### Added
- **Balancing policies** (M-LB-01, M-LB-02, ADR-0022): `least_requests` and `least_conn` (fewest requests in flight relative to the weight), `p2c` (power of two choices), and consistent hashing of the client IP, a header or a cookie (`ip_hash`, `header_hash`, `cookie_hash`) on a ketama-style ring that every instance computes the same way. Per-backend state is shared across reloads.
- **Sticky sessions** (M-LB-03): `sticky.cookie` pins a client to a backend with an HMAC-SHA256-signed cookie that never contains the backend address; `Secure`, `HttpOnly` and `SameSite=Lax` by default; the key comes from `secret` or `$RDOCK_DATA_DIR/sticky.key`, and `previous_secrets` keeps cookies valid across a key rotation.
- **Health checks** (M-LB-04, M-LB-05, M-LB-07…09, M-L4-05): active probes in the background over HTTP (status, body, method, host, headers), TCP or the gRPC health protocol, with jitter and streak thresholds; passive ejection after `failures` within `window` (connection errors, resets, timeouts and 502/503/504 by default), doubling ejection times up to 5 minutes, a single trial request before a backend returns, and at most `max_ejection_percent` of a pool ejected. When every backend is down the pool fails open by default (`when_all_down`). `slow_start`, `backup` backends, `max_requests` and `max_connections_per_backend`. Metrics `rdock_backend_up` and `rdock_backend_ejections_total`.
- **Retries** (M-LB-06, ADR-0015): `retries.on` takes `connect`, `reset`, `timeout`, `502`, `503` and `504`; each retry goes to a backend the request has not tried yet, after a jittered backoff of up to 25–250 ms; a retry budget keeps retries in flight within `budget_percent` (20) of the requests in flight, with 3 always allowed. Connect failures are retried for every method, everything else only for idempotent ones unless `retry_non_idempotent`; never after the client saw a response or for bodies over 64 KiB. A `503` with `Retry-After` pauses that backend for up to 60 seconds. Metrics `rdock_retries_total` and `rdock_retry_budget_exhausted_total`.
- **Splits, mirroring, gRPC-Web** (M-RT-03, M-RT-04, M-RT-07): `split` services spread requests over other services by weight (smooth round-robin, nested up to 4 levels), switched atomically on reload; the access log names the service that answered. `mirror` sends a copy of `percent` of a route's requests to another service in the background (bodies up to 64 KiB, at most 64 copies in flight per route, metric `rdock_mirror_requests_total`). The `grpc_web` middleware translates binary gRPC-Web from browsers to gRPC and back.
- **Limits** (M-TM-01…04, M-TM-06, M-TM-07): rate limits by `cookie:<name>`; the `in_flight` middleware caps requests in flight per key with an optional queue and deadline (429); `security.limits.max_in_flight` sheds load with 503; the `bandwidth` middleware limits response bytes per second per key; routes take `max_body`. `compress` adds zstd and Brotli, negotiated by `Accept-Encoding` q-values with the configured order breaking ties.
- **Client certificates** (M-TLS-01, W-CF-08): `listeners.<l>.tls.client_auth` with `mode: required` or `optional`, verified against `ca_files` and, with `cloudflare: true`, Cloudflare's built-in origin-pull CA (Authenticated Origin Pulls). The `client_cert` middleware demands a certificate per route, checks its names against `allow` patterns and forwards the identity in Traefik's or Envoy's (XFCC) headers; client-sent copies of those headers are always removed. Services present `tls.cert_file`/`key_file` to backends (upstream mTLS), checked at load.
- **JWT validation** (M-SEC-01): the `jwt` middleware verifies RS/PS/ES/EdDSA/HS tokens with ReverseDock's own verifier on ring, keys from `jwks_url` (background fetch, 10-minute cache, early refresh on an unknown `kid`), `jwks_file` or `hmac_secret`. Algorithms are fixed by the configuration and pinned per key; `exp` is required; `iss` and `aud` are required unless set to `any`; `claims_to_headers` replaces client-sent copies. Limits can count by `claim:<name>`. A new fuzz target covers the verifier.
- **Tracing and observability** (M-OBS-01…03): OpenTelemetry traces over OTLP/HTTP (protobuf, through ReverseDock's own rustls client): a server span per request named `{method} {route}`, a client span per upstream attempt, W3C `traceparent` continued and passed upstream, parent-based ratio sampling, batched export that drops spans rather than slow requests. New metrics `rdock_backend_requests_total` and `rdock_upstream_duration_seconds`. `observability.access_log.sample` logs a share of successful requests and every error.
- **DNS discovery** (M-LB-10): backend names are resolved with hickory and refreshed when their TTL expires (kept between 1 s and 5 min), with the system resolver as a fallback; `srv://_service._proto.name` backends use SRV records, the lowest priority as primaries and higher ones as backups.
- **Ping endpoint** (W-CF-07): `listeners.<l>.ping: /path` answers `200 OK` for any host before routing, for Cloudflare Load Balancing and other monitors.
- **Traefik labels** for v0.4: `healthcheck.mode/status/hostname/method/headers`, `passivehealthcheck.*`, `loadbalancer.strategy`, the `retry` middleware (moved onto the router's service as `retries`), `inFlightReq` and `passTLSClientCert`; `circuitBreaker` is reported with what to use instead. `rdock migrate traefik` translates them too.
- **Chaos suite and benchmarks** (H-ENG-01, H-ENG-02): Toxiproxy-driven tests (a slow backend, resets, an outage and a flapping backend) run in CI; a test shows the retry budget holding an outage to 1.35× the client traffic against 5.9× without it. `benchmarks/` compares ReverseDock with NGINX, HAProxy, Caddy and Traefik under identical configurations and limits with open-model k6 load, with the first published results. A nightly `bench` workflow checks ReverseDock against NGINX for regressions, and `benchmarks/soak/` runs a 24-hour soak with reloads, backend outages and certificate changes under load (H-ENG-03).
- `rdock validate` warns about routes that never match because an earlier route on the same listener has the same rule or matches everything (M-RT-02).

## [0.3.0-alpha.2] — v0.3 "Automatic HTTPS"

### Fixed
- A renewal no longer fails when the CA refuses its `replaces` field (RFC 9773) for any reason other than rate limits; it is ordered again without it, as was already done for `alreadyReplaced`.
- **Certificates from Let's Encrypt were refused at the last step** (`rejectedIdentifier`): the signing request carried a placeholder common name from the certificate library. It now names the first host (or is empty for names longer than 64 bytes). Pebble, the test CA, ignores the subject, so the end-to-end tests did not see it; found by a real DNS-01 order against Let's Encrypt staging, which then issued a wildcard certificate, renewed by ARI.
- `sudo rdock trust` created the local CA as root, so `rdock run` as your user could not read its keys; the files it creates now belong to the user who ran `sudo`. Removing a root that is not installed (`rdock trust --uninstall` twice) is no longer an error.

## [0.3.0-alpha.1] — v0.3 "Automatic HTTPS"

### Added
- Guides for [automatic HTTPS](https://reversedock.oday-bakkour.com/docs/guides/automatic-https/), [wildcards and DNS-01](https://reversedock.oday-bakkour.com/docs/guides/dns-challenge/) and [running behind Cloudflare](https://reversedock.oday-bakkour.com/docs/guides/cloudflare/) (Full (strict), Origin CA, Cloudflare Tunnel); Compose examples `deploy/docker/examples/https` and `cloudflare-tunnel`, validated in CI.
- **Automatic certificates** (ADR-0020): routes with `tls: auto` whose hosts no configured certificate covers get a certificate from Let's Encrypt (or `acme.ca`) through HTTP-01, answered on every plain-HTTP listener before routing. One certificate per name, or one per route with `tls.domains`; each with a new ECDSA P-256 key; stored in `$RDOCK_DATA_DIR/acme` (mode 0600, atomic writes, a lock against a second process) and served without a reload; renewed when a third of the lifetime is left; failures retried with backoff from 1 minute to 24 hours. `tlsserver` is ordered when the CA offers it. `acme.ca_root` trusts an internal CA's endpoint. Names public CAs do not certify (`localhost`, `.internal`, private addresses …) are never ordered; they go to the local CA. Tested end to end against Pebble.
- **Local CA and `rdock trust`** (B-TLS-13, ADR-0020): `localhost` and `*.localhost`, names under `.local`, `.internal`, `.home.arpa`, `.test`, `.example` and `.invalid`, and loopback, private and link-local addresses get a certificate from a local CA in `$RDOCK_DATA_DIR/pki` (directory 0700, keys 0600), created on first use: an ECDSA P-256 root valid for 10 years whose name constraints permit only those names and ranges, a 30-day intermediate that signs and is rotated with a third of its life left, and 7-day certificates renewed the same way, served without a reload. `rdock trust` installs the root with the platform tool (macOS `security`, Linux anchors with `update-ca-certificates`, `update-ca-trust` or `trust`, NSS `certutil`; Windows prints the `certutil` command) and `rdock trust --uninstall` removes it; nothing is installed automatically. Single-label names such as `nas` get a warning suggesting `nas.internal` or `nas.home.arpa`.
- **TLS-ALPN-01** (RFC 8737): certificates can also be validated on a TLS listener, without a plain-HTTP port. A handshake offering only `acme-tls/1` gets the validation certificate for its name and is closed without HTTP; no validation certificate is ever served otherwise. `acme.challenges` sets the order of preference, and after a failure the next attempt starts with the next challenge type.
- **Renewal through ARI** (RFC 9773): after issuance, on start and whenever the CA's Retry-After passes, ReverseDock asks the CA for its suggested renewal window and renews at a random time inside it, with `replaces` so Let's Encrypt exempts the order from rate limits. Without ARI it renews with a third of the lifetime left, so 90-, 64-, 45- and 6-day certificates all work. After a failure against Let's Encrypt production, the next attempt proves the setup on staging first. A CA outage never stops serving the stored certificate.
- **Certificate alerts** (B-TLS-12): `rdock status` lists every automatic certificate with its expiry, renewal time, failures and last error; metrics `rdock_cert_renewal_failures_total{name}` and `rdock_acme_orders_total{ca,result}` join `rdock_cert_expiry_timestamp_seconds`; after 3 failures in a row, or with less than 7 days left, a warning is logged and `observability.alerts.webhook` receives the event as JSON (at most once a day per certificate).
- **Cloudflare client IPs** (W-CF-01, W-CF-02): `security.trusted_proxies: [cloudflare]` trusts Cloudflare's edge ranges, fetched from `api.cloudflare.com/client/v4/ips` once a day (kept when the `etag` is unchanged, and when a fetch fails or looks wrong), cached in `$RDOCK_DATA_DIR/cloudflare/ips.json` and backed by a list built into the binary, so startup never waits for the network. Nothing is fetched unless a configuration trusts `cloudflare`. `client_ip_header: cf-connecting-ip` takes the client IP from `CF-Connecting-IP` sent by a trusted peer; with `auto`, a request straight from a Cloudflare address uses `CF-Connecting-IP` and every other trusted proxy `X-Forwarded-For`. From any other peer the header is removed and ignored. `rdock run` no longer refuses these two settings.
- **DNS-01 for any name** (W-DNS-01, W-DNS-02, W-CF-03): wildcards, hosts behind a firewall or a tunnel, or every route with `acme.dns_provider`. Providers: `cloudflare` (token with Zone → DNS → Edit; zone looked up or `zone_id`), `exec` (a program called as `present|cleanup <fqdn> <value>`, never through a shell) and `webhook` (JSON to an HTTPS endpoint). Before validation the record is looked up at the zone's authoritative nameservers, or `acme.dns_resolvers`, for up to `acme.dns_propagation_timeout` (2 minutes); records are removed afterwards. Docker labels: `rdock.tls=dns:<provider>`.
- Configuration for automatic HTTPS (ADR-0020): `acme: false` turns automatic certificates off; `acme.dns_provider` names a default DNS provider for every route; DNS providers `exec` (a program run without a shell) and `webhook` (JSON to an `https://` endpoint) next to `cloudflare`, which gains `zone_id`; `observability.alerts.webhook` for certificate alerts. Webhooks must use `https://` (plain `http://` only for localhost), exec commands must be absolute paths, and tokens should be `${file:…}` references. Public IP-address hosts are flagged unless `acme.profile: shortlived`, and DNS-01 for an IP address is refused.

### Changed
- **Zero-config mode serves HTTPS:** without a configuration file, labelled containers are served on `:443` with automatic certificates, `:80` redirects to HTTPS and answers HTTP-01, and `rdock.tls=off` containers stay on plain HTTP at `:80`.
- **`client_ip_header: cf-connecting-ip` needs `trusted_proxies`, not `cloudflare` specifically**: behind a Cloudflare Tunnel the trusted peer is `cloudflared` on your network.
- **Routes with `tls: off` and no `listeners` attach to the plain-HTTP listeners** instead of `defaults.listeners` (ADR-0021), so a plain route never lands on an HTTPS listener it cannot be served on.
- **`tls: auto` routes now get certificates.** In v0.2 a route asking for automatic HTTPS without a matching certificate was refused ("planned for v0.3"); now ReverseDock orders one from Let's Encrypt production, which accepts its terms of service. Set `acme: false` to keep v0.2's behaviour, or `acme: { staging: true }` to try it first. `ca: buypass` is refused: Buypass stopped issuing certificates on 2025-10-16.

## [0.2.0-alpha.1] — v0.2 "Docker-native"

### Added
- **Extra configuration files** (`providers.file.paths`): files or patterns such as `conf.d/*.yaml` (relative to the main file) add routes, services, middlewares, TCP objects and certificates to the main file. A name defined twice is an error naming both files; other sections belong in the main file. They are watched like the main file, and a file added next to a pattern is loaded without a restart. `rdock validate` reads them too.
- **`rdock migrate traefik`** (F-MGMT-03): turns the Traefik labels of a Compose file, or a Traefik dynamic configuration, into routes, services and middlewares for `rdock.yaml`, through the same translator as the Docker provider. What cannot be migrated is listed at the top of the output. `--expose-by-default` follows Traefik's default for services without `traefik.enable`.
- **Zero-config mode** (B-CFG-11): `rdock run` with no configuration file (none given and none at `/etc/rdock/rdock.yaml`) and a Docker socket at `/var/run/docker.sock` serves labelled containers over HTTP on `:80`; the admin listener keeps its default. Without the socket it exits with a hint. HTTPS joins it in v0.3.
- **The Docker provider** (`providers.docker`, ADR-0018): routes, services and middlewares from container labels, native `rdock.*` and a Traefik v3 subset (64 conformance fixtures in `tests/conformance/traefik-labels`). Containers are opt-in; replicas share a service; unhealthy containers leave the pool. A container Docker is stopping leaves its pool as soon as Docker signals it (the `kill` event), so new requests go to the other replicas while its open requests finish. Changes apply within about a second of the Docker event; if the Docker socket is lost, the last routes stay in service and the provider reconnects. Unix sockets and `tcp://` socket proxies; `rdock status` shows the provider's state. The `docker` cargo feature (on by default) builds it.
- The public website and documentation in `apps/website` (Astro + Starlight, ADR-0017): a landing page and 69 pages of guides, install and migration guides (from Traefik and NGINX), concepts, operations and reference. The configuration and CLI reference are generated from the schema and the binary; every complete configuration in the docs passes `rdock validate --strict` in CI, and "planned for vX.Y" badges are checked against what `rdock` refuses.

### Changed
- A file route that refers to another provider's object (`name@docker`) that does not exist is left out with a warning; the rest of the configuration applies (ADR-0018). The error for a missing service or middleware now reads "`x` does not exist".
- New logo, "Berth": a container moored in an amber dock bay. It replaces the two-arrow mark in the README banner, the website and docs header (with a dark-theme version), and the favicon; the website gains the full web icon set and a manifest. Master files and usage rules are in `docs/assets/logo/`.

### Fixed
- `rdock validate` no longer warns that a route without `Host` needs a host name for automatic HTTPS when `defaults.certificate` serves it.
- The Compose example mounts the config directory instead of the single file (editors replace files on save, which broke reloads), and starts after the backend so its name resolves on the first request.

## [0.1.0-alpha.3] — v0.1 "hello proxy"

### Breaking

- **The proxy** (`rdock run`): Pingora 0.9 HTTP engine behind our own listeners (ADR-0012). HTTP/1.1, HTTP/2 over TLS (ALPN), h2c on plain listeners and to backends, WebSocket, server-sent events and gRPC with trailers; backends by IP, DNS name (re-resolved every 10 s) or Unix socket, over HTTP, HTTPS (verified, custom CA, or `verify: false`) or h2c; smooth weighted round-robin and weighted random.
- Routing with the Traefik v3 grammar: priorities, normalised paths (forwarded as normalised), host/path/method/header/query/client-IP matchers; automatic HTTP→HTTPS redirect for HTTPS hosts; branded 404/5xx pages with the request ID (HTML or JSON).

- Security: forwarding headers trusted only from `security.trusted_proxies`; header, header-count, target and body limits (431/414/413, chunked bodies counted); HTTP/1.1 without `Host`, bare-LF line endings and unknown `Expect` refused; 10 s request-header deadline; request IDs.
- Operations: reload on file change, `SIGHUP`, `rdock reload` or the admin API, without dropping requests; listener changes without a restart; configuration history and last-known-good copy in `$RDOCK_DATA_DIR/state`, used at start when the file is broken; drain on shutdown (`lifecycle.drain_timeout`); systemd readiness (`Type=notify`).
- Admin listener (`127.0.0.1:2080`): `/healthz`, `/readyz`, `/metrics` (Prometheus), and with a token `/api/v1/status` and `/api/v1/config/reload`; `rdock status`, `rdock reload`, `rdock healthcheck`.
- `${NAME}`, `${env:NAME}` and `${file:/path}` references in the configuration; secret fields stay references (ADR-0016).
- JSON (or text) access log and JSON application logs; Prometheus metrics for requests, latency, upstream errors, connections, TLS handshakes, reloads and certificate expiry.
- Packaging: `Dockerfile` (CMake added), `Dockerfile.release` and multi-arch GHCR images on tags (signed, attested), `deploy/docker` Compose example, `deploy/systemd/rdock.service`.
- Tests: end-to-end suites against the real binary (protocols, middlewares, smuggling vectors, limits, slow clients, reload under load, listener changes, drain, last-known-good, certificate swap); fuzz targets in `tests/fuzz` (differential HTTP/1 framing, rule parser, configuration loader) and a weekly `fuzz` workflow.
