ReverseDock <Status since="v0.1" /> exports Prometheus metrics in the text format at
**`GET /metrics`** on the admin listener (`127.0.0.1:2080` unless `admin.listener` says
otherwise). Since v0.5 it needs an API token with the `metrics` role <Status since="v0.5" />
([how to create one](/docs/guides/logs-and-metrics/#scrape-with-prometheus)). Set
`observability.metrics.prometheus: false` to turn it off; it then answers 404.

```sh
curl -s -H "Authorization: Bearer $(cat rdock-token)" http://127.0.0.1:2080/metrics
```

A ready-made [Grafana dashboard](/docs/guides/logs-and-metrics/#grafana-dashboard) shows all
of them.

Label values come from your configuration (listener, route, service and certificate names) or
from small fixed sets, never from request data such as paths or hosts, so the number of series
stays bounded.

## HTTP

### `rdock_http_requests_total`

**Counter.** HTTP requests handled, counted when the response is finished.

| Label | Values |
|---|---|
| `listener` | Listener name. |
| `route` | Route name; empty when no route matched or the request was refused before routing. |
| `service` | Service of the route; empty when there is no route. |
| `method` | `GET`, `HEAD`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, `CONNECT`, `TRACE`, or `OTHER` for any other method. |
| `status_class` | `1xx`, `2xx`, `3xx`, `4xx` or `5xx`. A request whose client went away before any response was sent counts as `5xx`. |

### `rdock_http_request_duration_seconds`

**Histogram.** Time from the request headers to the end of the response, in seconds.

| Label | Values |
|---|---|
| `listener` | Listener name. |
| `route` | Route name, or empty. |

Buckets: 0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10, 30 seconds.

### `rdock_upstream_errors_total`

**Counter.** Failed attempts to connect to a backend.

| Label | Values |
|---|---|
| `service` | Service name. |
| `kind` | `connect` (refused or failed) or `timeout` (longer than the service's `timeouts.connect`). |

Errors after the connection is open, such as a read timeout, show up as 502 or 504 in
`rdock_http_requests_total` and in the access log.

## Connections and TLS

### `rdock_connections_open`

**Gauge.** Client connections open now. Label: `listener`.

### `rdock_connections_total`

**Counter.** Client connections accepted. Label: `listener`.

### `rdock_tls_handshake_errors_total`

**Counter.** TLS handshakes that failed or did not finish within the listener's
`timeouts.request_header`. Label: `listener`.

### `rdock_proxy_protocol_rejected_total` <Status since="v0.6" />

**Counter.** Connections closed by the [PROXY protocol](/docs/guides/behind-a-proxy/#proxy-protocol)
step of a listener with `proxy_protocol`. Labels: `listener` and `reason`: `untrusted` (a
header from a source outside `trusted`), `missing` (no header from a trusted source),
`malformed`, `timeout` (not complete within `timeouts.request_header`) and `too_large` (over
16 KiB).

### `rdock_cert_expiry_timestamp_seconds`

**Gauge.** Expiry (`notAfter`) of each certificate in `certificates`, in seconds since the Unix
epoch. Label: `name`, the key under `certificates`. Updated whenever a configuration is applied,
including when certificate files change.

### `rdock_cert_renewal_failures_total` <Status since="v0.3" />

**Counter.** Failed attempts to issue or renew an automatic certificate. Label: `name`, the
certificate's first domain name.

### `rdock_acme_orders_total` <Status since="v0.3" />

**Counter.** ACME certificate orders. Labels: `ca` (the CA's host name) and `result`
(`issued` or `failed`).

## TCP routes

<Status since="v0.6" /> Metrics of [TCP routes](/docs/guides/tcp-routes/).

### `rdock_tcp_connections`

**Gauge.** Open relays of TCP routes. Labels: `listener` and `route`.

### `rdock_tcp_bytes_total`

**Counter.** Bytes relayed by TCP routes. Labels: `route` and `direction`: `in` (from the client
to the backend) and `out` (from the backend to the client). Counted as the bytes move, so long
connections show up before they end.

### `rdock_tcp_rejected_total`

**Counter.** Connections a listener with TCP routes closed without relaying them. Labels:
`listener` and `reason`: `no_route`, `bad_client_hello` (bytes that start like TLS but are not a
valid ClientHello of at most 16 KiB), `denied` (`ip_allow`, `ip_deny`), `in_flight`, `no_backend`
and `connect_failed`. Failed handshakes of terminating routes count in
`rdock_tls_handshake_errors_total`.

## UDP routes

<Status since="v0.8" /> Metrics of [UDP routes](/docs/guides/udp-routes/).

### `rdock_udp_sessions`

**Gauge.** Open sessions (one per client address and port) of UDP routes. Labels: `listener` and
`route`.

### `rdock_udp_datagrams_total`

**Counter.** Datagrams relayed by UDP routes. Labels: `route` and `direction`: `in` (from the
client to the backend) and `out` (from the backend to the client).

### `rdock_udp_bytes_total`

**Counter.** Bytes relayed by UDP routes. Labels: `route` and `direction`, as above.

### `rdock_udp_dropped_total`

**Counter.** Datagrams a `udp` listener dropped instead of relaying them; none is ever answered.
Labels: `listener` and `reason`: `no_route`, `denied` (`ip_allow`, `ip_deny`), `session_limit`
and `client_limit` (the listener's session caps), `no_backend`, `socket_error`, `queue_full` (a
session's queue or the listener's socket was full), `oversize` (too large for the destination's
address family), `backend_unreachable` (the backend answered with ICMP "port unreachable") and
`closing` (a new client of a listener that is being removed).

### `rdock_udp_session_ends_total`

**Counter.** UDP sessions that ended. Labels: `route` and `reason`: `idle`, `responses`,
`backend_unreachable`, `error` and `closed` (the listener was removed or rdock stopped).

## Backends <Status since="v0.4" />

### `rdock_backend_requests_total`

**Counter.** Answers from each backend. Labels: `service`, `backend` (the resolved address,
or `unix:` and the socket path), `status_class`. Retried attempts count separately.

### `rdock_upstream_duration_seconds`

**Histogram.** Time from sending a request to a backend to its response headers. Label:
`service`. For percentiles: `histogram_quantile(0.99, sum by (le, service)
(rate(rdock_upstream_duration_seconds_bucket[5m])))`.

### `rdock_backend_up`

**Gauge.** `1` while a backend takes traffic, `0` while health checks or passive ejection keep
it out. Labels: `service`, `backend`.

### `rdock_backend_ejections_total`

**Counter.** Ejections by passive health. Labels: `service`, `backend`.

### `rdock_retries_total`

**Counter.** Retries. Labels: `service`, `reason` (`connect`, `reset`, `timeout`, `502`,
`503`, `504`).

### `rdock_retry_budget_exhausted_total`

**Counter.** Retries refused because the retry budget was used up. Label: `service`.

### `rdock_mirror_requests_total`

**Counter.** Mirrored copies. Labels: `service` and `outcome` (`sent`, `failed`, `dropped`,
`too_large`, `no_backend`).

Backend addresses come from your configuration and its DNS answers, so their number stays
bounded by your pools.

## HTTP cache

<Status since="v0.8" /> Metrics of the [HTTP cache](/docs/guides/caching/). Store and route
names come from the configuration.

### `rdock_cache_requests_total`

**Counter.** Requests on caching routes, counted when the response is finished. Labels: `store`,
`route` and `status`: `hit` (answered from the store), `stale` (a stale copy served because the
origin failed, `stale-if-error`), `revalidated` (the origin confirmed a stale copy with `304`),
`expired` (a stale copy was replaced, or the client asked for a fresh one), `miss` and `bypass`
(the cache was not used: another method, a request body, a `bypass` rule, a mirrored request, or
an answer a middleware gave before the cache).

### `rdock_cache_objects`

**Gauge.** Objects in a store. Label: `store`.

### `rdock_cache_bytes`

**Gauge.** Bytes in a store: bodies, headers and bookkeeping (file sizes for a disk store).
Label: `store`.

### `rdock_cache_evictions_total`

**Counter.** Objects removed to stay within a store's limits. Labels: `store` and `reason`:
`size` (`max_size`) or `count` (`max_objects`, disk stores).

### `rdock_cache_lock_waits_total`

**Counter.** Requests that waited for another request to fill the cache (request coalescing).
Label: `store`.

### `rdock_cache_dropped_total`

**Counter.** Disk-store objects removed by the start-up walk. Labels: `store` and `reason`:
`corrupt` (a checksum, length or format that does not check out) or `partial` (a temporary file
an interrupted fill left behind).

## Consumers and metering

<Status since="v0.8" /> Metrics of [consumers](/docs/guides/api-keys/) and
[usage metering](/docs/guides/usage-metering/).

### `rdock_consumer_requests_total`

**Counter.** Finished requests that have a consumer. Labels: `consumer`, `route` and
`status_class` (`2xx`…). Consumer names come from the configuration or from identities
(Cloudflare Access, OIDC logins, JWT claims), so the label is capped: the first 1,000 distinct consumers seen get their own series,
later ones are counted under `consumer="_other"`. Per-consumer numbers beyond that belong in
usage metering.

### `rdock_metering_events_total`

**Counter.** Metering events by `sink` (`webhook`, `otlp`) and `result`: `sent` (the receiver
accepted the batch) or `failed` (dropped after the last attempt or a refusal).

### `rdock_metering_dropped_total`

**Counter.** Metering events dropped, by `sink` and `reason`: `queue_full` (the sink's queue was
full when the request finished) or `undeliverable` (the batch failed every attempt or was
refused).

## OIDC login

<Status since="v0.8" /> Metrics of [`oidc`](/docs/guides/oidc-login/). Middleware names come from
the configuration.

### `rdock_oidc_logins_total`

**Counter.** Logins finished at the callback, or refused before reaching the provider. Labels:
`middleware` and `result`: `success`, `denied` (refused by `allowed`), `failed` (a wrong or
expired state, an ID token that failed a check, a session too large for the cookies),
`provider_error` (the provider answered `error=` or the token request failed) or `unavailable`
(the provider's configuration could not be read, `503`).

### `rdock_oidc_refreshes_total`

**Counter.** Session refreshes with the refresh token. Labels: `middleware` and `result`:
`success` or `failed` (the request then needs a new login).

### `rdock_oidc_provider_errors_total`

**Counter.** Failed requests to the OpenID provider. Labels: `middleware` and `operation`:
`discovery`, `jwks`, `token` (code exchange) or `refresh`.

## Validation, transformation and secrets

<Status since="v0.8" /> Metrics of [`validate`](/docs/guides/request-validation/),
[`transform`](/docs/guides/transforming-requests/) and
[`${vault:…}` references](/docs/guides/secrets/#vault-and-openbao). Middleware names come from
the configuration.

### `rdock_validation_requests_total`

**Counter.** Requests checked by `validate` middlewares. Labels: `middleware` and `result`:
`valid`, `invalid` (refused with `validation-failed`), `reported` (invalid, let through in
`mode: report`), `unknown_operation` (no operation of the OpenAPI document matched) or
`unsupported_media_type`.

### `rdock_transform_skipped_total`

**Counter.** Response bodies a `transform` middleware with `response.body.patch` left unchanged.
Labels: `middleware` and `reason`: `status` (not a 2xx with a body, or 206), `not_json`,
`encoded` (the backend compressed it), `too_large` (over `max_body`), `invalid_json`, or
`patch_failed` (a `test` failed or a location is missing).

### `rdock_vault_refresh_failures_total`

**Counter.** Reads of `${vault:…}` references that failed while a value from an earlier read
stayed in use (Vault is then degraded in `rdock status`). No labels.

## Plugins and agents

<Status since="v0.8" /> Metrics of [native plugins](/docs/guides/plugins/),
[WASM plugins](/docs/guides/wasm-plugins/) and [agents](/docs/guides/agents/). Plugin and middleware names come from the binary and the
configuration.

### `rdock_plugin_panics_total`

**Counter.** Panics caught in a native plugin's hooks. Each answered its request with `500` (a
panic in `response_body` lets the chunk pass unchanged, one in `log` only counts). Label:
`plugin` (the registered name).

### `rdock_wasm_failures_total`

**Counter.** Failed calls into [WASM plugins](/docs/guides/wasm-plugins/) (experimental; zero in
builds without the `wasm` feature). Each followed the middleware's `on_error`. Labels:
`middleware` (its name) and `reason`: `fuel` (ran out of fuel), `timeout` (past its deadline),
`memory` (grew past its limit), `trap` (the plugin crashed, or its instance could not be
created) and `invalid` (an edit or reply rdock refuses, such as setting `content-length`).

### `rdock_agent_requests_total`

**Counter.** Decisions of `agent` middlewares. Labels: `agent` (the middleware's name) and
`result`: `allow`, `deny` (the agent refused, or answered a non-2xx in `forward`), `error` (no
connection, an answer that is not a verdict), `timeout`, `breaker_open` (not called because the
breaker is open) and `oversize` (a body over `max_body` refused with `413`). `error`, `timeout`
and `breaker_open` follow `on_error`.

### `rdock_agent_duration_seconds`

**Histogram.** Time an agent took to answer (calls made, not those the breaker skipped). Label:
`agent`. Buckets from 1 ms to 5 s.

### `rdock_agent_breaker_open`

**Gauge.** `1` while an agent's circuit breaker is open, else `0`. Label: `agent`.

### `rdock_agent_ignored_headers_total`

**Counter.** Request headers an agent asked to set that were not applied. Labels: `agent` and
`reason`: `not_allowed` (not in `response_headers`), `invalid` (not a valid header) or
`too_late` (the verdict came with the body, after the request head had gone to the backend).

## Configuration

### `rdock_config_generation`

**Gauge.** Generation number of the configuration in use. It starts at 1 and grows with each
applied reload.

### `rdock_config_reloads_total`

**Counter.** Attempts to apply a configuration, including the first one at start. Label:
`result`, which is `applied` or `rejected`. A rejected reload leaves the running configuration
in place.

## Alerts <Status since="v0.5" />

### `rdock_alerts_sent_total`

**Counter.** Alert deliveries. Labels: `channel` (the channel's name under
`observability.alerts.channels`) and `result` (`sent` or `failed`, after retries).

## Build

### `rdock_build_info`

**Gauge**, always `1`. Labels: `version` (for example `0.6.0-alpha.1`) and `commit`.

## When series appear

Counters and gauges with labels appear after their first event: `rdock_tls_handshake_errors_total`
is missing until a handshake fails, and `rdock_cert_expiry_timestamp_seconds` until a
certificate is loaded. Use `or vector(0)` in queries that must always return a value.

## Example queries

```text
# Requests per second by route
sum by (route) (rate(rdock_http_requests_total[5m]))

# Share of 5xx answers per service
sum by (service) (rate(rdock_http_requests_total{status_class="5xx"}[5m]))
  / sum by (service) (rate(rdock_http_requests_total[5m]))

# 95th percentile latency per route
histogram_quantile(0.95, sum by (le, route) (rate(rdock_http_request_duration_seconds_bucket[5m])))

# Days until each certificate expires
(rdock_cert_expiry_timestamp_seconds - time()) / 86400

# Reloads that failed in the last hour
increase(rdock_config_reloads_total{result="rejected"}[1h]) > 0
```
