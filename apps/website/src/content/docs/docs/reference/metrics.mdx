ReverseDock <Status since="v0.1" /> exports Prometheus metrics in the text format at
**`GET /metrics`** on the admin listener (`127.0.0.1:2080` unless `admin.listener` says
otherwise). Since v0.5 it needs an API token with the `metrics` role <Status since="v0.5" />
([how to create one](/docs/guides/logs-and-metrics/#scrape-with-prometheus)). Set
`observability.metrics.prometheus: false` to turn it off; it then answers 404.

```sh
curl -s -H "Authorization: Bearer $(cat rdock-token)" http://127.0.0.1:2080/metrics
```

A ready-made [Grafana dashboard](/docs/guides/logs-and-metrics/#grafana-dashboard) shows all
of them.

Label values come from your configuration (listener, route, service and certificate names) or
from small fixed sets, never from request data such as paths or hosts, so the number of series
stays bounded.

## HTTP

### `rdock_http_requests_total`

**Counter.** HTTP requests handled, counted when the response is finished.

| Label | Values |
|---|---|
| `listener` | Listener name. |
| `route` | Route name; empty when no route matched or the request was refused before routing. |
| `service` | Service of the route; empty when there is no route. |
| `method` | `GET`, `HEAD`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, `CONNECT`, `TRACE`, or `OTHER` for any other method. |
| `status_class` | `1xx`, `2xx`, `3xx`, `4xx` or `5xx`. A request whose client went away before any response was sent counts as `5xx`. |

### `rdock_http_request_duration_seconds`

**Histogram.** Time from the request headers to the end of the response, in seconds.

| Label | Values |
|---|---|
| `listener` | Listener name. |
| `route` | Route name, or empty. |

Buckets: 0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10, 30 seconds.

### `rdock_upstream_errors_total`

**Counter.** Failed attempts to connect to a backend.

| Label | Values |
|---|---|
| `service` | Service name. |
| `kind` | `connect` (refused or failed) or `timeout` (longer than the service's `timeouts.connect`). |

Errors after the connection is open, such as a read timeout, show up as 502 or 504 in
`rdock_http_requests_total` and in the access log.

## Connections and TLS

### `rdock_connections_open`

**Gauge.** Client connections open now. Label: `listener`.

### `rdock_connections_total`

**Counter.** Client connections accepted. Label: `listener`.

### `rdock_tls_handshake_errors_total`

**Counter.** TLS handshakes that failed or did not finish within the listener's
`timeouts.request_header`. Label: `listener`.

### `rdock_cert_expiry_timestamp_seconds`

**Gauge.** Expiry (`notAfter`) of each certificate in `certificates`, in seconds since the Unix
epoch. Label: `name`, the key under `certificates`. Updated whenever a configuration is applied,
including when certificate files change.

### `rdock_cert_renewal_failures_total` <Status since="v0.3" />

**Counter.** Failed attempts to issue or renew an automatic certificate. Label: `name`, the
certificate's first domain name.

### `rdock_acme_orders_total` <Status since="v0.3" />

**Counter.** ACME certificate orders. Labels: `ca` (the CA's host name) and `result`
(`issued` or `failed`).

## Backends <Status since="v0.4" />

### `rdock_backend_requests_total`

**Counter.** Answers from each backend. Labels: `service`, `backend` (the resolved address,
or `unix:` and the socket path), `status_class`. Retried attempts count separately.

### `rdock_upstream_duration_seconds`

**Histogram.** Time from sending a request to a backend to its response headers. Label:
`service`. For percentiles: `histogram_quantile(0.99, sum by (le, service)
(rate(rdock_upstream_duration_seconds_bucket[5m])))`.

### `rdock_backend_up`

**Gauge.** `1` while a backend takes traffic, `0` while health checks or passive ejection keep
it out. Labels: `service`, `backend`.

### `rdock_backend_ejections_total`

**Counter.** Ejections by passive health. Labels: `service`, `backend`.

### `rdock_retries_total`

**Counter.** Retries. Labels: `service`, `reason` (`connect`, `reset`, `timeout`, `502`,
`503`, `504`).

### `rdock_retry_budget_exhausted_total`

**Counter.** Retries refused because the retry budget was used up. Label: `service`.

### `rdock_mirror_requests_total`

**Counter.** Mirrored copies. Labels: `service` and `outcome` (`sent`, `failed`, `dropped`,
`too_large`, `no_backend`).

Backend addresses come from your configuration and its DNS answers, so their number stays
bounded by your pools.

## Configuration

### `rdock_config_generation`

**Gauge.** Generation number of the configuration in use. It starts at 1 and grows with each
applied reload.

### `rdock_config_reloads_total`

**Counter.** Attempts to apply a configuration, including the first one at start. Label:
`result`, which is `applied` or `rejected`. A rejected reload leaves the running configuration
in place.

## Alerts <Status since="v0.5" />

### `rdock_alerts_sent_total`

**Counter.** Alert deliveries. Labels: `channel` (the channel's name under
`observability.alerts.channels`) and `result` (`sent` or `failed`, after retries).

## Build

### `rdock_build_info`

**Gauge**, always `1`. Labels: `version` (for example `0.4.0-alpha.1`) and `commit`.

## When series appear

Counters and gauges with labels appear after their first event: `rdock_tls_handshake_errors_total`
is missing until a handshake fails, and `rdock_cert_expiry_timestamp_seconds` until a
certificate is loaded. Use `or vector(0)` in queries that must always return a value.

## Example queries

```text
# Requests per second by route
sum by (route) (rate(rdock_http_requests_total[5m]))

# Share of 5xx answers per service
sum by (service) (rate(rdock_http_requests_total{status_class="5xx"}[5m]))
  / sum by (service) (rate(rdock_http_requests_total[5m]))

# 95th percentile latency per route
histogram_quantile(0.95, sum by (le, route) (rate(rdock_http_request_duration_seconds_bucket[5m])))

# Days until each certificate expires
(rdock_cert_expiry_timestamp_seconds - time()) / 86400

# Reloads that failed in the last hour
increase(rdock_config_reloads_total{result="rejected"}[1h]) > 0
```
