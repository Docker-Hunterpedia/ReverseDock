The control plane's own settings, read only by `rdock control run`.

## `control.history`

**Type:** `integer` · **Default:** `50`

Published revisions kept for listing and rollback. Default 50 (1–1000).

## `control.identity_lifetime`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `30d`

Lifetime of the client certificate each data plane receives; it is renewed when a third is left. A data plane whose certificate expires while the control plane is away keeps serving but must enrol again with a new token. Default 30d (1h–90d).

## `control.join_token_ttl`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `1h`

How long a join token from `rdock control token create` stays usable. Default 1h (1m–30d).

## `control.listener`

**Type:** [`ListenAddress`](/docs/reference/configuration/#listenaddress) · **Default:** `127.0.0.1:7443`

The cluster listener data planes connect to (mutual TLS, HTTP/2). Default `127.0.0.1:7443`: set an address other machines reach.

## `control.name`

**Type:** `string`

A display name for the cluster.

## `control.names`

**Type:** list of `string`

DNS names and IP addresses on the control plane's server certificate, as data planes write them in `cluster.control.url`. `localhost`, `127.0.0.1`, `::1` and the listener's IP are always included.

## `control.offline_after`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `1m30s`

A data plane that has not asked for a bundle for this long is shown as offline and is not chosen as a canary. Default 90s (10s–1h).

## `control.rollout`

**Type:** object · **Default:** `{"auto_rollback":false,"canary_timeout":"2m","mode":"canary","soak":"1m"}`

How a published revision reaches the data planes: one canary first, then the rest.

### `control.rollout.auto_rollback`

**Type:** `boolean` · **Default:** `false`

Rolling back automatically when the canary's health drops: planned, only `false` is accepted.

:::note[Planned for a later version]
Automatic rollback of a rollout on the canary's health: accepted by `rdock validate` with a warning, refused by `rdock run` until a later version.
:::

### `control.rollout.canary`

**Type:** `string`

The instance that takes each revision first. When it is offline or not set, the first online instance by name is chosen.

### `control.rollout.canary_timeout`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `2m`

How long the canary has to report on a revision; without a report by then the rollout halts. Default 2m (10s–1h).

### `control.rollout.mode`

**Type:** `canary` · `all` · **Default:** `canary`

`canary` (default) or `all`. The first revision of a cluster and rollbacks (including an abandoned rollout) always go to every instance at once.

- `canary`: One canary takes the revision first; the rest follow after `soak` once it acknowledged it. A refusal (NACK) by any instance halts the rollout.
- `all`: Every connected data plane takes the revision at once.

### `control.rollout.soak`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `1m`

How long the canary serves a revision it acknowledged before the rest take it. Default 60s (0s–24h).
