## `type: headers`

Set, add or remove request and response headers.

### `middlewares.<name>.hsts`

**Type:** object

## `type: redirect`

Redirect to another scheme or to a URL built from a regular expression.

### `middlewares.<name>.always`

**Type:** `boolean` · **Default:** `false`

Redirect even a request that already uses `scheme` (a redirect that sets `hostname`, `path` or `prefix` is always sent). The Gateway API's `RequestRedirect` filter sets it: there a redirect is sent whatever the request's scheme. Default `false`.

### `middlewares.<name>.hostname`

**Type:** `string`

Replace the host name.

### `middlewares.<name>.path`

**Type:** `string`

Replace the whole path, e.g. `/new`.

### `middlewares.<name>.permanent`

**Type:** `boolean` · **Default:** `false`

`301`/`308` when true, `302`/`307` when false (the second code of each pair is used for methods other than GET, so the method and body are kept), as in Traefik.

### `middlewares.<name>.port`

**Type:** `integer`

Port of the target, left out of the URL when it is the scheme's default. Unset: the scheme's default port when `scheme` is set, otherwise the request's port.

### `middlewares.<name>.prefix`

**Type:** object

Replace a leading path prefix, by path segment: `{ from: /a, to: /b }` turns `/a/x` into `/b/x` and `/a` into `/b`; other paths are kept.

#### `middlewares.<name>.prefix.from`

**Type:** `string` · **Required**

The prefix to replace, starting with `/`. It matches whole path segments: `/a` matches `/a` and `/a/x`, not `/ab`.

#### `middlewares.<name>.prefix.to`

**Type:** `string` · **Required**

Its replacement, starting with `/`, or empty to remove the prefix.

### `middlewares.<name>.regex`

**Type:** `string`

Regular expression matched against the full request URL. Not combined with the fields above.

### `middlewares.<name>.replacement`

**Type:** `string`

Target URL; may use `$1`, `${name}` groups from `regex`.

### `middlewares.<name>.scheme`

**Type:** `http` · `https`

Redirect to this scheme. Alone (without `hostname`, `path` or `prefix`; `port`, `status` and `permanent` may be set), a request that already uses it is not redirected, unless `always` is set.

- `http`: `http://`.
- `https`: `https://`.

### `middlewares.<name>.status`

**Type:** `integer`

Status code of the redirect: `301`, `302`, `303`, `307` or `308`, for every method. Overrides `permanent`.

## `type: static`

Serve files from a directory on ReverseDock's own file system. It answers the request, so a route that ends with it needs no service (unless `pass_through` is on).

### `middlewares.<name>.cache_control`

**Type:** object · **Default:** `{"default":"no-cache"}`

`Cache-Control` of served files.

#### `middlewares.<name>.cache_control.default`

**Type:** `string` · **Default:** `no-cache`

Value for files no prefix matches. `no-cache` makes clients revalidate with the `ETag`.

### `middlewares.<name>.directory_redirect`

**Type:** `boolean` · **Default:** `true`

Redirect (`308`) a directory path without a trailing slash to the path with one when the directory has an index file, or is listed.

### `middlewares.<name>.fallback`

**Type:** `string`

File served (with status 200) for a GET or HEAD whose last path segment has no `.` and that names no file, e.g. `/index.html` for a single-page app. Off when unset.

### `middlewares.<name>.fallback_except`

**Type:** list of `string`

Path prefixes that never get the `fallback`, e.g. `/api/`; they stay `404`.

### `middlewares.<name>.hidden`

**Type:** `refuse` · `allow` · **Default:** `refuse`

Files and directories whose name starts with `.` (`.env`, `.git/`).

- `refuse`: A path with any component starting with `.` answers `404`.
- `allow`: Hidden files and directories are served like any other.

### `middlewares.<name>.index`

**Type:** list of `string` · **Default:** `["index.html"]`

File names tried, in order, for a request that names a directory.

### `middlewares.<name>.listing`

**Type:** `boolean` · **Default:** `false`

List a directory that has no `index` file (F-WEB-02): HTML, or JSON for clients that prefer it in `Accept`. Off by default. Follows `hidden` and `symlinks`: names a request would be refused are not listed. At most 10,000 entries, sorted by name. A directory that exists is listed instead of getting the `fallback`.

### `middlewares.<name>.max_ranges`

**Type:** `integer` · **Default:** `1`

Most byte ranges answered in one request, from 1 to 16. A request for more gets the whole file (`200`); more than 1 allows `multipart/byteranges` answers.

### `middlewares.<name>.nosniff`

**Type:** `boolean` · **Default:** `true`

Send `X-Content-Type-Options: nosniff`.

### `middlewares.<name>.pass_through`

**Type:** `boolean` · **Default:** `false`

Send requests that name no file (and methods other than GET and HEAD) on to the route's service instead of answering `404` or `405`. The route then needs a service.

### `middlewares.<name>.precompressed`

**Type:** list of `gzip` · `br` · `zstd` · **Default:** `["zstd","br","gzip"]`

Precompressed sidecar files (`app.js.zst`, `app.js.br`, `app.js.gz`) served to clients that accept the coding, in this order of preference. `[]` turns them off.

### `middlewares.<name>.root`

**Type:** `string` · **Required**

Directory to serve. It must exist and be a directory when the configuration is applied.

### `middlewares.<name>.symlinks`

**Type:** `none` · `within_root` · `all` · **Default:** `none`

Which symbolic links are followed.

- `none`: None: a path with a symbolic link in it answers `404`.
- `within_root`: Links that stay inside `root`; the kernel refuses any resolution that leaves it.
- `all`: Every link, also out of `root`. `rdock validate` warns about it.

### `middlewares.<name>.types`

**Type:** map of names to `string`

File extension → media type, overriding the built-in table, e.g. `{ ts: text/typescript }`.

## `type: hold_body`

Hold the request body until it is complete (up to `max`) before any of it reaches the backend. The backend connection and the request head are already sent, so this does not shield backend workers from slow uploads; it refuses oversize bodies with `413` and lets body middlewares see the whole body.

### `middlewares.<name>.max`

**Type:** [`ByteSize`](/docs/reference/configuration/#bytesize) · **Default:** `1MiB`

Largest body held, at most 64MiB; a longer one is refused with `413`. The route's `max_body` (or `security.limits.max_body_bytes`) applies when it is smaller.

### `middlewares.<name>.timeout`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `30s`

Longest time from the first body byte to the last; a slower upload is refused with `408`. The service's `timeouts.read` also runs while the backend waits for the body.

## `type: cache`

Cache responses in a store named under `caches` (RFC 9111). Only what the origin's headers allow is stored; see `docs/guides/caching`.

### `middlewares.<name>.authorization`

**Type:** `refuse` · `store` · **Default:** `refuse`

Responses to requests that carry `Authorization` to the origin: `refuse` (default) stores them only when they are marked `public`, `s-maxage` or `must-revalidate` (RFC 9111 §3.5); `store` stores them anyway. The risk of `store` is serving one credential's answer to another.

- `refuse`: Store only `public`, `s-maxage` or `must-revalidate` responses (RFC 9111 §3.5).
- `store`: Store them like other responses.

### `middlewares.<name>.background_refresh`

**Type:** `boolean` · **Default:** `false`

Refresh stale responses in the background (`stale-while-revalidate`). Not supported in this version: `stale-while-revalidate` is treated as plain staleness.

:::note[Planned for a later version]
Background refresh of stale cached responses (stale-while-revalidate): accepted by `rdock validate` with a warning, refused by `rdock run` until a later version.
:::

#### `middlewares.<name>.bypass.cookies`

**Type:** list of `string`

Skip when the request has one of these cookies.

#### `middlewares.<name>.bypass.headers`

**Type:** list of `string`

Skip when the request has one of these headers.

### `middlewares.<name>.cache_status`

**Type:** `boolean` · **Default:** `true`

Add `Cache-Status` (RFC 9211) to responses.

### `middlewares.<name>.default_ttl`

**Type:** map of names to [`Duration`](/docs/reference/configuration/#duration)

Lifetime by status (`"200": 5m`) for responses whose origin gives none (no `max-age`, `s-maxage` or `Expires`). Never applies over `no-store`, `private` or `no-cache`. Empty by default: the risk is caching personalised pages the origin did not mark.

### `middlewares.<name>.heuristic_freshness`

**Type:** `boolean` · **Default:** `false`

Give responses with `Last-Modified` and no explicit lifetime 10 % of their age, at most a day (RFC 9111 §4.2.2). Off by default: the origin did not ask for caching.

### `middlewares.<name>.key`

**Type:** object · **Default:** `{"consumer":false,"headers":[],"query":"as_sent"}`

What, besides store, route, scheme, host, path and method, selects a stored response.

#### `middlewares.<name>.key.consumer`

**Type:** `boolean` · **Default:** `false`

Keep one copy per authenticated identity: the consumer, else the `basic_auth` user, else the `jwt` issuer and subject, else the client certificate's subject.

#### `middlewares.<name>.key.headers`

**Type:** list of `string`

Request headers whose values select a response (beyond the origin's `Vary`).

#### `middlewares.<name>.key.query`

**Type:** `as_sent` · `sorted` · **Default:** `as_sent`

How the query string enters the key.

- `as_sent`: The query exactly as forwarded.
- `sorted`: Parameters sorted by name.

#### `type: undefined`

The query exactly as forwarded.

#### `type: undefined`

Parameters sorted by name.

#### `type: undefined`

Only these parameters (`name` or `prefix*`).

#### `middlewares.<name>.key.query.only`

**Type:** list of `string` · **Required**

#### `type: undefined`

All but these parameters (`name` or `prefix*`).

#### `middlewares.<name>.key.query.ignore`

**Type:** list of `string` · **Required**

### `middlewares.<name>.lock`

**Type:** object · **Default:** `{"enabled":true,"timeout":"5s"}`

Request coalescing: one origin fetch per key at a time.

#### `middlewares.<name>.lock.enabled`

**Type:** `boolean` · **Default:** `true`

While one request fetches a key, others wait for its response instead of asking the origin too. Off, every miss goes to the origin.

#### `middlewares.<name>.lock.timeout`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `5s`

Longest wait. After it the waiting request goes to the origin without storing, and a fetch running that long no longer holds others back.

### `middlewares.<name>.max_object_size`

**Type:** [`ByteSize`](/docs/reference/configuration/#bytesize) · **Default:** `64MiB`

Largest response body stored; larger ones pass through uncached.

### `middlewares.<name>.request_directives`

**Type:** `honour` · `ignore` · **Default:** `honour`

The client's `no-cache`, `max-age`, `min-fresh` and `max-stale`: `honour` (default, RFC 9111 §5.2.1) or `ignore`, so clients cannot force origin fetches. `only-if-cached` is always honoured.

- `honour`: Apply them (RFC 9111 §5.2.1).
- `ignore`: Ignore them, except `only-if-cached`.

### `middlewares.<name>.set_cookie`

**Type:** `refuse` · `strip` · **Default:** `refuse`

Responses that set a cookie: `refuse` (default) never stores them; `strip` stores them without `Set-Cookie`. The risk of `strip` is a page that depends on the cookie.

- `refuse`: Never store them.
- `strip`: Store them without `Set-Cookie`.

### `middlewares.<name>.shared_across_users`

**Type:** `boolean` · **Default:** `false`

The route authenticates requests but its responses are the same for every user, so one stored copy may be served to all of them. Required (or `key.consumer`) when the route has an authenticating middleware; the risk is serving one user's page to another.

### `middlewares.<name>.stale_if_error`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `1d`

Longest time a stale response is served when the origin fails, if the origin allowed it with `stale-if-error` (RFC 5861). `0s` turns it off.

### `middlewares.<name>.statuses`

**Type:** list of `integer`

Statuses that may be stored, each only with a lifetime; default 200, 203, 204, 300, 301, 308, 404, 410. 206 and 304 are never stored as such.

### `middlewares.<name>.store`

**Type:** `string` · **Required**

The store, a name under `caches`.

### `middlewares.<name>.tags`

**Type:** object · **Default:** `{"headers":["cache-tag","surrogate-key"],"keep":false}`

Cache tags for purging groups of responses.

#### `middlewares.<name>.tags.headers`

**Type:** list of `string` · **Default:** `["cache-tag","surrogate-key"]`

Response headers that carry tags (comma or space separated).

#### `middlewares.<name>.tags.keep`

**Type:** `boolean` · **Default:** `false`

Pass the tag headers on to clients; by default they are removed.

## `type: plugin`

A native plugin compiled into this binary and registered under `name` (ADR-0030). The stock `rdock` binary registers none; see `docs/guides/plugins`.

### `middlewares.<name>.config`

**Type:** `object`

The plugin's own settings, checked by the plugin when the configuration is validated and loaded. Values are interpolated like any other (`${env:…}`, `${file:…}`) and stay visible in the configuration API.

### `middlewares.<name>.name`

**Type:** `string` · **Required**

The name the plugin is registered under in this binary.

## `type: agent`

Ask an out-of-process agent (a WAF, a policy service) whether to allow a request, with its body up to `max_body` (ADR-0030). Fails closed by default.

### `middlewares.<name>.address`

**Type:** [`HttpUrl`](/docs/reference/configuration/#httpurl) · **Required**

The agent's URL (`http://` or `https://`). Use `https://` or a loopback address unless the network between rdock and the agent is private.

### `middlewares.<name>.breaker`

**Type:** object · **Default:** `{"failures":5,"open_for":"30s","window":"10s"}`

The circuit breaker that stops calling a failing agent for a while.

#### `middlewares.<name>.breaker.failures`

**Type:** `integer` · **Default:** `5`

Failed calls in a row that open the breaker; `0` turns it off.

#### `middlewares.<name>.breaker.open_for`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `30s`

How long the breaker stays open.

#### `middlewares.<name>.breaker.window`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `10s`

The failures must fall within this time.

### `middlewares.<name>.max_body`

**Type:** [`ByteSize`](/docs/reference/configuration/#bytesize) · **Default:** `64KiB`

Largest request body sent to the agent; `0` sends none. The body is held until the agent has answered, so nothing of it reaches the backend before the verdict.

### `middlewares.<name>.on_error`

**Type:** `deny` · `allow` · **Default:** `deny`

What happens when the agent cannot answer (unreachable, timeout, an invalid answer, an open breaker): `deny` refuses the request (502, 504 on timeout, 503 while the breaker is open), `allow` lets it through unchecked.

- `deny`: Refuse the request (fail closed).
- `allow`: Let the request through unchecked (fail open); counted and logged.

### `middlewares.<name>.on_oversize`

**Type:** `reject` · `skip` · **Default:** `reject`

A body longer than `max_body`: `reject` answers `413`, `skip` asks the agent without the body (only when the length is declared; a chunked body that grows past `max_body` is refused with `413` either way).

- `reject`: Refuse the request with `413`.
- `skip`: Ask the agent without the body.

### `middlewares.<name>.protocol`

**Type:** `rdock` · `forward` · `ext_proc` · `ext_authz` · `spop` · **Default:** `rdock`

How the request is described to the agent.

- `rdock`: POST a JSON document describing the request; the agent answers a JSON verdict (`schema/agent.v1.json`).
- `forward`: Replay the request to the agent (same method, path, query, allowed headers and body); a 2xx allows, any other answer is sent to the client. What a WAF reverse-proxy image understands.
- `ext_proc`: Envoy's gRPC external processing (planned for a later version).
- `ext_authz`: Envoy's gRPC external authorization (planned for a later version).
- `spop`: HAProxy's stream processing offload protocol (planned for a later version).

:::note[Planned for a later version]
Agents over Envoy's gRPC external processing (protocol: ext_proc): accepted by `rdock validate` with a warning, refused by `rdock run` until a later version.
:::

### `middlewares.<name>.request_headers`

**Type:** list of `string`

Request headers sent to the agent besides the default set (`accept`, `accept-encoding`, `accept-language`, `cache-control`, `content-type`, `origin`, `referer`, `user-agent`); `["*"]` sends every header except hop-by-hop ones. `authorization`, `cookie` and `proxy-authorization` go only when listed here.

### `middlewares.<name>.response_headers`

**Type:** list of `string`

Request headers the agent may set on the request that goes to the backend (allowed answers only). Copies sent by the client are removed first. Applied only when the verdict comes before the request head leaves, which is the case for requests without a body (or whose body is not sent to the agent).

### `middlewares.<name>.timeout`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `1s`

Time allowed for the agent's whole answer.

### `middlewares.<name>.tls`

**Type:** object

TLS to an `https://` agent.

#### `middlewares.<name>.tls.ca_file`

**Type:** `string`

CA bundle used instead of the system roots.

#### `middlewares.<name>.tls.cert_file`

**Type:** `string`

Client certificate for upstream mTLS.

#### `middlewares.<name>.tls.key_file`

**Type:** `string`

Client key for upstream mTLS.

#### `middlewares.<name>.tls.server_name`

**Type:** `string`

SNI and verification name, when it differs from the backend host.

#### `middlewares.<name>.tls.verify`

**Type:** `boolean` · **Default:** `true`

Verify the backend certificate and host name.

## `type: cloudflare_access`

Verify the token Cloudflare Access adds to requests it let through (W-CF-06): a preset over `jwt` with the team's keys, issuer and RS256, the token from the `Cf-Access-Jwt-Assertion` header, then the `CF_Authorization` cookie.

### `middlewares.<name>.audience`

**Type:** [`Audience`](/docs/reference/configuration/#audience) · **Required**

The Application Audience (AUD) tag of the Access application, or several. Required: without it a token of any application of the same team would pass.

### `middlewares.<name>.certs_url`

**Type:** [`HttpUrl`](/docs/reference/configuration/#httpurl)

Where the keys are fetched from instead of the team's certs URL: for tests, or an egress proxy that mirrors it. `https://` (or a loopback address).

### `middlewares.<name>.claims_to_headers`

**Type:** map of names to `string`

Request headers set from claims (`claim: header`), e.g. `{ email: X-Auth-Email, common_name: X-Auth-Service-Token }`. Client-sent copies are removed first.

### `middlewares.<name>.team`

**Type:** `string` · **Required**

The Zero Trust team name (`acme`) or team domain (`acme.cloudflareaccess.com`).

## `type: api_key`

Authenticate with consumers' API keys (`rdk_…`), read from `Authorization: Bearer` or `X-API-Key`; sets the request's consumer (F-GW-01).

### `middlewares.<name>.anonymous`

**Type:** `deny` · `allow` · **Default:** `deny`

Requests without a key: `deny` answers `401`; `allow` lets them through without a consumer (an invalid key is still refused).

- `deny`: Answer `401`.
- `allow`: Continue without a consumer.

### `middlewares.<name>.forward_credential`

**Type:** `boolean` · **Default:** `false`

Keep the key in the request to the backend. Off by default: the backend gets the consumer in `X-Consumer-Name`, `X-Consumer-Groups` and `X-Credential-Id` instead.

### `middlewares.<name>.groups`

**Type:** list of `string`

Only consumers in one of these groups are let in; others get `403`. Any consumer when empty.

### `middlewares.<name>.headers`

**Type:** list of `string` · **Default:** `["Authorization","X-API-Key"]`

Request headers the key is read from, in order; the first present wins. A key in `Authorization` must follow `Bearer `.

### `middlewares.<name>.query`

**Type:** `string`

A query parameter the key is also read from, after the headers. Off unless named: keys in URLs end up in other systems' logs.

### `middlewares.<name>.realm`

**Type:** `string`

The realm of the `WWW-Authenticate` challenge.

## `type: quota`

Requests per consumer per calendar window (hour, day, month), persisted across restarts; `429` when used up (F-GW-02).

### `middlewares.<name>.flush_interval`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `10s`

How often counters are written to disk.

### `middlewares.<name>.headers`

**Type:** `off` · `draft` · **Default:** `off`

`draft` adds `RateLimit-Policy` and `RateLimit` to responses, in the syntax of `draft-ietf-httpapi-ratelimit-headers-11`. Off by default while the draft changes.

- `off`: None (`Retry-After` is always sent with `429`).
- `draft`: `RateLimit-Policy` and `RateLimit` as in `draft-ietf-httpapi-ratelimit-headers-11`.

### `middlewares.<name>.key`

**Type:** [`RateLimitKey`](/docs/reference/configuration/#ratelimitkey) · **Default:** `consumer`

What to count by; only `consumer` (the default) is accepted. Requests without a consumer are counted per client IP.

### `middlewares.<name>.limit`

**Type:** `integer` · **Required**

Requests allowed per window.

### `middlewares.<name>.overrides`

**Type:** map of names to `integer`

Group → limit, for consumers in that group (the first of the consumer's groups that has one wins).

### `middlewares.<name>.window`

**Type:** `hour` · `day` · `month` · **Required**

The calendar window, in UTC: `hour`, `day` (from 00:00) or `month` (from the 1st).

- `hour`: From the start of each hour.
- `day`: From 00:00 UTC.
- `month`: From 00:00 UTC on the 1st.
