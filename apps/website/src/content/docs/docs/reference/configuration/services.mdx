Backend pools that routes send traffic to.

## `services.<name>.backends`

**Type:** list of object

Backend servers. Set this, `split` or `respond`.

### `services.<name>.backends[].address`

**Type:** [`BackendAddress`](/docs/reference/configuration/#backendaddress) · **Required**

`host:port`, `[ipv6]:port` or `unix:///path.sock`.

### `services.<name>.backends[].backup`

**Type:** `boolean` · **Default:** `false`

Only used when no primary backend is available: the same as `priority: 1`.

### `services.<name>.backends[].for_zones` <Status maturity="beta" />

**Type:** list of `string`

Zones whose proxies should use this backend under `locality: { mode: prefer }`, instead of its own `zone` (Kubernetes topology hints, `hints.forZones`).

### `services.<name>.backends[].priority` <Status maturity="beta" />

**Type:** `integer`

Priority tier from 0 (the default, used first) to 7. See the service's `failover`. Not together with `backup`.

### `services.<name>.backends[].weight`

**Type:** `integer` · **Default:** `1`

Relative share of traffic.

### `services.<name>.backends[].zone` <Status maturity="beta" />

**Type:** `string`

The zone the backend runs in, e.g. `eu-west-1a`, for `locality: { mode: prefer }`.

## `services.<name>.failover` <Status maturity="beta" />

**Type:** `strict` · `spill` · **Default:** `strict`

How traffic moves between backend `priority` tiers. `strict` (the default): a tier gets traffic only when every tier above it has no available backend. `spill`: a tier keeps `healthy share × overprovisioning` of the traffic (at most all of it) and the rest goes to the next tier, as Envoy's priority levels do.

- `strict`: The next tier only when every tier above has no available backend.
- `spill`: Tiers share traffic by their health and the overprovisioning factor.

### `services.<name>.health.slow_start`

**Type:** [`SlowStart`](/docs/reference/configuration/#slowstart)

### `services.<name>.health.when_all_down`

**Type:** `fail_open` · `fail_closed` · **Default:** `fail_open`

- `fail_closed`: Answer `503`.

## `services.<name>.load_balancer`

**Type:** object · **Default:** `{"hash_on":null,"policy":"round_robin"}`

How a backend is chosen for each request.

### `services.<name>.load_balancer.decay` <Status maturity="beta" />

**Type:** [`Duration`](/docs/reference/configuration/#duration)

`peak_ewma`: time constant of the latency average. Default 10s (Finagle's and Linkerd's `decay`).

### `services.<name>.load_balancer.hash_on`

**Type:** `string`

Header or cookie name for `header_hash` and `cookie_hash`.

### `services.<name>.load_balancer.measure` <Status maturity="beta" />

**Type:** `first_byte` · `last_byte`

`peak_ewma`: what a latency sample measures. Default `first_byte`.

- `first_byte`: Time to the response headers (NGINX `least_time header`): a long download or a slow client does not make a backend look slow.
- `last_byte`: Time to the end of the response (NGINX `last_byte`). Upgraded connections (WebSocket) give no sample.

### `services.<name>.load_balancer.policy`

**Type:** `round_robin` · `random` · `least_conn` · `least_requests` · `p2c` · `ip_hash` · `header_hash` · `cookie_hash` · `peak_ewma` · **Default:** `round_robin`

Selection policy.

- `round_robin`: Weighted round-robin.
- `random`: Weighted random.
- `least_conn`: Fewest requests in flight relative to the weight (an HTTP/1.1 request holds one connection, so this is also the least-connections policy).
- `least_requests`: Fewest requests in flight relative to the weight.
- `p2c`: Power of two random choices.
- `ip_hash`: Consistent hash of the client IP (Traefik's `hrw`).
- `header_hash`: Consistent hash of a request header (`hash_on`).
- `cookie_hash`: Consistent hash of a cookie (`hash_on`).
- `peak_ewma` <Status maturity="beta" />: Power of two distinct random choices over `latency × (in_flight + 1) / weight`, with a latency average that reacts to peaks at once (Finagle's and Linkerd's Peak-EWMA).

## `services.<name>.locality` <Status maturity="beta" />

**Type:** object

Prefer backends in the proxy's own zone (`locality` at the top level sets the zone). Omitted, the top-level `locality.mode` applies.

### `services.<name>.locality.mode`

**Type:** `off` · `prefer` · **Required**

`prefer` or `off`.

- `off`: Every available backend, whatever its zone.
- `prefer`: Only backends in the proxy's zone while at least one of them is available; all otherwise (Kubernetes `PreferSameZone`).

## `services.<name>.max_connections_per_backend`

**Type:** `integer`

Requests in flight to one backend; a backend at the limit gets no more until one ends.

## `services.<name>.max_requests`

**Type:** `integer`

Requests in flight across the pool; more are answered `503` (circuit breaker).

## `services.<name>.overprovisioning` <Status maturity="beta" />

**Type:** [`Factor`](/docs/reference/configuration/#factor)

With `failover: spill`: how much more than its share each tier can carry. Default 1.4 (Envoy's `overprovisioning_factor`): a tier keeps all traffic until fewer than about 71 % of its backends are available.

## `services.<name>.pass_host_header`

**Type:** `boolean` · **Default:** `true`

Forward the client's `Host` header (otherwise the backend address is used).

## `services.<name>.respond` <Status maturity="beta" />

**Type:** object

Answer every request with this status instead of forwarding it, e.g. `500` for a share of a split that has no valid backend. Set this, `backends` or `split`.

### `services.<name>.respond.status`

**Type:** `integer` · **Required**

Status code, from 200 to 599.

## `services.<name>.retries`

**Type:** object

Retries of failed requests (ADR-0010, ADR-0015, ADR-0022). Without this setting the defaults below apply: a connection that cannot be opened is tried again on another backend, up to twice, within the retry budget (ADR-0028). `attempts: 0` turns retries off.

### `services.<name>.retries.attempts`

**Type:** `integer` · **Default:** `2`

Additional attempts after the first.

### `services.<name>.retries.budget_percent`

**Type:** `integer` · **Default:** `20`

Retries in flight may be at most this share of the requests in flight, in percent (at least 3 are always allowed), so retries cannot overload a failing pool.

### `services.<name>.retries.on`

**Type:** list of `connect` · `reset` · `timeout` · `502` · `503` · `504` · **Default:** `["connect"]`

Failures that are retried.

### `services.<name>.retries.per_try_timeout` <Status maturity="beta" />

**Type:** [`Duration`](/docs/reference/configuration/#duration)

Abandons an attempt that has not finished a read for this long and retries it on another backend, within the budget and only where a retry is allowed (`on` must list `timeout`). It replaces `timeouts.read` for every read of such an attempt, the wait for the response headers and each pause of the response body; the last attempt and requests that cannot be retried wait `timeouts.read`.

### `services.<name>.retries.retry_non_idempotent`

**Type:** `boolean` · **Default:** `false`

Also retry non-idempotent methods such as POST. Only safe if backends are idempotent.

## `services.<name>.scheme`

**Type:** `http` · `https` · `h2c` · `h3` · **Default:** `http`

Protocol spoken to the backends. gRPC uses `h2c` (cleartext) or `https`.

- `http`: HTTP/1.1 in cleartext.
- `https`: HTTP/1.1 or HTTP/2 over TLS.
- `h2c`: HTTP/2 in cleartext (gRPC without TLS).
- `h3`: HTTP/3 over QUIC. Not supported in this version (planned, ADR-0032): Pingora 0.9 has no QUIC connector.

:::note[Planned for a later version]
HTTP/3 to backends (scheme: h3): accepted by `rdock validate` with a warning, refused by `rdock run` until a later version.
:::
