In-place binary upgrades (`rdock upgrade`, `SIGUSR2`): the binary, the drain bound and the start timeout.

<Status maturity="beta" />

## `upgrade.binary`

**Type:** `string` · **Default:** `/usr/local/bin/rdock`

The binary `SIGUSR2` and `rdock upgrade` without `--binary` run. Default `/usr/local/bin/rdock`, where the systemd unit and the release image install it. It must be a regular file owned by root or rdock's user and not writable by the group or others, in a directory with the same owners that the group and others cannot write to (unless it is sticky, like /tmp).

## `upgrade.drain`

**Type:** [`DrainLimit`](/docs/reference/configuration/#drainlimit) · **Default:** `10m`

How long the old process may still serve its open connections (HTTP/1 keep-alive is switched off and HTTP/2 clients get GOAWAY at once); the rest are closed then. Default 10m (Envoy's drain time); `unlimited` waits for every connection, which keeps an old, possibly vulnerable binary serving for as long as a client holds a connection.

## `upgrade.start_timeout`

**Type:** [`Duration`](/docs/reference/configuration/#duration) · **Default:** `30s`

How long the new process may take to report that it is ready, and then that it serves; otherwise the old process resumes and the upgrade fails. Default 30s.

## `upgrade.trusted_keys`

**Type:** list of `string`

minisign public keys (`RWQ…`); when set, `<binary>.minisig` must be a valid signature of the binary by one of them.
