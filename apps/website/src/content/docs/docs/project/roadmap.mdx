ReverseDock is planned in milestones, not dates. Each milestone ships a usable binary and has acceptance criteria that CI checks. Progress on each one is tracked in the [GitHub milestones](https://github.com/Docker-Hunterpedia/ReverseDock/milestones); the full plan with requirement IDs is [docs/07-roadmap.md](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/07-roadmap.md) in the repository.

| Milestone | Theme | You can… | Status |
|---|---|---|---|
| M0 | Foundations | build, lint, test and release; the configuration model and schema exist | Done (0.1.0-alpha.2) |
| v0.1 | Hello proxy | replace NGINX for host and path routing with your own certificates | <Status since="v0.1" /> 0.1.0-alpha.3 |
| v0.2 | Docker-native | replace Traefik on a Compose box using your existing labels | <Status since="v0.2" />  0.2.0-alpha.1 |
| v0.3 | Automatic HTTPS | go from DNS to HTTPS with one label | <Status since="v0.3" />  0.3.0-alpha.2 |
| v0.4 | Production reliability | run busy APIs with load balancing, health checks, retries, mTLS and JWT | <Status since="v0.4" />  0.4.0-alpha.1 |
| v0.5 | Management | operate it from a dashboard and REST API with history and rollback | <Status since="v0.5" />  0.5.0-alpha.1 |
| v0.6 | Swarm, L4, static | multi-node Docker, TCP and SNI passthrough, static sites | <Status since="v0.6" />  0.6.0-alpha.1 |
| v0.7 | Kubernetes | run it as a Gateway API controller | <Status since="v0.7" />  0.8.0-alpha.1 |
| v0.8 | Cache and extensibility | cache like NGINX, extend it with plugins and agents, run an API gateway | <Status since="v0.8" />  0.8.0-alpha.1 |

| v1.0 | Stable | rely on a written stability promise and migrate from Traefik, Caddy or NGINX; implemented, released as `1.0.0-rc.N` until an independent security review | <Status planned="v1.0" /> |

## v0.1: Hello proxy <Status since="v0.1" />

HTTP/1.1, HTTP/2, h2c, WebSocket, server-sent events and gRPC; routing with the Traefik v3 grammar; TLS with your own certificates; the middlewares `headers`, `redirect`, `rewrite`, `strip_prefix`, `add_prefix`, `replace_path`, `basic_auth`, `forward_auth`, `ip_allow`, `ip_deny`, `rate_limit`, `cors`, `compress`, `errors` and `maintenance`; reloads without dropped requests, history and last-known-good; Prometheus metrics; the official image, a Compose example and a systemd unit. See [What is ReverseDock](/docs/start/what-is-reversedock/) and the [changelog](/docs/project/changelog/).

## v0.2: Docker-native <Status since="v0.2" />

The Docker provider: routes from `rdock.*` labels and compatibility with a documented subset of `traefik.*` labels, tested against real Compose files. A zero-configuration mode, `rdock migrate traefik` to turn labels into YAML, diagnostics for unsupported labels, and examples for Dokploy, Coolify and Portainer. Losing the Docker socket does not drop traffic.

## v0.3: Automatic HTTPS <Status since="v0.3" />

ACME with HTTP-01, TLS-ALPN-01 and DNS-01, renewal guided by ARI, a local CA for development, Cloudflare integration (trusted IP ranges, `CF-Connecting-IP`, DNS-01, Tunnel example). The goal: a fresh VPS reaches valid HTTPS in under 60 seconds.

## v0.4: Production reliability <Status since="v0.4" />

Load-balancing policies, active and passive health checks, retries with a retry budget, sticky sessions, traffic splits and mirroring, mTLS and Cloudflare Authenticated Origin Pulls, JWT, limits, brotli and zstd, OpenTelemetry tracing, a chaos suite, and the [first published benchmarks](https://github.com/Docker-Hunterpedia/ReverseDock/tree/main/benchmarks) against NGINX, HAProxy, Caddy and Traefik. Full request buffering moves to v0.8 and stays open there.

## v0.5: Management <Status since="v0.5" />

The embedded dashboard and the versioned REST API with its OpenAPI document and generated clients: admin users, sessions and two-step verification, scoped tokens, a hash-chained audit log, a configuration API with history and rollback, live traffic, logs and events, routing explanations, alerts, a Grafana dashboard, a security review of the admin surface, and [about twice the throughput on 2 CPUs](/docs/project/performance/) with a passed 24-hour soak.

## v0.6: Swarm, L4, static <Status since="v0.6" />

The Docker Swarm provider in task mode, TCP routes with SNI passthrough and TLS termination, the PROXY protocol in and out, static sites with SPA fallback, DNS-01 with seven more providers, a per-attempt connect budget and connection retries by default, with [results](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/benchmarks/results/2026-11-07-v06/report.md) for a 3-node Swarm and a soak.

## v0.7: Kubernetes <Status since="v0.7" />

Released in 0.8.0-alpha.1, together with v0.8 (there is no 0.7 release): a Gateway API controller in the same binary (Gateway API v1.7.0, Standard channel: GatewayClass, Gateway, HTTPRoute, GRPCRoute, TLSRoute with passthrough, TCPRoute, ReferenceGrant, ListenerSet), one Service and address per Gateway, status written by a leader chosen with a Lease, EndpointSlice backends, TLS from Secrets and cert-manager, Ingress translation with the common ingress-nginx annotations, a Helm chart, raw manifests and Kustomize. It passes the upstream Gateway API v1.7.0 conformance suite in CI on kind (`GATEWAY-HTTP`, `GATEWAY-GRPC`, `GATEWAY-TLS` and `GATEWAY-TCP`: all core tests and every claimed extended feature; 2026-11-11, commit `19e88cc`), and the Helm install on k3s is tested in CI; no report has been submitted upstream yet, and the chart is installed from a checkout of the release tag (it is not published to a chart registry). Request timeouts and retries on routes are not part of it; UDPRoute joins it with UDP routes in v0.8 (`GATEWAY-UDP` passes on kind in CI, 2026-11-12, commit `43d81de`: core 21 and extended 7 passed, so all five profiles pass). See [install](/docs/install/kubernetes/) and the [Gateway API guide](/docs/guides/kubernetes-gateway-api/).

## v0.8: Cache and extensibility <Status since="v0.8" />

Released in 0.8.0-alpha.1, together with v0.7 ([ADR-0030](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/decisions/0030-v0-8-cache-extensibility-gateway.md)):

- **Cache:** the [`cache` middleware](/docs/guides/caching/) with memory and disk stores, RFC 9111 storability and freshness, revalidation, `Vary`, request coalescing, `stale-if-error`, tags and a purge API on the admin listener (one instance). The stampede test passes (50 concurrent misses, one origin fetch). The public RFC 9111 suite [`http-tests/cache-tests`](https://github.com/http-tests/cache-tests) runs in CI against the cache at its safe defaults; on 2026-11-12 (commit `c292639`) its gate passed with 205 tests passing and 2 required failures that are on a reviewed allow-list: `other-date-update` and `other-date-update-expires`, because Pingora 0.9.1 rewrites `Date` on every response, which needs an upstream change. 35 optional tests fail, and rdock does not store `Set-Cookie` responses by default, so the suite's four `Set-Cookie` storage tests do not run as intended.
- **Extensions:** [native plugins](/docs/guides/plugins/) in Rust with an SDK, two example plugins and `rdock` as a library; [agents](/docs/guides/agents/) over HTTP that fail closed, with a WAF example (the CRS project's ModSecurity image). [WASM plugins](/docs/guides/wasm-plugins/) are **experimental** and **not in the release binaries or images**: build with `--features wasm` to use them; modules are signed.
- **API gateway:** [consumers and API keys](/docs/guides/api-keys/), [per-consumer rate limits and quotas](/docs/guides/quotas/), [usage metering](/docs/guides/usage-metering/), [OIDC login](/docs/guides/oidc-login/), [request validation](/docs/guides/request-validation/), [transformation](/docs/guides/transforming-requests/), problem details ([problem types](/docs/reference/problems/)), [Cloudflare Access](/docs/guides/cloudflare/) and [Vault or OpenBao references](/docs/guides/secrets/).
- **Also:** [UDP routes](/docs/guides/udp-routes/) and the Gateway API `UDPRoute` (`GATEWAY-UDP` passes on kind in CI, 2026-11-12, commit `43d81de`: core 21 and extended 7, so all five profiles pass), [directory listings](/docs/guides/static-files/), `hold_body`, and the [Terraform and OpenTofu provider](/docs/guides/terraform/) (source only).

**Left open after v0.8:** full request pre-buffering (and so the request head reaches the backend before an agent or `validate` verdict on the body, a Pingora 0.9.1 limitation); background refresh for `stale-while-revalidate`; gRPC and SPOP agents; publishing the Terraform provider to the registries (it needs its own repository and a signing key); the `Date` rewrite; a dashboard page for consumers, keys and quotas; OIDC back-channel logout and early session revocation. The CI jobs `http-cache`, `openbao`, `oidc-dex`, `wasm`, `waf-example` and `terraform-provider` are not yet required checks, and the 2-CPU benchmark that ADR-0030 asks for has not been run. No soak, no benchmark and no multi-node lab were run for 0.8.0-alpha.1; the evidence is the CI described above.

## v0.9: Scale <Status since="v0.9" />

Released in 0.9.0-alpha.1 ([ADR-0031](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/decisions/0031-v0-9-scale.md), [ADR-0032](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/decisions/0032-http3-on-quinn-and-h3.md)):

- **Upgrades and sockets:** [replace the binary in place](/docs/guides/upgrades/) without refusing a connection (Linux), [socket, runtime and HTTP/2 settings](/docs/guides/sockets-and-threads/), TLS session tickets shared between listeners, a host index for routing.
- **Balancing:** `peak_ewma`, [outlier detection](/docs/guides/backends/), slow start, priority tiers, zones, a per-try timeout.
- **Edge security:** [TLS client fingerprints](/docs/guides/client-fingerprints/) (JA4), [GeoIP](/docs/guides/geoip/), [abuse protection](/docs/guides/abuse-protection/) with bans, identity rules on client certificates including SPIFFE.
- **Cluster:** a [control plane](/docs/guides/cluster/) that rolls configuration out to several instances with a canary and rollback, [certificates ordered once](/docs/guides/shared-certificates/) across instances, [rate limits and quotas shared](/docs/guides/rate-limiting/) between instances, a Cluster page in the dashboard.
- **Multi-tenant:** [admission control](/docs/guides/admission/) with priority classes and [tenants](/docs/guides/tenants/) that scope API users and tokens.
- **HTTP/3** ([guide](/docs/guides/http3/)) is **experimental** and **not in the release binaries or images**: build with `--features http3` to use it.

**Not measured to the milestone's criteria:** the 24-hour soak at target request rate and the 8-CPU and dedicated-hardware numbers are open. A weekly soak of about 5 hours on a free hosted runner stands in for the soak and had not completed a full run when this was written; only smoke runs on a shared sandbox exist. HTTP/3 is tested against curl in CI but not against the h3i suite. A run of the binary upgrade under real systemd is untested.

**Refused as planned or left open:** hedged requests, automatic rollback of a rollout on health, a cluster-wide `in_flight` count, a highly available control plane, tenant-owned listeners and certificates, a tenant label on core metrics, HTTP/3 to backends, 0-RTT, connection migration, WebTransport and WebSocket over HTTP/3, the SPIFFE Workload API, bot verification, CPU pinning, and migrating UDP sessions across an upgrade. See the [roadmap in the repository](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/07-roadmap.md) for the full list.

## v1.0: Stable <Status planned="v1.0" />

Implemented on `main` and released as `1.0.0-rc.N`; the final 1.0 waits for an independent security review, which has not been commissioned ([ADR-0033](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/decisions/0033-v1-0-stable.md)).

- **The promise:** [stability, deprecations and support](/docs/project/stability/) per surface, [maturity levels](/docs/project/maturity/) with an `experimental:` opt-in, and a CI check that compares the public surfaces with the last release.
- **Migration:** [`rdock migrate traefik`](/docs/migrate/from-traefik/), [`rdock migrate caddy`](/docs/migrate/from-caddy/) and [`rdock migrate nginx`](/docs/migrate/from-nginx/) with a report of every item; the last two are beta. `rdock migrate config` rewrites deprecated settings.
- **Failure and security:** [failure behaviour](/docs/operations/failure-behaviour/) proven by a chaos suite, the [threat model](/docs/project/threat-model/), more fuzz targets, the fixes of two internal reviews and SBOMs read from the shipped binaries.

**Not run yet:** the benchmark workflow with the 1.0 method and the 60-second HTTPS proof, so [no new result](/docs/project/performance/) is published; the chaos suite's tmpfs, Docker and Pebble variants; the reproducible-build check. **Open outside the project:** the independent security review, a benchmark on dedicated hardware, the 24-hour soak, and a 60-second run on a real server. The [roadmap in the repository](https://github.com/Docker-Hunterpedia/ReverseDock/blob/main/docs/07-roadmap.md) says what has run and what has not, criterion by criterion.

## Out of scope for 1.0

FastCGI, a forward-proxy mode, a mail proxy, eBPF experiments, and Nomad, Consul, key-value and ECS providers. They are recorded so they are not proposed again by accident; each would need its own design decision first.
