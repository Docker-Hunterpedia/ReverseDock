# rdock-admin

The admin listener (`admin.listener`, default `127.0.0.1:2080`): health, readiness, metrics and the admin API.

**v0.1–v0.4:** `GET /healthz`, `GET /readyz` and `GET /metrics` (Prometheus) without authentication; `GET /api/v1/status` and `POST /api/v1/config/reload` with a shared bearer token (removed in v0.5).

**v0.5** ([ADR-0024](../../docs/decisions/0024-management-api-and-dashboard.md)): axum on a tokio runtime of its own (`admin.threads`), never through proxy listeners. Engine calls are sent to the proxy's runtime, so anything they start lives with the data plane. Every request passes the `Host` allow-list (421, DNS rebinding) and, for unsafe methods, the cross-site check (403); every response gets the security headers. TLS (`admin.tls`, TLS 1.3) is required off loopback. The CLI uses the Unix socket (`admin.socket`, mode 0600), which needs no token. Users (`users.rs`, `passwords.rs`) are kept in `$RDOCK_DATA_DIR/admin/users.json` with Argon2id hashes; the first admin is created with a single-use bootstrap token (`bootstrap.rs`) through `POST /api/v1/setup`, and `POST /api/v1/auth/login` checks passwords under per-address and per-name limits (`limits.rs`) and starts a server-side session (`sessions.rs`). The session's own endpoints, TOTP enrolment (`totp.rs`), the second factor, re-authentication and logout are in `account.rs`; unsafe requests with the cookie need `X-CSRF-Token`. The dashboard from `apps/dashboard/dist` is embedded with rust-embed and served for page paths outside `/api/` (`dashboard.rs`, `admin.dashboard`). Every other `/api/v1` request is identified once (`caller.rs`: socket, session or API token) and handlers check the role they need; API tokens are in `tokens.rs`, user and token management in `manage.rs`. The hash-chained audit log is `audit.rs`; the configuration API (effective configuration, the `api` provider's objects with `If-Match`, dry runs, history, rollback, export and import) is `config_api.rs`, applied by the engine (`crates/rdock/src/engine/api.rs`). The the configuration API, live streams and the other dashboard pages follow in the v0.5 milestone.
