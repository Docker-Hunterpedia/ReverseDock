# rdock-tls

TLS termination: the rustls SNI certificate resolver, certificate store, TLS policies, mTLS and the local development CA.

**v0.1:** PEM certificates with plain or encrypted PKCS#8 keys, an SNI index (exact name, then one-label wildcard, then `defaults.certificate`) behind a lock-free resolver that is swapped on reload, and the `modern`/`intermediate` policies on rustls with the ring provider ([ADR-0013](../../docs/decisions/0013-tls-crypto-provider-ring.md)), ALPN `h2`/`http/1.1` and session tickets. **v0.3:** the resolver serves configured, then ACME-issued, then local-CA certificates, each swapped on its own; `is_private_name` and `is_local_ca_name` decide which names go to the local CA. mTLS lands in v0.4. **v0.6:** `clienthello` reads the SNI and ALPN of a ClientHello without terminating TLS, returning every byte it read, for SNI passthrough on TCP routes ([ADR-0026](../../docs/decisions/0026-swarm-l4-static.md)). **v0.9 (unreleased, [ADR-0031](../../docs/decisions/0031-v0-9-scale.md)):** `tickets` holds one ticket key set and one session cache per security class, shared by listeners and kept across reloads and binary upgrades; `fingerprint` computes JA4 (and optional JA3) from the ClientHello `clienthello` parses, which now refuses duplicate extension types and more than 128 extensions; `client_auth` gained typed identity rules and SPIFFE X.509-SVID checks. Design: [architecture §10](../../docs/05-architecture.md).
