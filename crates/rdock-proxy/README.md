# rdock-proxy

The data plane: the Pingora `ProxyHttp` implementation, listeners, router, middleware runtime, forwarded headers, error pages and layer-4 proxies.

**v0.1:** our own accept loops hand each connection to Pingora's HTTP engine ([ADR-0012](../../docs/decisions/0012-own-listeners-pingora-http-engine.md)), so listeners are added, changed and removed in-process on reload. `compile` turns a validated `Config` into an immutable runtime (routes, services, certificates, middlewares) that is swapped atomically; `gate` refuses settings planned for later versions ([ADR-0014](../../docs/decisions/0014-http-semantics-v0-1.md)). It also holds the router, path normalisation, trusted-proxy handling, upstream DNS cache and peer selection, connection hardening (header deadline, bare-LF rejection) and the error pages. TCP routes with SNI passthrough landed in v0.6 (`tcp`), UDP routes with per-client sessions in v0.8 (`udp`, ADR-0030). **v0.9 (released in 0.9.0-alpha.1, [ADR-0031](../../docs/decisions/0031-v0-9-scale.md), [ADR-0032](../../docs/decisions/0032-http3-on-quinn-and-h3.md)):** a per-listener host index in the router, listener sockets bound through `socket2` (`listeners.<l>.socket`), HTTP/2 settings, `tls.max_handshakes`, GeoIP matchers, and HTTP/3 ingress (`http3`, experimental, built only with the cargo feature `http3`: our own QPACK decoding and validation, a frame-size guard in front of h3, and a Pingora custom session so requests share the HTTP/1 and HTTP/2 pipeline). Design: [architecture §6–§8 and §17–§18](../../docs/05-architecture.md).
